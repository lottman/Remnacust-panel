# Remnacust Panel

Выпуск **Panel/Page 1.1.7.101** входит в комплект Installer **1.2.141** с Node **1.1.26** и Core/WASM **1.1.16**. [Изменения 99 → 101](docs/releases/1.1.7.101.md). Обновление установленного сервера выполняется отдельно.

[Русский](README.md) · [English](README.en.md)

Панель управления VPN-пользователями, подписками, устройствами и нодами Xray на основе Remnawave. В репозитории находятся панель и отдельный сайт подписки. Интерфейс и встроенное руководство доступны на RU/EN/FA/ZH.

[Установка](#установка) · [Требования](#требования) · [Документация](#документация) · [Выпуски](https://github.com/lottman/Remnacust-panel/releases)

## Где находятся настройки

При установке нашим скриптом каждый компонент использует постоянный каталог:

| Компонент | Окружение | Docker Compose |
| --- | --- | --- |
| Панель | `/opt/remnacust/panel/.env` | `/opt/remnacust/panel/docker-compose.yml` |
| Нода | `/opt/remnacust/node/.env` | `/opt/remnacust/node/docker-compose.yml` |
| Сайт подписки | `/opt/remnacust/subscription-page/.env` | `/opt/remnacust/subscription-page/docker-compose.yml` |

Сначала выполните `cat /opt/remnacust/FILES.txt`: явно выбранный внешний каталог может отличаться. Скрытые файлы видны через `ls -la`. Не создавайте новый пустой `.env` в `/opt/remnacust`.

```bash
cd /opt/remnacust/panel
ls -la
nano .env
docker compose config --quiet
docker compose up -d --no-build --pull never
```

`restart` не перечитывает `.env`: после правки окружения контейнер нужно пересоздать. Сохраняйте исходный `APP_SECRET`, ключи нод и реквизиты БД. Копии находятся в `backups/`, журналы — в `logs/`.

## Требования

Ресурсы — ориентир для начальной установки, а не гарантия числа пользователей. Нагрузка зависит от соединений, частоты обновления подписок, правил и объёма статистики.

| Компонент | CPU | RAM | Диск |
| --- | --- | --- | --- |
| Панель с БД и кешем | Минимум 2 ядра, рекомендуется 4 | Минимум 2 GiB, рекомендуется 4 GiB | От 20 GiB; дополнительное место для копий и образов |
| Отдельная нода | От 1 ядра | От 1 GiB с запасом под Xray | Место для образов, геофайлов и журналов |
| Отдельный сайт подписки | Начальный ориентир: 1 ядро | Начальный ориентир: 1 GiB; точный минимум не измерен | Место для образов и журналов |

При совместном размещении оставляйте запас для всех компонентов. Требования панели/ноды согласованы с [рекомендациями Remnawave](https://docs.rw/install/requirements/); оценка сайта — рекомендация для планирования.

| ПО | Требование |
| --- | --- |
| ОС установщика 1.2.141 | Ubuntu 22.04 / 24.04 / 26.04 LTS и Debian 12 / 13, Linux amd64 или arm64 |
| Контейнеры | Docker Engine и актуальный плагин Docker Compose v2; `docker-compose` v1 не поддерживается |
| PostgreSQL | 14.24 / 15.19 / 16.15 / 17.11 / 18.6; 195 миграций, HWID и границы доступа |
| Установка готовых образов | Root, доступ к APT, GitHub/GHCR и рабочий DNS; Node.js и Go на VPS не нужны |
| Сборка из исходников | Node.js 26.13 LTS; для Core/редактора отдельно Go 1.27.3 |

Отдельный минимальный номер Engine или minor-версии Compose не проверен: используйте актуальные пакеты официального репозитория. Образы БД и кеша выбирает комплект; устанавливать эти сервисы на хост обычно не нужно.

Поддержка PostgreSQL 14 заканчивается **12 ноября 2026 года**. Для новой установки выбирайте поддерживаемую major-версию с текущими исправлениями. Не подключайте старый data volume к другой major-версии: нужен отдельный перенос. [Совместимость БД](docs/DATABASE-COMPATIBILITY.md) · [политика PostgreSQL](https://www.postgresql.org/support/versioning/).

## Установка

Подготовьте домен панели и DNS-записи. Для подписок используйте отдельный публичный адрес. Откройте порты выбранного HTTPS proxy, сохраните SSH-доступ; внутренние порты БД, кеша и API ноды не должны быть общедоступны.

```bash
curl -fsSLo installer.sh https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh
sudo bash installer.sh install-panel
```

Команда скачивает последний стабильный установщик. В вопросе о версии нажмите Enter для Latest; `--version` нужен только для выбора конкретного выпуска.

Скрипт спрашивает домен, способ HTTPS и установку сайта подписки. После запуска создайте администратора. Для своего reverse proxy предусмотрен `--proxy existing`. [Руководство установщика](https://github.com/lottman/Remnacust-installer#readme).

Отдельный сайт можно установить позже: `sudo remnacust install-subscription-page`. Он подключается к локальной или удалённой панели с ограниченным API-токеном. [Настройка сайта](subscription-page/README.md).

## Возможности

- Пользователи, сквады, сроки, трафик, импорт/экспорт и массовые операции. `FROZEN` приостанавливает доступ и сохраняет остаток срока; активация возобновляет отсчёт.
- HWID и персональные ключи, число устройств и отзыв доступа.
- Квоты хостов/тегов в GiB и скорость в Mbps, включая пределы пользователя и устройства на совместимых Node/Core.
- Профили Xray, хосты, шаблоны подписок, правила ответов и история конфигураций.
- Автовыбор, категории геофайлов, DIRECT/REJECT и маршруты через настроенные группы.
- Здоровье нод, статистика, сессии, резервные копии и API-токены с отдельными правами.

Обычные ноды и страницы Remnawave сохраняют базовую работу в пределах их протоколов и API. Расширенные ограничения хостов, устройств и учёт автовыбора требуют совместимых наших Node/Core. Сетевой сбой или неизвестная совместимость не разрешают снимать установленные ограничения. [Совместимость нод](docs/NODE-COMPATIBILITY.md).

## Подписки, геофайлы и CDN

Состав пула автовыбора и хосты, на которых он показывается, настраиваются отдельно. Пул выбирается хостами либо тегами. Состав обновляется вместе с подпиской; сервер для нового соединения выбирает стратегия клиента. Набор стратегий зависит от приложения и формата. [Автовыбор](docs/XRAY-AUTOSELECT.md).

Геофайл загружается с ПК или по HTTPS в общую библиотеку. Небольшие наборы встраиваются в JSON; большие могут передаваться объединёнными DAT поддерживаемым Happ/INCY. Для полной маршрутизации нужна JSON-подписка: включите JSON на базовом пути или используйте `/json`. URI/Base64 не переносит весь набор правил. После сохранения шаблона обновите подписку в приложении. [Геофайлы](docs/GEOFILES.md).

Домены: **Подписка → Настройки → Страницы подписки**. Основной домен синхронизируется с `SUB_PUBLIC_DOMAIN` через службу установщика. На основной домен допускается до трёх CDN. В карточке пользователя доступны обычные/CDN-ссылки и QR-коды.

Для VK/Yandex перенесите из карточки CDN источник, Host/SNI и сгенерированную пару заголовка запроса. Не включайте общий кеш ответов подписки. Адрес backend и API-токен — серверные настройки; их нельзя подставлять в публичные ссылки. [Домены и CDN](docs/SUBSCRIPTION-DOMAINS.md) · [API и права](docs/API.md).

## Обновление и диагностика

```bash
sudo remnacust upgrade-panel
sudo remnacust upgrade-node
sudo remnacust upgrade-subscription-page --page-id ID
```

Перед обновлением сохраняются конфигурация и резервная копия. Скрипт обновляет системные пакеты; вопросы настройки пакетов требуют SSH-терминала. Перед повтором обновления из панели завершите требуемое обслуживание пакетов через SSH. Автоматической перезагрузки сервера нет.

CLI-журналы: `/opt/remnacust/logs/installer-panel.log`, `installer-node.log`, `installer-subscription-page.log`. Следующее действие того же компонента заменяет его журнал. При ошибке показывается путь. Обновление панели также сохраняет `panel-update-<ID>.log`; каталог журналов должен оставаться закрытым.

Ноды могут обслуживать последнюю конфигурацию без панели при действующих ключах, сроках и локальном остатке квот. Новый резерв и изменения доступа требуют связи; бесконечная автономность не обещается. CDN, DNS и proxy ноды должны работать независимо. [Автономность](docs/NODE-AUTONOMY.md).

Если подписка временно не загрузилась, проверьте журнал, доступность панели, права токена страницы и настройки CDN. Не заменяйте ключи пользователя для исправления сетевого сбоя. [Операции](docs/OPERATIONS.md).
