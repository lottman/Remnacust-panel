# Remnacust Panel

[Русский](README.md) · [English](README.en.md)

Панель управления VPN-пользователями, подписками, устройствами и нодами Xray на основе Remnawave. В репозитории находятся панель и отдельный сайт подписки. Интерфейс и встроенное руководство доступны на RU/EN/FA/ZH.

[Установка](#установка) · [Требования](#требования) · [Документация](#документация) · [Выпуски](https://github.com/lottman/Remnacust-panel/releases)

## Где находятся настройки

При установке нашим скриптом каждый компонент использует постоянный каталог:

| Компонент | Окружение | Docker Compose |
| --- | --- | --- |
| Панель | `/opt/remnacust/panel/.env` | `/opt/remnacust/panel/docker-compose.yml` |
| Нода | `/opt/remnacust/node/.env` | `/opt/remnacust/node/docker-compose.yml` |
| Сайт подписки | `/opt/remnacust/subscription-page/.env` | `/opt/remnacust/subscription-page/docker-compose.yml` |

Сначала выполните `cat /opt/remnacust/FILES.txt`: явно выбранный внешний каталог может отличаться. Скрытые файлы видны через `ls -la`. Не создавайте новый пустой `.env` в `/opt/remnacust`.

```bash
cd /opt/remnacust/panel
ls -la
nano .env
docker compose config --quiet
docker compose up -d --no-build --pull never
```

`restart` не перечитывает `.env`: после правки окружения контейнер нужно пересоздать. Сохраняйте исходный `APP_SECRET`, ключи нод и реквизиты БД. Копии находятся в `backups/`, журналы — в `logs/`.

## Требования

Ресурсы — ориентир для начальной установки, а не гарантия числа пользователей. Нагрузка зависит от соединений, частоты обновления подписок, правил и объёма статистики.

| Компонент | CPU | RAM | Диск |
| --- | --- | --- | --- |
| Панель с БД и кешем | Минимум 2 ядра, рекомендуется 4 | Минимум 2 GiB, рекомендуется 4 GiB | От 20 GiB; дополнительное место для копий и образов |
| Отдельная нода | От 1 ядра | От 1 GiB с запасом под Xray | Место для образов, геофайлов и журналов |
| Отдельный сайт подписки | Начальный ориентир: 1 ядро | Начальный ориентир: 1 GiB; точный минимум не измерен | Место для образов и журналов |

При совместном размещении оставляйте запас для всех компонентов. Требования панели/ноды согласованы с [рекомендациями Remnawave](https://docs.rw/install/requirements/); оценка сайта — рекомендация для планирования.

| ПО | Требование |
| --- | --- |
| ОС установщика 1.2.178 | Ubuntu 22.04 / 24.04 / 26.04 LTS и Debian 12 / 13, Linux amd64 или arm64 |
| Контейнеры | Docker Engine и актуальный плагин Docker Compose v2; `docker-compose` v1 не поддерживается |
| PostgreSQL | Для новой установки — поддерживаемая основная версия с текущими исправлениями; образы Compose в этом репозитории используют 18.7. Границы проверенной совместимости — в [руководстве БД](docs/DATABASE-COMPATIBILITY.md) |
| Установка готовых образов | Root, доступ к APT, GitHub/GHCR и рабочий DNS; Node.js и Go на VPS не нужны |
| Сборка из исходников | Node.js 26.13.1, закреплённый в CI; для Core/редактора отдельно Go 1.27.4 |

Отдельный минимальный номер Engine или minor-версии Compose не проверен: используйте актуальные пакеты официального репозитория. Образы БД и кеша выбирает комплект; устанавливать эти сервисы на хост обычно не нужно.

Плановый срок поддержки PostgreSQL 14 завершился **12 ноября 2026 года**. Обновление панели сохраняет существующий образ БД и его том: фактическая версия вашей базы может отличаться от новой установки. Не подключайте старый data volume к другой major-версии: нужен отдельный перенос. [Совместимость БД](docs/DATABASE-COMPATIBILITY.md) · [политика PostgreSQL](https://www.postgresql.org/support/versioning/).

## Установка

Подготовьте домен панели и DNS-записи. Для подписок используйте отдельный публичный адрес. Откройте порты выбранного HTTPS proxy, сохраните SSH-доступ; внутренние порты БД, кеша и API ноды не должны быть общедоступны.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/lottman/Remnacust-installer/main/Install.sh) @ install-panel
```

Команда скачивает последний стабильный установщик. В вопросе о версии нажмите Enter для Latest; `--version` нужен только для выбора конкретного выпуска.

Скрипт спрашивает домен, способ HTTPS и установку сайта подписки. После запуска создайте администратора. Для своего reverse proxy предусмотрен `--proxy existing`. [Руководство установщика](https://github.com/lottman/Remnacust-installer#readme).

Отдельный сайт можно установить позже: `sudo remnacust install-subscription-page`. Он подключается к локальной или удалённой панели с ограниченным API-токеном. [Настройка сайта](subscription-page/README.md).

## Возможности

- Пользователи, сквады, сроки, трафик, импорт/экспорт и массовые операции. `FROZEN` приостанавливает доступ и сохраняет остаток срока; активация возобновляет отсчёт.
- HWID и персональные ключи, число устройств и отзыв доступа.
- Квоты хостов/тегов в GiB и скорость в Mbps, включая пределы пользователя и устройства на совместимых Node/Core.
- Профили Xray, хосты, шаблоны подписок, правила ответов и история конфигураций.
- Автовыбор, категории геофайлов, DIRECT/REJECT и маршруты через настроенные группы.
- Здоровье нод, статистика, сессии, резервные копии и API-токены с отдельными правами.

Адреса управления нодой собраны в одном списке: IPv4, IPv6 и имена хостов, до 65 уникальных записей с учётом выключенных. Порядок задаёт приоритет, переключатель разрешает адрес для связи панели. Сохранённые адреса можно переставлять и выключать; для исправления добавьте новый адрес. Карточка показывает текущий адрес управления. Настроенный SOCKS5 используется для всех резервных адресов; сбой прокси не вызывает прямой обход. Столбец прокси показывает наличие настройки, а не исправность соединения. [Обслуживание нод](docs/NODE-COMPATIBILITY.md).

В компактном списке первый включённый адрес отмечен фиолетовой меткой «Панельный». С Node 1.1.39 полный поиск назначенных IPv4/IPv6 выполняется при первом доступном ответе API, далее — не чаще раза в 30 минут, в том числе когда Core ещё не запущен. Интервал сохраняется после перезапуска панели. Полный успешный поиск добавляет новые IP и удаляет исчезнувшие ранее найденные или подтверждённые нодой IP. Ручные IP, которых нода никогда не сообщала, и имена хостов сохраняются; порядок и выключенные состояния оставшихся строк не меняются. «Повторно найти IP» запускает ту же проверку сразу. Ошибка или неполный ответ не очищают список. Нода сообщает интерфейсы своей ОС: отвязка у хостера станет видна после обновления этих интерфейсов.

Хост помечается как DANGLING, если выбранный профиль или inbound отсутствует либо inbound больше не принадлежит этому профилю. Выберите действующую пару и сохраните хост; клонирование требует корректной привязки. Выключенный хост или недоступная нода сами по себе не означают повреждённую привязку.

Геофайлы управляются общим переключателем и настройкой шаблона. Для стандартных наборов можно настроить автообновление раз в 48 часов с изменяемым интервалом; «Обновить сейчас» проверяет источник без замены файла при неизменном SHA-256. Стандартные категории доступны вместе с пользовательскими. При включённом общем переключателе и доступных полных наборах обновление подписки в Happ восстанавливает стандартные файлы, сохраняя ручные Routing/geodata. [Геофайлы](docs/GEOFILES.md).

Если все адреса управления выключены, панель не запускает и не перенастраивает ноду через скрытый резерв. Параллельное изменение параметров управления проверяется на конфликт: перечитайте форму перед повторным сохранением. Сохранённые изменения ожидают применения и повторяются после временного сбоя доставки; проверяйте итоговое состояние ноды. Массовое назначение профиля и inbound сохраняется согласованно.

Адаптивный Xera HTTP предлагает «Сбалансированный» (balanced), «Низкая задержка» (low-latency) и «Нестабильная сеть» (unstable-network). По измеренным HTTP-ответам, передаче данных и ожиданию запросов они регулируют параллелизм. При наличии adaptive обязательны все три поля: mode, minStreams и maxStreams. Целые границы — от 1 до 32, минимум не больше максимума; форма панели предлагает 4/32. Считаются одновременно активные HTTP-запросы отдельно для каждого направления, назначения и версии настроек транспорта. Это не число TCP-соединений или пользователей и не распределение CPU.

«Применить в JSON» обновляет черновик; профиль сохраняется отдельно. Для клиентских параметров inbound затем обновите подписку в приложении. Без адаптации прежние ручные настройки сохраняются. Подстройка влияет только на новые запросы, не прерывая и не повторяя начатые. Нужен Remnacust Core 1.1.22 или новее в клиенте с поддержкой Xera HTTP. Профили используют измеренную обратную связь без обучения ИИ и не гарантируют невидимость для DPI или преимущество в конкретной стране.

Ручной JSON и extra, прежние режимы передачи auto/stream-auto, ALPN, padding и квоты сохраняются.

Управление через API сохраняет проверки прав и ограничения административных операций. Подготовлены обновления руководства на RU/EN/FA/ZH и исправления зависимостей безопасности. [Изменения Panel/Page 1.1.7.135](docs/releases/1.1.7.135.md).

Обычные ноды и страницы Remnawave сохраняют базовую работу в пределах их протоколов и API. Расширенные ограничения хостов, устройств и учёт автовыбора требуют совместимых наших Node/Core. Сетевой сбой или неизвестная совместимость не разрешают снимать установленные ограничения. [Совместимость нод](docs/NODE-COMPATIBILITY.md).

## Подписки, геофайлы и CDN

Текст шаблона можно редактировать, пока список хостов ещё загружается или недоступен. Инструменты, которым нужны хосты, показывают собственное состояние загрузки или ошибки; ошибка получения самого шаблона требует повторной загрузки.

Состав пула автовыбора и хосты, на которых он показывается, настраиваются отдельно. Пул выбирается хостами либо тегами. Состав обновляется вместе с подпиской; сервер для нового соединения выбирает стратегия клиента. Набор стратегий зависит от приложения и формата. [Автовыбор](docs/XRAY-AUTOSELECT.md).

«Распределять соединения» распределяет новые соединения между доступными участниками, без измерения CPU или свободной полосы. Xray использует roundRobin с HTTP-проверками, Mihomo/Clash/Stash — load-balance с round-robin. Для sing-box явно используется urltest по времени HTTP-ответа; циклического распределения в этом формате нет. Открытые соединения остаются на прежнем сервере.

В дополнительных настройках подписки включите JSON на базовом пути и общий переключатель системы геофайлов (по умолчанию выключен). Затем GEO включается отдельно через меню ⋯ каждого шаблона; значок рядом показывает состояние. Для новых шаблонов GEO выключены. Геофайл загружается с ПК или по HTTPS в общую библиотеку. Небольшие наборы встраиваются в JSON; большие могут передаваться объединёнными DAT поддерживаемым Happ/INCY. Для полной маршрутизации нужна JSON-подписка: включите JSON на базовом пути или используйте `/json`. URI/Base64 не переносит весь набор правил. После сохранения шаблона обновите подписку в приложении. [Геофайлы](docs/GEOFILES.md).

Порог встроенных правил настраивается в разделе «Геофайлы»: 1–250 000 адресов/условий, по умолчанию 20 000, отдельно для каждого итогового профиля. Ограничения размера и сложности могут потребовать DAT раньше. При выключенной автоматизации ручные настройки Xray сохраняются.

Файлы библиотеки можно редактировать; готовые наборы сохраняются копией с новым именем. Под ними добавляются отдельные адреса с DIRECT, блокировкой или выбранным маршрутом VPN.

Домены: **Подписка → Настройки → Страницы подписки**. Основной домен синхронизируется с `SUB_PUBLIC_DOMAIN` через службу установщика. На основной домен допускается один CDN. В карточке пользователя доступны обычные/CDN-ссылки и QR-коды.

Для VK/Yandex перенесите из карточки CDN источник, Host/SNI и сгенерированную пару заголовка запроса. Не включайте общий кеш ответов подписки. Адрес backend и API-токен — серверные настройки; их нельзя подставлять в публичные ссылки. [Домены и CDN](docs/SUBSCRIPTION-DOMAINS.md) · [API и права](docs/API.md).

## Обновление и диагностика

```bash
sudo remnacust upgrade-panel
sudo remnacust upgrade-node
sudo remnacust upgrade-subscription-page --page-id ID
```

Перед обновлением сохраните конфигурацию и резервную копию вне сервера. Обслуживание системных пакетов, требующее ответов на вопросы, выполняйте в интерактивном SSH-сеансе; обновление компонента из панели может отложить этот этап и показать уведомление в журнале. Автоматической перезагрузки сервера нет.

CLI-журналы: `/opt/remnacust/logs/installer-panel.log`, `installer-node.log`, `installer-subscription-page.log`. Следующее действие того же компонента заменяет его журнал. При ошибке показывается путь. Обновление панели также сохраняет `panel-update-<ID>.log`; каталог журналов должен оставаться закрытым.

Ноды могут обслуживать последнюю конфигурацию без панели при действующих ключах, сроках и локальном остатке квот. Новый резерв и изменения доступа требуют связи; бесконечная автономность не обещается. CDN, DNS и proxy ноды должны работать независимо. [Автономность](docs/NODE-AUTONOMY.md).

Если подписка временно не загрузилась, проверьте журнал, доступность панели, права токена страницы и настройки CDN. Не заменяйте ключи пользователя для исправления сетевого сбоя. [Операции](docs/OPERATIONS.md).
