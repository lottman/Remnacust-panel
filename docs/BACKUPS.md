# Резервные копии и восстановление

Штатная копия панели сохраняет базу данных. Отдельно сохраняйте .env, исходный APP_SECRET, сертификаты, настройки reverse proxy и пароль копий. Важные копии храните вне сервера.

## Пароль и создание копии

При новой установке установщик спрашивает пароль резервных копий; Enter создаёт его автоматически. Пароль показывается после установки и сохраняется в backup-password.txt каталога панели с закрытым доступом. Сохраните его отдельно от сервера.

Откройте **Резервные копии**, введите пароль и создайте копию либо настройте расписание. Отправка копий настраивается отдельно от общих уведомлений. Пустая настройка пароля в образце окружения не включает автоматическое резервирование. Если раздел сообщает, что пароль не настроен, выполните настройку по руководству выбранного установщика.

Не заменяйте APP_SECRET для сброса пароля копий: он нужен и другим сохранённым секретам. Новый пароль не открывает прежний архив.

## Что содержится в архиве

ZIP защищён паролем AES-256. Внутри находится database.dump — сжатый PostgreSQL custom-format dump, без дополнительного шифрования самого файла dump.

Копия включает пользователей, ключи, блокировки устройств, лимиты, учёт трафика, конфигурации и историю миграций. Диагностические записи состояния нод и записи подключений исключены из восстанавливаемых данных. Нужные диагностические выгрузки скачивайте отдельно.

Архив не заменяет копию всей установки. Размер зависит от сохранённых данных; фиксированный размер или коэффициент сжатия не гарантируется.

## Проверка копии

Откройте ZIP совместимым архиватором в закрытом каталоге и введите пароль по запросу. Не помещайте пароль в командную строку или журналы.

Проверьте оглавление извлечённого файла средствами PostgreSQL:

```bash
pg_restore --list database.dump
```

Если нужен просмотр SQL без восстановления:

```bash
pg_restore --file=database.sql database.dump
chmod 600 database.sql
```

Используйте утилиты той же основной версии, что создала dump, или более новые совместимые утилиты. Файлы dump и SQL содержат ключи доступа; после проверки удалите ненужные расшифрованные копии.

Успешное чтение оглавления не заменяет пробное восстановление. Проверяйте восстановление в отдельной базе с отдельным окружением, не поверх работающей установки. Проверьте вход администратора, пользователей, подписки, устройства и ограничения.

## Восстановление и обновление

Кнопки восстановления в интерфейсе нет: восстановление выполняется на сервере средствами PostgreSQL по процедуре вашей установки. Перед этим остановите процессы, пишущие в целевую базу, и сохраните текущее состояние.

При смене основной версии PostgreSQL нужен отдельный перенос; нельзя подключать старый data volume к образу другой основной версии. Откат образа панели после миграций может потребовать восстановления совместимой копии базы.

После восстановления сохраните журналы нод и выполните [сверку квот](QUOTA-RECOVERY.md). Ноды могут хранить более свежий расход, чем копия базы. Пауза новых резервов не означает удаление сохранённых резервов.

После изменения окружения пересоздайте контейнеры из фактического каталога установки. Обычный restart не перечитывает .env. Не удаляйте том базы или копий при обновлении.

## Старые отдельные зашифрованные dump

Для прежнего формата .dump.enc в репозитории сохранена локальная утилита panel/backup-decrypt.mjs. Она не нужна для обычного database.dump из ZIP.

Файл пароля должен содержать только пароль без перевода строки и иметь закрытые права. Из корня исходников:

```bash
node panel/backup-decrypt.mjs verify legacy.dump.enc password.txt
node panel/backup-decrypt.mjs decrypt legacy.dump.enc password.txt > database.plain.dump
chmod 600 database.plain.dump
```

Проверяйте результат в отдельной базе. Не добавляйте пароль, архив или расшифрованный dump в Git.
