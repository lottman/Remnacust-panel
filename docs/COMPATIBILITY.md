# Версии и совместимость

Панель и страница подписки 1.1.7.97, комплект 1.2.136: изолирован пул загрузок геофайлов от API подписки, ограничены пакеты учёта трафика и записи эпох квот, согласован холодный запуск смешанного парка нод. При недоступном узле независимые ноды продолжают запуск; неизвестная поддержка не отключает защиту. Миграция `20261104190000_utc_access_expiry` исправляет сравнение срока в UTC без изменения сохранённых дат, остатка заморозки и квот. Новых переменных `.env` нет. Node 1.1.22 и Core 1.1.13 сохранены. Обновляйте панель и страницу вместе; обновление панели не заменяет удалённые ноды.

Панель 1.1.7.95 проверяет выданные ключи и пользователей массовой конфигурации наборами SQL. Срок, статус, сквады, блокировка HWID и смена ключей продолжают учитываться. Проверка поддержки ноды выполняется перед тяжёлой сборкой; паузы лимитов читаются одним запросом на ноду. Синхронизации объединяются, одновременно обрабатываются не более трёх нод на процесс, занятая advisory-блокировка повторяется вне транзакции. Подтверждённая штатная Remnawave-нода получает обычную конфигурацию: новые ограничения хоста, правила сайтов и неактивные хосты-исключения на её inbound отключены. Если этот inbound используется и нашей нодой, обе используют совместимые обычные ключи. На отдельных совместимых inbound новые функции сохраняются. Старое наше ядро без учёта получателя автовыбора использует ключи и лимиты серверов пула; обновление Node/Core и подписки включает отдельный учёт. Панель показывает режим совместимости. Неизвестная нода и сетевой сбой сами по себе не отключают ограничения. Существующие резервы квот и финансовые блокировки не стираются при понижении версии. API старых страниц подписки сохранён; страницы со скрытыми ключами не строят ненужные ссылки. Новых переменных .env и миграций нет.

Панель и страница подписки 1.1.7.94, установщик 1.2.133: массовые проверки доступа используют SQL-наборы, синхронизации одной ноды объединяются, ожидание занятой advisory-блокировки выполняется вне SQL-транзакции. Страницы с выключенным показом ключей не создают ненужные ссылки; API старых страниц сохраняется. Запрос сведений обновлённой страницы ожидает до 30 секунд. Для базовой конфигурации штатной Remnawave-ноды не требуется host-policy-v2; квоты, скорость, правила назначения и специальный доступ при неактивной подписке требуют совместимых Node/Core. Настроенные ограничения не обходятся. Node 1.1.22 и Core 1.1.13 сохранены; новых миграций и переменных `.env` нет.

Панель и страница подписки 1.1.7.93, установщик 1.2.132: учёт подключения через автовыбор относится к получателю, отдельно от прямого использования участников пула. Миграция `20261104010000_autoselect_quota_ownership` добавляет внутренние маршруты и ключи. Для общей скорости устройства между маршрутами требуются Node 1.1.22 и Core 1.1.13; после обновления нужна новая выдача подписки клиенту. Прежние ключи и исторический расход сохраняют прежнее поведение. Новых переменных `.env` нет.
