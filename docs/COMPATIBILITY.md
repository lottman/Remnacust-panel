Снимок совместимости на **6 ноября 2026 года**. Опубликованный комплект и локальные изменения ниже разделены: версия в `package.json`, новый текст руководства или успешный тест сами по себе не означают выпуск.

[Состав и изменения выпуска 1.1.7.97](releases/1.1.7.97.md). Исторические версии компонентов и основы прежних комплектов перечислены в [REMNAWAVE-UPDATES.md](REMNAWAVE-UPDATES.md); они не заменяют текущую stable-таблицу.

Обновление Panel не заменяет удалённый Node или Core. Обновление образа Node тоже не доказывает смену работающего Core: ранее выбранное managed-ядро или rollback-версия могут сохраняться в постоянном каталоге. Сверяйте выбранное и запущенное ядро, capabilities и подтверждение применения конфигурации.

## Ресурсы для планирования

| Служба | Минимальный ориентир | Рекомендация |
| --- | --- | --- |
| Panel с её БД и кешем | **2 CPU, 2 GiB RAM, 20 GiB SSD** | **4 CPU и 4 GiB RAM**; оставляйте дополнительное место для роста БД, журналов и резервных копий. |
| Node с Core | **1 CPU, 1 GiB RAM** | Увеличивайте ресурсы по трафику, числу пользователей, транспорту и функциям Core. Это не обещание пропускной способности. |
| Отдельная Subscription Page | **Точный минимум не измерялся** | Для начального планирования можно выделить **1 CPU и 1 GiB RAM**. Это рекомендация, а не установленный тестами минимум. |

Числа Panel/Node опираются на [официальные требования Remnawave](https://docs.rw/install/requirements/). Это исходные ориентиры, не нагрузочная сертификация всех расширений Remnacust. Если службы размещаются на одном VPS, учитывайте их совместный бюджет и запас под фоновые операции; ориентир отдельной Page не включён в бюджет отдельного сервера Panel автоматически.

Для готовых образов **Node.js и Go на хосте не нужны**. **Node.js 24** требуется для сборки и проверок исходников Panel/Page/Node; **Go 1.27.3** — для сборки текущего Core/WASM. Это требования разработки, а не дополнительные пакеты для обычного VPS. Подробности: [BUILDING.md](BUILDING.md).

## PostgreSQL: опубликованное и проверенное локально

Для stable-установки сохраняйте конфигурацию БД выбранного stable-комплекта. Следующая матрица относится к **локальным исходникам с 194 миграциями**; она **не подтверждает всю эту матрицу для выпущенного 1.1.7.97**.

| PostgreSQL, проверенный minor | Миграции под владельцем БД без superuser | Focused проверки текущих исходников |
| --- | --- | --- |
| **14.24** | 194 / PASS | Quota, expiry, diagnostics и одновременная SQL-нагрузка / PASS |
| **15.19** | 194 / PASS | Quota, expiry, diagnostics и одновременная SQL-нагрузка / PASS |
| **16.15** | 194 / PASS | Quota, expiry, diagnostics и одновременная SQL-нагрузка / PASS |
| **17.11** | 194 / PASS | Quota, expiry, diagnostics и одновременная SQL-нагрузка / PASS |
| **18.6** | 194 / PASS | Quota, expiry, diagnostics и одновременная SQL-нагрузка / PASS |

На каждой версии выполнены 468 сравнений старой и новой quota-семантики. Диагностика проверена с ограниченными ролями без `pg_read_all_stats`: учитываются только подключения текущей роли в текущей БД, собственный диагностический PID исключается. Проверки выполнялись на собственных временных loopback-стендах; это не production-замер, полный тест всех функций панели или проверка Installer на всех ОС.

PostgreSQL 13 и более старые версии **не входят в проверенную матрицу**. Список версий, поддерживаемых Prisma, не является обещанием совместимости всей схемы Remnacust. Для новой установки выбирайте поддерживаемую major-версию с актуальными исправлениями. Поддержка **PG14 заканчивается 12 ноября 2026 года**: [политика PostgreSQL](https://www.postgresql.org/support/versioning/).

**При смене major нельзя подключать прежний data volume к новому образу PostgreSQL.** Нужен отдельный перенос через `pg_upgrade` либо dump/restore с проверкой на копии БД. Совместимость утилит и формата резервной копии проверяется отдельно; матрица миграций не доказывает произвольный cross-major restore. [Резервные копии](BACKUPS.md) · [Совместимость схемы с upstream](DATABASE-COMPATIBILITY.md).

## Старые ноды и проверки возможностей

Старая версия Node не означает запрет на всю работу панели. Используется **feature gating по подтверждённым возможностям**, а не требование обновить одновременно весь парк.

| Сценарий | Поведение |
| --- | --- |
| Обычный профиль на подтверждённой штатной Remnawave-ноде | Разрешён совместимый базовый режим. Xray ноды должен поддерживать выбранные протоколы и транспорты. |
| Новые ограничения хоста, скорость, правила назначения, специальный доступ неактивной подписки | Требуются соответствующие возможности агента и Core. Отказ относится к затронутой функции/inbound; ограничения не снимаются молча ради совместимости. |
| Inbound общий для штатной и кастомной ноды | На общем inbound действует совместимый режим. Это не отключает новые функции на независимых совместимых inbound. |
| Учёт получателя автовыбора и общая скорость устройства между маршрутами | Stable Node **1.1.22** + Core **1.1.13**, подтверждённые capabilities и новая выдача подписки клиенту. Старое наше ядро может использовать прежний режим с ключами и учётом участников пула. |
| Неизвестная capability, недоступная нода или сетевой сбой | Это не подтверждение legacy-режима и не разрешение ослабить защиту. Сохраняются действующие ограничения; предусмотренные повтор и диагностика относятся к затронутой операции. |
| Откат версии при существующих квотах | Резервы и финансовые блокировки не стираются. Совместимость отката проверяется отдельно. |

Версия образа, наличие REST-маршрута и успешное сохранение в Panel не равны подтверждённому применению Core. Для конкретных функций сверяйте runtime/capabilities. Подробности: [NODE-COMPATIBILITY.md](NODE-COMPATIBILITY.md), [лимиты](HOST-LIMITS.md), [автовыбор](XRAY-AUTOSELECT.md).
