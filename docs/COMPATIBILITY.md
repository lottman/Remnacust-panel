Снимок совместимости комплекта Panel 1.1.7.124 на **14 ноября 2026 года**. Обновляйте компоненты по их собственным версиям: обновление панели не заменяет удалённую ноду или ядро.

Обновление Panel не заменяет удалённый Node или Core. Обновление образа Node тоже не доказывает смену работающего Core: ранее выбранное managed-ядро или rollback-версия могут сохраняться в постоянном каталоге. Сверяйте выбранное и запущенное ядро, capabilities и подтверждение применения конфигурации.

## Изменения выпуска 1.1.7.124

Редактор и схема соответствуют Core 1.1.21. Обновлены Node.js 26.13.1 LTS и совместимые зависимости интерфейса, API и страницы подписки; сохранены языки RU/EN/FA/ZH, RTL, даты и переводы кодов ошибок. Новых миграций БД нет. [Изменения выпуска](releases/1.1.7.124.md).

## Изменения выпуска 1.1.7.123

Проверка ноды отличает готовый управляющий API от ещё запускающегося Xray. Временный 503 статистики проверяется через authenticated health; первая проверка после запуска панели также запускает восстановление конфигурации. Встроены согласованные Core 1.1.20 и редактор; ноды обновляются отдельно.

## Изменения выпуска 1.1.7.122

Пулы автовыбора поддерживают независимый фильтр явных адресов IPv4/IPv6; режим any сохраняет прежнее поведение. Фильтр не меняет стратегию балансировки, доступ пользователя или квотные ключи. Исправлены IPv6-адрес SOCKS-прокси и определение интерфейса ноды по IPv6-маршруту. Installer 1.2.170 добавляет отдельную IPv6-only NAT-сеть приложениям панели при безопасном preflight; старые сети, БД, кеш и опубликованные порты сохраняются. Ядро и 205 миграций БД не меняются. [Изменения выпуска](releases/1.1.7.122.md).

## Изменения выпуска 1.1.7.121

Добавлен общий выключатель автоматизации геофайлов, по умолчанию выключенный. Миграция 205 сохраняет библиотеку и предпочтения шаблонов; ручные правила и источники не блокируются. Добавлены стандартные источники GeoIP/GeoSite с ручным обновлением и отдельными расписаниями. Исправлены восстановление стандартных DAT при Base64, повторная обрезка категорий клиентом, выбор категорий и защита используемых файлов. Валидация больших загрузок уступает цикл событий. Обновлена транзитивная FTP-библиотека. [Изменения выпуска](releases/1.1.7.121.md).

## Изменения выпуска 1.1.7.120

Исправлены анимации закрытия окон и единая палитра редактора, добавлены часы приближающейся оплаты работающих нод. Новый порядок причин отказа применяется по умолчанию и не меняет сохранённые настройки. Node 1.1.32 ограничивает задержку переподключения к приватному Xray API и ожидает завершения извлечения пользователей. При отказе синхронизации изменения пользователей блокируются до успешного применения; работающий Core сохраняется. Новых миграций базы нет. [Изменения выпуска](releases/1.1.7.120.md).

## Изменения выпуска 1.1.7.119

Исправлен возврат со скачанных кастомных DAT на стандартные источники Happ/INCY после отключения всех автоматических файлов в подписке или возврата всех её профилей к обычным правилам. Пустые URL не считались подтверждением восстановления клиентских файлов. Восстановление использует сохранённую историю профиля и устройства; ручные источники имеют приоритет. Новых миграций после 1.1.7.118 нет. Подробности и ограничения — в [изменениях выпуска](releases/1.1.7.119.md).

## Изменения выпуска 1.1.7.118

Исправлена передача даты автоматической разморозки из всех четырёх форм: выбранное локальное время сохраняется как UTC без потери часов и минут. Добавлены доступные названия кнопок профилей, сквадов и выбора inbound. Новые установки используют PostgreSQL 18.6; обновление приложения сохраняет существующий образ БД и том. Проверки прав API-токенов не расширяют доступ.

Исправлена ложная ошибка A039 после сохранённой заморозки и аналогичные ответы при изменении доступа. Изменения статуса и срока сохраняются вместе с заданием применения; недоступная нода не отменяет сохранение. Повторы ограничены по параллельности, используют актуальное состояние и продолжаются после перезапуска панели. Добавлена обязательная автоматическая разморозка с заранее назначенной датой; при простое панели срок не увеличивается. API новых заморозок требует `frozenUntil` с часовым поясом. Старые записи без даты сохраняются до назначения даты или ручной активации. При переходе с 1.1.7.116 и более старых версий нужны миграции 203 и 204; после 1.1.7.117 новых миграций нет. Сохранены исправления интерфейса, блокировки HWID и сборка обоих ядер на Go 1.27.4 из предыдущего выпуска. [Полный список](releases/1.1.7.118.md).

[Изменения 113](releases/1.1.7.113.md): переход встроенных правил в DAT выбирается отдельно для каждого итогового профиля, включая варианты одного хоста. Настройка 1–250 000 условий (по умолчанию 20 000) сохраняется. Удалён прежний дополнительный порог 90 КБ; независимые пределы размера профиля, компиляции, сложности и полного ответа действуют. Ручные правила при выключенной автоматизации не изменяются.

Проверены официальные [Remnawave Backend 3.4.9](https://github.com/remnawave/backend/releases/tag/3.4.9) и [Node 3.4.5](https://github.com/remnawave/node/releases/tag/3.4.5). Новое включение хостов по SRR из 3.4.9 не переносилось в этот выпуск. Устранение конфликта Lua routing и служебного API уже реализовано в нашей ноде отдельным приватным API-сокетом; Xray 26.11.9 уже включён. Основа и версии собственных компонентов не подменяются номерами upstream.

Reviewed official Backend 3.4.10 and Node 3.4.5. Backend 3.4.10 corrects a per-SRR rule name for the optional 3.4.9 feature, which is not present in this fork. The optional per-SRR host feature is not part of this release. Our node already preserves Lua routing through a separate private API socket, and Core already includes Xray 26.11.9. The table reports our actual component versions rather than claiming a wholesale upstream upgrade.

Если службы размещаются на одном VPS, учитывайте их совместный бюджет и запас под фоновые операции; ориентир отдельной Page не включён в бюджет отдельного сервера Panel автоматически.

Для готовых образов **Node.js и Go на хосте не нужны**. **Node.js 26.13.1 LTS** требуется для сборки и проверок исходников Panel/Page/Node; **Go 1.27.4** — для сборки текущего Core/WASM. Это требования разработки, а не дополнительные пакеты для обычного VPS. Подробности: [BUILDING.md](BUILDING.md).

## PostgreSQL: проверенная матрица

Для **Panel 1.1.7.121** все **205 файлов миграций** последовательно применены под ролью `NOSUPERUSER / NOCREATEDB / NOCREATEROLE` на каждой версии ниже. [CI-прогон с завершёнными заданиями всех пяти версий](https://github.com/lottman/Remnacust-panel/actions/runs/43388357641). На каждой версии проверены диапазон порога 1–250 000, сохранение предпочтений шаблонов при выключенном по умолчанию master, блокировка недопустимых включений и конкурентных изменений, rollback, поколение кэша, quota-семантика, UTC-границы доступа и ограниченная диагностика. Это проверка исходников на одноразовых стендах, не изменение production-БД.

| PostgreSQL, проверенный minor | Миграции под владельцем БД без superuser | Целевые проверки |
| --- | --- | --- |
| **14.24** | 205 / PASS | Геофайлы, кэш, quota, expiry, diagnostics / PASS |
| **15.19** | 205 / PASS | Геофайлы, кэш, quota, expiry, diagnostics / PASS |
| **16.15** | 205 / PASS | Геофайлы, кэш, quota, expiry, diagnostics / PASS |
| **17.11** | 205 / PASS | Геофайлы, кэш, quota, expiry, diagnostics / PASS |
| **18.6** | 205 / PASS | Геофайлы, кэш, quota, expiry, diagnostics / PASS |

Диагностика проверена с ограниченными ролями без `pg_read_all_stats`: учитываются только подключения текущей роли в текущей БД, собственный диагностический PID исключается. HWID, изоляция хостов, скрытые ключи, FROZEN, синхронизация доменов, история шаблонов и нагрузка подписки отдельно проверены основным backend-заданием на PostgreSQL 17. Проверки выполнялись на собственных временных стендах; это не production-замер, полный тест каждой функции на каждой major-версии БД или проверка Installer на всех ОС.

PostgreSQL 13 и более старые версии **не входят в проверенную матрицу**. Список версий, поддерживаемых Prisma, не является обещанием совместимости всей схемы Remnacust. Для новой установки выбирайте поддерживаемую major-версию с актуальными исправлениями. Поддержка **PG14 заканчивается 12 ноября 2026 года**: [политика PostgreSQL](https://www.postgresql.org/support/versioning/).

**При смене major нельзя подключать прежний data volume к новому образу PostgreSQL.** Нужен отдельный перенос через `pg_upgrade` либо dump/restore с проверкой на копии БД. Совместимость утилит и формата резервной копии проверяется отдельно; матрица миграций не доказывает произвольный cross-major restore. [Резервные копии](BACKUPS.md) · [Совместимость схемы с upstream](DATABASE-COMPATIBILITY.md).

## Старые ноды и проверки возможностей

Старая версия Node не означает запрет на всю работу панели. Используется **feature gating по подтверждённым возможностям**, а не требование обновить одновременно весь парк.

| Сценарий | Поведение |
| --- | --- |
| Обычный профиль на подтверждённой штатной Remnawave-ноде | Разрешён совместимый базовый режим. Xray ноды должен поддерживать выбранные протоколы и транспорты. |
| Новые ограничения хоста, скорость, правила назначения, специальный доступ неактивной подписки | Требуются соответствующие возможности агента и Core. Отказ относится к затронутой функции/inbound; ограничения не снимаются молча ради совместимости. |
| Inbound общий для штатной и кастомной ноды | На общем inbound действует совместимый режим. Это не отключает новые функции на независимых совместимых inbound. |
| Учёт получателя автовыбора и общая скорость устройства между маршрутами | Stable Node **1.1.22** + Core **1.1.13**, подтверждённые capabilities и новая выдача подписки клиенту. Старое наше ядро может использовать прежний режим с ключами и учётом участников пула. |
| Неизвестная capability, недоступная нода или сетевой сбой | Это не подтверждение legacy-режима и не разрешение ослабить защиту. Сохраняются действующие ограничения; предусмотренные повтор и диагностика относятся к затронутой операции. |
| Откат версии при существующих квотах | Резервы и финансовые блокировки не стираются. Совместимость отката проверяется отдельно. |

Версия образа, наличие REST-маршрута и успешное сохранение в Panel не равны подтверждённому применению Core. Для конкретных функций сверяйте runtime/capabilities. Подробности: [NODE-COMPATIBILITY.md](NODE-COMPATIBILITY.md), [лимиты](HOST-LIMITS.md), [автовыбор](XRAY-AUTOSELECT.md).
