Дата: 14 октября 2026 года. Сверка с клиентским файлом «Remnacust_Новые_возможности.docx» от 13 октября. Исходная панель 1.1.7.30; исправление подготовлено для панели 1.1.7.31, установщика 1.2.57, ноды 1.1.9 и ядра 1.1.5.

## Что проверено для HWID

Новая установка принудительно задаёт HWID_ENABLED_DEFAULT=true; seed создаёт включённые правила в PostgreSQL. Если число у пользователя отсутствует, действует общий fallbackDeviceLimit=999. Положительное число задаёт персональный максимум, 0 снимает ограничение количества. Запрет регистрации новых устройств действует отдельно, в том числе для безлимитных пользователей. Уменьшение числа не удаляет автоматически уже зарегистрированные устройства. Для постоянного запрета устройства используется блокировка; удалённое устройство вправе зарегистрироваться заново, если регистрация разрешена.

Повторный запуск и обновление сохраняют явное отключение HWID, резервный лимит и персональные значения. Для старой БД без hwidSettings выполняется инициализация. HWID — идентификатор, передаваемый совместимым клиентом при запросе подписки; это не аппаратная аттестация и не доказательство количества физических телефонов. Клиент без поддерживаемого HWID не проходит ограничение количества, кроме явно заданного безлимита или настроенного правила ответа, отключающего HWID-проверку. Отзыв отдельного действующего подключения требует персональных ключей и совместимых компонентов.

## Исправление

В персональном режиме ответ о превышении количества обходил настроенные сообщения и возвращал жёстко заданную русскую строку. Теперь обычный и персональный режимы используют общий путь ответа: сохраняют текст администратора, клиентский формат, скрытие примечаний, отдельное объявление и HWID-заголовки. Правила допуска, значения лимитов и хранящиеся настройки не менялись. Добавлены пять проверок этого поведения, интеграционный тест seed/конкурентной регистрации с PostgreSQL и проверка живого API в выпуске.

## Фактические проверки и границы

Пройдены типизация backend/frontend/ноды, backend- и frontend-регрессии, проверка переводов и документации, сборка панели. PostgreSQL: 155 миграций, HWID/defaults/конкурентная регистрация, квоты, удаление/outbox, очистка журналов, долговременная оптимизация, инжект скрытых хостов, dump/restore. Для исторической миграции проверены оба известные LF/CRLF-хэша, отказ подменённого хэша и сохранение защищённых данных после перезапуска.

Проверка ядра: go test -race для infra/conf, transport/internet/xerahttp, app/dispatcher, app/proxyman/command, app/commander, proxy/olcrtc. У app/proxyman/command нет отдельных Go unit-тестов; живой тест отзыва использует его API. Govulncheck: нет уязвимостей вызываемого кода или импортируемых пакетов; обнаружена одна запись на уровне требуемого модуля без выявленного вызова уязвимого кода.

Проверки выполнялись на одноразовых локальных БД и контейнерах. Они не меняют производственные лимиты/данные и не заменяют испытание реальных IdP, аппаратных passkey, внешних SSH/Telegram/CDN/ACME или полной нагрузки всех клиентских протоколов. Совместимость специальных транспортов с конкретным приложением нужно проверять отдельно.

Клиентский файл соответствует реализованному набору функций с указанными в нём условиями совместимости. Не обнаружено пункта, требующего добавления отсутствующей функции. Найденное расхождение поведения сообщения HWID исправлено. Выпуск должен быть опубликован только после успешной проверки новой сборки на amd64 и arm64.
