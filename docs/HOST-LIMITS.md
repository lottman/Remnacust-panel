# Квота и скорость хостов и тегов

Настройки находятся в карточке хоста и в настройках его тегов. Лимит пользователя здесь относится к одному пользователю **в выбранном хосте**, а не к одному устройству и не ко всем нодам учётной записи вместе. Отдельное глобальное поле скорости в карточке пользователя не требуется.

| Настройка | Область действия | Единица / API |
| --- | --- | --- |
| Квота пользователя хоста | Расход одного пользователя на данном хосте | GiB в форме; `userTrafficLimitBytes` в байтах |
| Скорость пользователя хоста | Все устройства и соединения одного пользователя на данном хосте, загрузка и отдача вместе | Mbps; `serverSpeedLimitMbps` |
| Общая скорость хоста | Все пользователи данного хоста вместе | Mbps; `totalSpeedLimitMbps` |
| Квота пользователя тега | Общий расход пользователя на участвующих хостах тега | GiB в форме; `limitBytes` в байтах |
| Скорость пользователя тега | Одинаковый предел отдельно на каждом участвующем хосте | Mbps; `speedLimitMbps` настроек тега |
| Общая скорость тега | Общий пул участвующего трафика | Mbps; `totalSpeedLimitMbps` настроек тега |

`speedLimitMbps` **самого хоста** — другое поле: целевой параметр Brutal в клиентской конфигурации. Он не заменяет серверный `serverSpeedLimitMbps`. Для принудительного ограничения нужны совместимые Remnacust Node и Core; лимит не зависит от наличия настройки скорости в клиентском приложении.

## Пример

Для хоста A установите скорость пользователя 2 Mbps. Два устройства пользователя Иван делят эти 2 Mbps; это не по 2 Mbps каждому. У пользователя Анна свой предел 2 Mbps. Общая скорость хоста, если задана, дополнительно ограничивает их суммарный трафик. Это верхние пределы, а не гарантированная полоса или равное распределение между устройствами.

Пример выше предполагает один обслуживающий узел. Если область назначена нескольким нодам, панель консервативно делит её скорость между назначенными нодами; неактивная доля не означает гарантированное перераспределение полосы.

Чтобы назначить правило нескольким хостам, задайте скорость пользователя у тега и включите «Применять скорость пользователя тега» на нужных хостах. На хосте B Иван получит отдельный предел этого хоста. Если нужен общий пул группы для всех участвующих пользователей, используйте именно общую скорость тега.

## Ноль, наследование и единицы

- `0` или пустое значение скорости отключает соответствующий собственный предел; включённые ограничения тегов сохраняются. В списке отсутствие предела отображается как `∞`.
- Квота тега, скорость пользователя тега и общая скорость тега включаются у хоста тремя независимыми переключателями. Добавление тега не означает снятие собственных лимитов хоста.
- Одновременно действующие ограничения не складываются в большую разрешённую скорость: более строгий предел продолжает ограничивать трафик.
- Скорость задаётся целыми значениями 0–10000 Mbps. Mbps уже означает мегабиты **в секунду**; дополнительное `/сек` не нужно. 8 Mbps приблизительно соответствуют 1 MB/s без накладных расходов.
- Объём квоты задаётся в GiB (1024³ байт). Это не Mbps и не длительность.

В форме сначала расположены квота и скорость одного пользователя, затем общая скорость и коэффициент учёта. На узком экране поля располагаются в одну колонку. Подпись единицы видна внутри числового поля. Обозначения Mbps и GiB сохраняются на английском при любом языке интерфейса.

## Работа без панели

Скорость обеспечивается локальным ядром. Для ограниченного объёма используются выданные локальные резервы квоты: панель не нужна для каждого пакета, но нужна для выдачи нового резерва. При исчерпании остатка доступ не становится безлимитным. Сброс немедленно получают доступные ноды, остальные — при восстановлении связи; старые резервы на недоступных нодах могут временно увеличить общий расход сверх новой квоты. Подробности учёта и восстановления: [QUOTA-RECOVERY.md](QUOTA-RECOVERY.md).

## Реализация и проверка

Форма сохраняет существующие поля API, без новой миграции и параллельного механизма ограничения. Преобразование Mbps в байты в секунду выполняется в политике панели; Core применяет общий bucket владельца в области хоста и отдельный bucket общей скорости.

Существующие тесты Core в `xray/app/dispatcher/host_policy_test.go` проверяют разделение скорости между устройствами и соединениями, независимость пользовательской скорости разных хостов, общую скорость хоста и пул группы:

```bash
cd Remnacust-core/xray
go test ./app/dispatcher -run 'TestHostPolicy(SharesSpeedAcrossConnectionsAndDevices|V2TagUserSpeedIsIndependentPerHost|V2WholeHostSpeedAcrossUsersAndDirections|V2GroupSpeedAcrossHosts)$' -count=1
```

Эти тесты проверяют механизм ядра. Состояние конкретной рабочей ноды проверяется отдельно после доставки политики; сохранённое значение формы само по себе не подтверждает её применение.
