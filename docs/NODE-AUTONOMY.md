# Работа нод без панели

Путь клиент → CDN → прокси ноды → Xray не должен проходить через панель.
Панель выдаёт конфигурацию и права; рабочая нода проверяет ключи локально.
Доступность подписки и добавление новых ключей при выключенной панели — отдельные
операции, они не гарантируются этим механизмом.

## Два состояния установленной ноды

Автономная политика `remnacust-quota-reserves-v1` использует сохранённые сроки
идентичностей и ограниченные локальные резервы USER/HOST/TAG. Прежний 90-секундный
срок политики её не останавливает. Сохраняются скорости, правила назначения,
запреты и сроки подписки. Ключи и состояние ядра восстанавливаются из приватного
checkpoint; квоты сохраняются в журнале. Административная пауза не отменяется
автоматическим восстановлением.

Старая политика без локальных резервов закрывает защищённые подключения после
90 секунд без продления. Простое увеличение этого времени или удаление проверки
позволило бы обходить квоты и сроки. Автоматический координатор переводит
совместимые ноды через проверку возможностей, барьер старого расхода, резервирование
и подтверждение применения. Недоступный участник общей квоты может задерживать
переход; его долг и резерв нельзя просто исключить из расчёта.

## Проверка перед обновлением

Локальная команда внутри контейнера панели:

```sh
node /opt/app/dist/cli.js check-node-continuity
```

Она возвращает JSON и код 0 только при подтверждении готовности. Проверяются все
включённые ноды с назначенным профилем: завершённый автономный режим, общий контроль
квоты пользователя, совпадение сохранённых desired/applied ревизий и источников,
живое подтверждение той же ревизии, экземпляра ядра и журнала квот. Восстановление
БД, активная recovery-пауза, недоступность и изменение состава/политики во время
проверки отклоняют результат. Пустой состав допустим. Результат — снимок состояния,
а не обещание бесконечного резерва трафика или доступности инфраструктуры.

Кнопка обновления проверяет это до передачи задания службе. Установщик проверяет
ещё раз непосредственно перед остановкой приложений. Старый CLI не запускается
в интерактивном режиме: сначала проверяется наличие команды. Если её нет,
проверка выполняется из уже проверенного нового образа во временном контейнере
с сетью текущей панели, приватным окружением, read-only root и без дополнительных
capabilities или host mounts. Старая панель остаётся работать. Для осознанного
обслуживания с возможным перерывом доступен явный `--allow-disruption`; этот
параметр не отключает защиту в ядре.

`docker compose down`, остановка сервера или ручная остановка ноды обходят эту
проверку. Панель и ноду нужно держать в разных Compose-проектах; CDN должен указывать
на ноду. Обновление самой ноды или её ядра может прервать текущие соединения.

## Границы безопасности

- Проверка не выдаёт новый кредит, не снимает блокировки, не изменяет конфигурацию
  и не удаляет старые гранты. Окончание срока или резерва продолжает закрывать доступ.
- При отключённой панели сохраняется последнее подтверждённое состояние. Новую
  блокировку или заморозку, заданную на панели во время разрыва, нода узнает после
  восстановления связи. Немедленный удалённый отзыв без канала связи невозможен.
- Команда использует сохранённые ключи нод: TLS 1.3, проверку своей CA, mTLS и
  короткоживущий RSA JWT. Проверка имени соответствует существующей схеме частной
  CA/SNI нод. Перенаправления запрещены, системный HTTP-прокси не используется,
  SOCKS задаётся только сохранённой настройкой администратора.
- Одновременно проверяются не более восьми нод; ограничены время, размер ответа
  и состав. Ошибки содержат UUID и фиксированный код без адресов, токенов и сертификатов.
- Проверка из интерфейса доступна только администратору в уже существующем endpoint
  обновления. Нового публичного endpoint или доступа для API-токенов нет.

Подтверждение в SQL само по себе не является живым подтверждением. Координатор
повторно проверяет incarnation перед начальным барьером; readiness не выводится
только из глобальной фазы ACTIVE.
