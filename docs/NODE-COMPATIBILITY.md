# Совместимость нод

Панель, агент ноды и запущенное ядро имеют независимые версии. Текущий комплект указан в [таблице совместимости](COMPATIBILITY.md). Обновление панели не обновляет удалённые ноды, а обновление образа ноды может сохранять ранее выбранный managed Core.

Проверяйте версию агента, фактически запущенный Core и поддержку нужной функции в карточке ноды. Номер из старого наблюдения не подтверждает готовность нового адреса или ядра.

## Подключение

В форме ноды используется единый список **IP-адреса**: IPv4, IPv6 и имена хостов, до 65 уникальных записей с учётом выключенных. Включённые адреса задают управляющую связь в порядке списка. Сохранённый адрес можно переставить или выключить; изменить либо удалить его нельзя. Для исправления добавьте правильный адрес и выключите старый.

Все адреса используют один настроенный порт API и один настроенный SOCKS5. Не указывайте адрес другого сервера. Проверьте текущий адрес управления и время последнего наблюдения; ответ ping не подтверждает рабочий API.

При недоступном прокси ошибка сохраняется, прямого обхода нет. Столбец прокси показывает наличие настройки, а не её исправность. Управляющий proxy не направляет через себя VPN-трафик пользователя. [Порядок проверки](OPERATIONS.md).

## Стандартные агенты Remnawave

Панель выбирает совместимый формат обмена по версии агента. Старому агенту не требуется обновление только ради базового подключения, если его API и протоколы поддерживаются.

| Возможность агента | Что доступно |
| --- | --- |
| Старые версии без массовых действий | Операции с пользователями выполняются отдельными запросами |
| Нет сведений о CPU/RAM | Показатели остаются неизвестными; это не нулевая нагрузка |
| Нет геопроверки | Отдельная функция проверки недоступна; обычная работа профиля может сохраняться |
| Нет расширений Remnacust | Базовая работа профилей и пользователей в пределах возможностей агента и Core |

Для Remnawave Node 1.0–1.4 используется старый HTTP API. Разрешайте его только для конкретных адреса и порта в REMNACUST_LEGACY_HTTP_NODES и используйте закрытую сеть или защищённый туннель. Ошибка TLS не вызывает автоматический переход на HTTP.

Совместимость формата запросов не означает, что все старые контейнеры, клиентские протоколы и сетевые условия проверены в реальном трафике. После переноса проверьте подписку, подключение и учёт расхода.

## Функции ядра

Жёсткие лимиты хостов и тегов, отдельный лимит устройства, учёт получателя автовыбора, ограничение сайтов и немедленный отзыв открытых соединений требуют совместимых Remnacust Node/Core. Обычная поддержка XHTTP не означает поддержку Xera HTTP.

В подтверждённом стандартном режиме недоступные расширения не применяются; сохранённые настройки остаются в панели. Если inbound совместно используется стандартной и кастомной нодой, проверьте ограничения этой конфигурации перед выдачей пользователям.

Старое кастомное ядро может учитывать лимиты участника вместо получателя автовыбора. Для отдельного учёта получателя обновите агент, запущенный Core и клиентскую подписку. Исторический расход не перераспределяется задним числом.

Понижение версии не освобождает уже выданный резерв и не снимает блокировку автоматически. Отсутствие связи не считается разрешением отключить ограничения.

## Ошибки применения

Если обязательная политика не применена, панель сохраняет прежнюю рабочую конфигурацию. Новая конфигурация остаётся ожидающей до успешной проверки и доставки. Это отличается от полностью остановленного Core: доступный API с остановленным Core не подтверждает работающую VPN-ноду.

При необходимости обновления проверьте оба компонента — агент и ядро. После успешного применения обновите подписку и проверьте клиентское подключение. Не подменяйте индивидуальные ключи общим ключом пользователя для устранения ошибки.

Потеря управляющей связи сама по себе не исключает разрешённый хост из подписки. Пока нода недоступна или ещё не получила ключи, профиль может оставаться в клиенте, но новое подключение не заработает.

## Работа без панели

Нода с применённой автономной политикой использует сохранённую конфигурацию, сроки и локальный остаток резерва. Для нового резерва и изменений доступа нужна связь с панелью. После исчерпания остатка ограничение не становится безлимитным.

Отзыв на физически недоступной ноде применяется после восстановления связи. После запуска совместимый агент запрашивает актуальное состояние; сохранение настройки в панели не заменяет подтверждение применения.
