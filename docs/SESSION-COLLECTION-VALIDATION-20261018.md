# Проверка сбора сессий — 18 октября 2026

Проверены исходники панели c201f9a653a24c5056dc3eb76c67a7ad5c4bcda9 и ноды 7a4b8804dc43a580d580abe3a285e35e791d13c0. Ядро — опубликованный Core 1.1.7 из образа ноды 1.1.11 выпуска 1.2.63; в новом выпуске оно не меняется.

В отдельном контейнере без NET_ADMIN применена конфигурация настоящего генератора ноды с уровнем политики 17. Открыты три VLESS TCP-соединения: обычного пользователя, персонального устройства и персонального устройства с привязкой к хосту. Соединения передавали данные через локальный echo-сервер. Для хоста настроено отдельное разрешение в изолированном файле политики; состояние работающих нод не изменялось.

Настоящий gRPC SDK, сервис статистики ноды и функция группировки панели получили все три идентификатора и связали их с одним владельцем. Один IP не дублировался. Три повторных опроса не стирали активные наблюдения. Персональный запрос пользователя включал его устройства и хосты. Через 1,5 секунды после закрытия соединений активные IP исчезли. Проверка завершилась успешно.

Регрессионные тесты отдельно проверили ошибки SDK, исключения, некорректные ответы, настоящий пустой ответ, неизвестные идентификаторы, сохранение последнего времени наблюдения и учёт неполного опроса. Успешный пустой результат и сбой различаются.

Ограничения: это не полный installed panel→node→core E2E и не проверка всех протоколов и приложений. Список отражает активные авторизованные соединения во время опроса. Короткие соединения между опросами могут быть пропущены. Ядро исключает loopback 127.0.0.1 из OnlineMap; стенд использовал реальный адрес контейнера. Наблюдение включится после обновления ноды и применения конфигурации панелью. Экспорт подписок и серверная запись дополнительно покрыты тестами сервиса записи, а не этим сетевым сценарием.

## Проверка кнопки 19 октября

На установленной панели пользователя подтверждены четыре подключённые ноды. После полной загрузки страницы кнопка стала доступной; нажатие завершило обход всех четырёх нод. В этом опросе активные авторизованные IP не обнаружены. Причина прежнего состояния браузера не зафиксирована и не объявляется точно установленной. В интерфейсе добавлены периодическая и ручная загрузка списка, счётчик доступных нод и отдельные сообщения загрузки, ошибки, пустого списка и недоступности. Устаревшее обязательное требование NET_ADMIN убрано с экрана запуска. Проверены рендер состояний и реальный клик на локальном стенде; это отдельно от проверки установленной панели.

Изменения экрана запуска опубликованы в [1.2.66](https://github.com/lottman/Remnacust-installer/releases/tag/v1.2.66), панель 1.1.7.36. Исходные проверки и сборка прошли. Обновление на VPS этим прогоном не устанавливалось.

## Исправления 19 октября — выпуск 1.2.67

По запросу убрана отдельная кнопка обновления нод и периодический опрос каждые 5 секунд. Каждый запуск и повторный обход сначала загружает актуальный список; обход получает непосредственно этот ответ и не зависит от предыдущего рендера. Ошибка загрузки и пустой список допускают повтор через «Начать обход»; при ошибке старый список не используется. Уход со страницы во время загрузки не запускает фоновый обход.

На установленной панели подтверждено: три ноды завершили обход с нулём активных IP, а две другие не могли применить профиль. Их карточки показывают ошибку разбора JSON. Причина воспроизведена настоящими CLI-командами: предупреждение о freedom.domainStrategy попадает перед JSON в stdout. Core 1.1.8 направляет диагностику команд api в stderr, оставляя stdout для ответа. Регрессионный сценарий проверяет сохранение предупреждений, чтение JSON и продолжение старого VLESS-соединения после live-apply. Нода 1.1.13 содержит новое ядро. Это не подтверждение наличия пользовательских сессий: тестовый обход на установленной панели их не обнаружил.
