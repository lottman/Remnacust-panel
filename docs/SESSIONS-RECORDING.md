# Запись подключений

Откройте `/dashboard/tools/sessions-explorer` → **Запись**. Укажите длительность от 1 минуты до 7 дней и интервал опроса 10–300 секунд. Кнопка запуска создаёт серверную запись: закрытие вкладки не останавливает её. После перезапуска панели запись продолжится; недоступная панель не может собирать подключения.

Записываются наблюдаемые активные подключения: ID пользователя, UUID/название/страна ноды, IP, последнее время активности по данным ядра, первое и последнее наблюдение панелью, количество повторных наблюдений. Поиск в текущем снимке работает по имени пользователя, ID, IP, имени и UUID ноды. Удалённый пользователь остаётся в истории по ID.

**Скачать пользователей и подписки** выдаёт JSON с пользователями, актуальными ссылками подписок и наблюдениями. Ссылки вычисляются при выгрузке; они не копируются в диагностическую таблицу. Если пользователь удалён, ссылка равна `null`. Выгрузка разрешена только администратору панели, ответы запрещено кешировать. Содержимое трафика не записывается.

Одна запись активна одновременно, сохраняется до 20 записей. Данные удаляются через 3 дня после окончания; можно удалить вручную. Лимит одной записи — 20 000 различных сочетаний пользователь/нода/IP: при превышении запись завершается с предупреждением. Эти диагностические данные исключены из штатного резервного копирования. Для архива скачайте JSON.

Опросы идут с ограничением параллелизма и времени ожидания. Недоступные ноды и неудачные опросы подсчитываются отдельно; UUID последних неудачных нод есть в JSON. Остановка завершает уже идущий опрос. Опросы не гарантируют обнаружение коротких подключений между снимками и не являются журналом каждого пакета или посещённого сайта.

В окне активных сессий отдельного пользователя неудачный опрос всех выбранных нод показывает ошибку. Частичный обход сохраняет полученные подключения и выводит предупреждение с названиями нод, которые не удалось опросить. Успешный пустой ответ отличается от ошибки.

Контракты интеграций: [API](API.md).
