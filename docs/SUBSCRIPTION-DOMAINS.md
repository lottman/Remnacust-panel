# Домены подписок и CDN

Откройте **Подписка → Настройки → Страницы подписки → Домены подписок**. Вкладка страниц находится сразу после основных настроек. Блок доменов доступен независимо от состояния службы управления локальными страницами.

`SUB_PUBLIC_DOMAIN` в `/opt/remnacust/panel/.env` синхронизируется с основным доменом реестра в обе стороны. Поддерживаются `sub.example.com`, `sub.example.com/api/sub` и `https://sub.example.com/api/sub/`; в окружении сохраняется имя с необязательным путём, без протокола. Схема HTTP, credentials, IP-адреса, локальные имена, query/fragment и небезопасные пути не принимаются.

При изменении основного домена в интерфейсе локальная служба установщика обновляет `.env` и соответствующие значения `SUB_PUBLIC_DOMAIN` у приложений панели в зарегистрированном Compose. Остальные переменные, ключи, тома и сервисы сохраняются. Перезапуск панели не требуется: новые ссылки используют реестр. Изменение `.env` вручную проверяется API при запуске, открытии/обновлении списка и затем каждые 30 секунд. Старое окружение уже запущенного контейнера не перезаписывает новое значение на сервере. CDN-домены остаются только в реестре: одна переменная `.env` хранит лишь основной адрес.

Нужны панель 1.1.7.78 и локальная служба установщика 1.2.113 или новее. На ручной установке без службы либо со сторонним YAML Compose интерфейс показывает недоступность синхронизации, сохраняя доступ к списку и CDN. Изменение основного адреса не выдаётся за успешную запись `.env`. Обновление зарегистрированной панели установщиком приводит рабочий Compose к поддерживаемому JSON-представлению; имя файла остаётся `docker-compose.yml`.

Служба принимает только значение домена и ревизию файлов по приватному Unix-сокету с HMAC-аутентификацией. Пути и имена переменных нельзя передать из браузера. Символические/жёсткие ссылки, нештатные типы файлов и параллельные изменения отклоняются. Перед записью сохраняется приватная копия в `/opt/remnacust/backups/panel/subscription-domain-<id>/`. Повторная синхронизация без изменений не создаёт новую копию. Секреты и содержимое `.env` не возвращаются клиенту.

При недоступности службы, некорректном значении или конфликте с уже зарегистрированным CDN показывается отдельный статус. Ошибка чтения списка больше не отображается как ошибка сохранения и не сопровождается сообщением о пустом реестре.

Регистрация домена и синхронизация `.env` не создают DNS-запись и сертификат. Настройте их на сервере страницы или в CDN через соответствующее управление установщика.

## Основной домен

В карточке пользователя показаны обычная ссылка и до трёх CDN этого основного домена, с отдельными копированием и QR-кодом. Назначенный домен помечен как выбранный. Все адреса используют один ключ и одни ограничения подписки. Новый CDN сверх трёх отклоняется, в том числе при одновременном создании или переносе из другой группы; лишние старые записи автоматически не удаляются. Редактировать существующий CDN и получить обычную ссылку можно даже при превышении старого лимита.

Для бота предусмотрены отдельные права на все ссылки, только обычную или только CDN. Фильтры каталога и точные маршруты перечислены в [API.md](API.md#user-subscription-links). Чтение каталога доменов не разрешает получать ключи пользователей; существующие права токенов не меняются автоматически.

Основной домен используется для новых ссылок, пока у пользователя не выбран другой домен. У него есть стабильный UUID: его можно получить и использовать через API `subscription-domains:list` и `subscription-domains:get`. Токен с набором прав «Управление пользователями» получает только эти права чтения — этого достаточно, чтобы бот назначил UUID в `subscriptionDomainUuid` при создании или изменении пользователя.

Панель не выдаёт `REMNAWAVE_PANEL_URL` клиентам. Этот параметр — только серверное соединение страницы подписки с панелью. Укажите для `SUB_PUBLIC_DOMAIN` отдельный публичный hostname страницы подписки, а не внутренний адрес панели.

## CDN-домен

Новые ссылки используют обычный поддомен: `https://cdn.example.com/<ключ>`, без `/cdn/<UUID>`. Если настроен статичный публичный путь, он сохраняется перед ключом. Этот вид используется в карточке пользователя, `subscriptionUrl`, списке ссылок API и шаблонах. В карточке отдельная кнопка QR есть у каждой обычной/CDN-ссылки и у резервной текущей ссылки, когда каталог доменов недоступен.

На публичной странице ссылка для копирования, QR и импорта в приложение берётся из адреса, который клиент открыл в браузере. Вход через CDN не заменяется основным или служебным доменом. Персональная ссылка устройства сохраняет свой токен; обновление вида ссылки не превращает её в общую подписку.

### Один раз настроить CDN

С версии 1.1.7.82 (установщик 1.2.118) для каждого CDN панель выдаёт индивидуальное нейтральное имя заголовка, например `X-b696de253bef3af261369640`. В **Подписка → Настройки → Страницы подписки → Домены подписок → Настроить CDN** скопируйте готовые имя и значение заголовка. Обычные ссылки `https://cdn.example.com/<ключ>` продолжают работать без замены в приложении.

1. Источник CDN: основной **сайт подписки**, например `https://sub.example.com`. Это не административный адрес панели.
2. Host и SNI: домен этого основного сайта, например `sub.example.com`.
3. Включите добавление **заголовков запросов к источнику**:

   | Название | Значение |
   | --- | --- |
   | Индивидуальное имя из поля «Название заголовка запроса» | Готовое секретное значение из поля «Значение заголовка» |

Имя и ключ формируются независимо для каждого CDN с помощью HMAC и закрытого APP_SECRET установки. В текущей версии значение содержит UUID и отдельную подпись; скопируйте его целиком. APP_SECRET остаётся только на сервере. Смена APP_SECRET меняет и имена, и ключи: после неё обновите настройки всех CDN. Значение выдаётся только отдельным защищённым API с правом изменения доменов; обычное чтение списка возвращает лишь публичное имя заголовка. Старое UUID-значение и X-Remnacust-CDN работают как выбор адреса только в открытом режиме. Они не доказывают происхождение запроса и не обходят ограничение источника.

4. Сохраните пути, query string и `GET`/`HEAD`. Отключите принудительное кэширование персональных ответов подписки и сохраняйте Cache-Control источника.

**VK:** HTTP-заголовки → Добавление заголовков запросов → название и значение → Сохранить изменения. **Яндекс:** HTTP-заголовки и методы → Редактировать → Заголовки запроса к источнику → Добавить → Сохранить. Добавление заголовков ответа клиенту для этого не подходит.

После обновления подписки панель распознаёт CDN по этому заголовку, даже когда Host изменён на основной сайт. Геофайлы, контрольные суммы, HTML/QR и персональные ссылки устройств сохраняют CDN-домен. Несколько CDN получают разные UUID; API-ключи в CDN указывать не нужно.

Провайдерские инструкции: [VK: заголовки](https://github.com/vk-cs/docs-public/blob/master/docs/ru/networks/cdn/instructions/manage-cdn/http-headers/http-headers.md), [Яндекс: заголовки запросов и ответов](https://yandex.cloud/ru/docs/cdn/operations/resources/configure-headers).

### Ранее выданные ссылки

Ранее выдавались ссылки `https://cdn.example.com/cdn/<UUID>/<ключ>`. В открытом режиме они продолжают приниматься; при ограничении источника дополнительно нужен секретный заголовок CDN. Такие ссылки больше не формируются для новых пользователей, API и шаблонов. Для обычных ссылок при подмене Host настройте заголовок запроса к источнику, указанный выше. Раздел «Проверить ссылку с этим доменом» в настройках CDN преобразует ссылку или ключ локально в браузере и не добавляет ID в путь.

При постепенном обновлении компонентов старые страницы подписки продолжают получать прежний формат публичных метаданных резолвера. Новая страница запрашивает версию `2` и понимает также прежний ответ панели. Для полного перехода выдачи обновляйте панель и страницу вместе.

### Проверки

UUID — публичный селектор зарегистрированного CDN, не пароль и не подтверждение того, что запрос физически прошёл через CDN. Он не отменяет проверку ключа, статуса, заморозки, срока или HWID. Произвольный hostname, URL, несколько значений, несоответствие имени значению, неизвестный UUID, основной домен и конфликт ID в заголовке и пути отклоняются. Селектор потребляется на странице подписки и не пересылается как авторизация. Страница подтверждает контекст панели собственным действующим токеном; отзыв токена приводит к отказу, а не подстановке основного домена.

Публичный `GET /api/sub/domains/:uuid/resolve` возвращает только UUID, публичный адрес CDN и его нейтральное имя заголовка. Он не раскрывает список доменов, родительский источник, данные пользователей или адрес панели. Управление реестром защищено авторизацией и scopes.

`SUB_PUBLIC_DOMAIN` остаётся основным адресом без служебного пути CDN. `REMNAWAVE_PANEL_URL` используется только для закрытого серверного соединения страницы с панелью. Поле API `publicBaseUrl` содержит готовый публичный префикс; добавьте ключ пользователя. Новых переменных окружения и миграций БД нет.

## Привязка к пользователю

В карточке пользователя есть поле **Домен подписки**. Пустое значение использует основной домен. Выбор основного или CDN-домена меняет ссылку пользователя и API-ответ с его подпиской, не меняя хосты VPN и не требуя перевыпуска ключей.

Домен нельзя удалить, пока он основной, назначен пользователям или является родителем CDN-доменов. Это защищает действующие ссылки от случайной поломки.

## API

| Операция | Путь | Scope |
| --- | --- | --- |
| Список | `GET /api/subscription-domains` | `subscription-domains:list` |
| Один домен | `GET /api/subscription-domains/:uuid` | `subscription-domains:get` |
| Создать | `POST /api/subscription-domains` | `subscription-domains:create` |
| Изменить | `PATCH /api/subscription-domains/:uuid` | `subscription-domains:update` |
| Удалить | `DELETE /api/subscription-domains/:uuid` | `subscription-domains:delete` |

В запросах создания и изменения передавайте `name`, `domain`, `path`, `kind`, `parentUuid` и `isDefault`. `path` — необязательный статичный путь подписки, например `/api/sub`; CDN без пути наследует путь основного домена. Для `domain` принимаются только публичные hostname без схемы, порта и пути. Для `CDN` обязателен UUID основного домена; для `PRIMARY` `parentUuid` должен быть `null`.


## Доступ через CDN / CDN origin access

В карточке основного домена выберите «Открытый доступ», «Только через CDN» или «Перенаправлять на CDN». Последний режим переводит прямые GET/HEAD-запросы на выбранный CDN этого же домена, сохраняя ключ подписки, /json, путь устройства, геофайла и параметры запроса. Проверка охватывает страницу, профили и DAT с контрольными суммами. Адрес источника и SUB_PUBLIC_DOMAIN остаются основными: не заменяйте их CDN-доменом. У одного основного домена не более трёх CDN.

Сначала обновите панель и нашу страницу подписки. В «Настроить CDN» скопируйте индивидуальные имя и значение заголовка в заголовки ЗАПРОСОВ VK/Яндекса. CDN должен перезаписывать этот заголовок, а не добавлять второе значение. Ключ нельзя помещать в ответы, публичные ссылки или настройки приложения. Получение ключа через POST /api/subscription-domains/{uuid}/credentials требует прав изменения доменов либо отдельного права credentials; чтение списка ключ не раскрывает. Публичный UUID и старый /cdn/ID выбирают адрес, но не открывают закрытый источник. Каждый CDN имеет отдельные имя и ключ, привязанные к этой установке.

Проверьте через CDN HTML, обычную ссылку, /json и скачивание геофайлов до включения ограничения. Для CDN без правильного ключа возвращается 403, а не повторное перенаправление. Прямой запрос к закрытому источнику получает 403; режим перенаправления отвечает 307 без кэширования. Если приложение не следует перенаправлениям, выдайте ему CDN-ссылку сразу. Изменения могут распространяться между процессами до пяти секунд. При обновлении существующие домены остаются открытыми. Старые страницы работают в открытом режиме; для закрытого режима нужна обновлённая наша страница либо прямой CDN-доступ к API панели с тем же заголовком. Это защита выдачи, а не сетевое скрытие IP или изменение VPN-транспорта.

Edit the primary domain and choose Open access, CDN only, or Redirect to CDN. Redirect sends direct GET/HEAD requests to a selected CDN belonging to the same primary, preserving the subscription key, /json, device paths, geofile paths and query parameters. The policy covers HTML, profiles, DAT and checksums. Keep the origin address and SUB_PUBLIC_DOMAIN on the primary domain; never replace them with the CDN hostname. Each primary supports at most three CDNs.

Update both the panel and our subscription page first. In Configure CDN, copy its individual header name and value into REQUEST headers in VK/Yandex. The CDN must overwrite that header, not append another value. Never put the key in response headers, public links or client settings. POST /api/subscription-domains/{uuid}/credentials requires domain write access or the specific credentials permission; list/read access does not disclose the key. A public UUID or legacy /cdn/ID selects a domain but cannot unlock a restricted origin. Every CDN has a separate name and key tied to this installation.

Test CDN HTML, the base link, /json and geofile downloads before restricting access. A CDN request without the correct key returns 403 instead of looping. Direct access returns 403 in CDN-only mode or an uncacheable 307 in redirect mode. Give clients the CDN link directly if they do not follow redirects. Changes may take up to five seconds across processes. Existing domains remain open after upgrade. Old pages work in open mode; restricted mode needs our updated page or direct CDN access to the panel subscription API with the same request header. This protects delivery; it does not hide network IPs or change VPN transports.


## JSON и Throne / JSON and Throne

При включённом «Отдавать JSON на базовом пути подписки» распознанные Throne 1.x от стабильной 1.2.0 получают полный Xray JSON на обычной ссылке; при передаче beta-номера поддерживается 1.2.0-beta.5 и новее. Это одинаково для основного и CDN-домена. Старые и нераспознанные версии не переключаются автоматически. Явные `/json` и `/v2ray-json` имеют приоритет над распознаванием браузера на странице подписки; блокировки доступа и запрет выбора формата по пути в правилах ответов сохраняются. Явно выбранные Mihomo/Clash/sing-box и исключение из базового JSON не заменяются Xray-форматом. Throne не получает специальные расширения Happ/INCY или отдельную доставку DAT автоматически.

With JSON enabled at the base subscription URL, recognized Throne 1.x clients from stable 1.2.0 receive full Xray JSON without a suffix; explicitly reported beta builds are supported from 1.2.0-beta.5. Primary and CDN domains behave identically. Older or unrecognized versions retain their existing format. Explicit `/json` and `/v2ray-json` override browser detection on the subscription page, while access controls and the response-rule setting that disables format paths remain effective. Explicit Mihomo/Clash/sing-box formats and base-JSON opt-outs are preserved. Throne is not automatically granted Happ/INCY extensions or separate DAT delivery.
