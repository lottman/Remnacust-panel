# Домены подписок и CDN

Откройте **Подписка → Настройки → Страницы подписки → Домены подписок**. Вкладка страниц находится сразу после основных настроек. Блок доменов доступен независимо от состояния службы управления локальными страницами.

`SUB_PUBLIC_DOMAIN` в `/opt/remnacust/panel/.env` синхронизируется с основным доменом реестра в обе стороны. Поддерживаются `sub.example.com`, `sub.example.com/api/sub` и `https://sub.example.com/api/sub/`; в окружении сохраняется имя с необязательным путём, без протокола. Схема HTTP, credentials, IP-адреса, локальные имена, query/fragment и небезопасные пути не принимаются.

При изменении основного домена в интерфейсе локальная служба установщика обновляет `.env` и соответствующие значения `SUB_PUBLIC_DOMAIN` у приложений панели в зарегистрированном Compose. Остальные переменные, ключи, тома и сервисы сохраняются. Перезапуск панели не требуется: новые ссылки используют реестр. Изменение `.env` вручную проверяется API при запуске, открытии/обновлении списка и затем каждые 30 секунд. Старое окружение уже запущенного контейнера не перезаписывает новое значение на сервере. CDN-домены остаются только в реестре: одна переменная `.env` хранит лишь основной адрес.

Нужны панель 1.1.7.78 и локальная служба установщика 1.2.113 или новее. На ручной установке без службы либо со сторонним YAML Compose интерфейс показывает недоступность синхронизации, сохраняя доступ к списку и CDN. Изменение основного адреса не выдаётся за успешную запись `.env`. Обновление зарегистрированной панели установщиком приводит рабочий Compose к поддерживаемому JSON-представлению; имя файла остаётся `docker-compose.yml`.

Служба принимает только значение домена и ревизию файлов по приватному Unix-сокету с HMAC-аутентификацией. Пути и имена переменных нельзя передать из браузера. Символические/жёсткие ссылки, нештатные типы файлов и параллельные изменения отклоняются. Перед записью сохраняется приватная копия в `/opt/remnacust/backups/panel/subscription-domain-<id>/`. Повторная синхронизация без изменений не создаёт новую копию. Секреты и содержимое `.env` не возвращаются клиенту.

При недоступности службы, некорректном значении или конфликте с уже зарегистрированным CDN показывается отдельный статус. Ошибка чтения списка больше не отображается как ошибка сохранения и не сопровождается сообщением о пустом реестре.

Регистрация домена и синхронизация `.env` не создают DNS-запись и сертификат. Настройте их на сервере страницы или в CDN через соответствующее управление установщика.

## Основной домен

Основной домен используется для новых ссылок, пока у пользователя не выбран другой домен. У него есть стабильный UUID: его можно получить и использовать через API `subscription-domains:list` и `subscription-domains:get`. Токен с набором прав «Управление пользователями» получает только эти права чтения — этого достаточно, чтобы бот назначил UUID в `subscriptionDomainUuid` при создании или изменении пользователя.

Панель не выдаёт `REMNAWAVE_PANEL_URL` клиентам. Этот параметр — только серверное соединение страницы подписки с панелью. Укажите для `SUB_PUBLIC_DOMAIN` отдельный публичный hostname страницы подписки, а не внутренний адрес панели.

## CDN-домен

### Один раз настроить CDN

С версии 1.1.7.81 (установщик 1.2.117) для каждого CDN панель выдаёт индивидуальное нейтральное имя заголовка, например `X-b696de253bef3af261369640`. В **Подписка → Настройки → Страницы подписки → Домены подписок → Настроить CDN** скопируйте готовые имя и значение заголовка. Обычные ссылки `https://cdn.example.com/<ключ>` продолжают работать без замены в приложении.

1. Источник CDN: основной **сайт подписки**, например `https://sub.example.com`. Это не административный адрес панели.
2. Host и SNI: домен этого основного сайта, например `sub.example.com`.
3. Включите добавление **заголовков запросов к источнику**:

   | Название | Значение |
   | --- | --- |
   | Индивидуальное имя из поля «Название заголовка запроса» | UUID соответствующего CDN-домена из поля «Значение заголовка» |

Имя воспроизводимо из случайного постоянного UUID домена и не меняется при обновлении панели, изменении домена или перезапуске. Хранить дополнительные секреты или переменные .env не требуется. В API оно доступно в `requestHeaderName` (для основного домена — `null`). При переходе с общего `X-Remnacust-CDN` замените в CDN только имя, сохранив значение. Старое имя поддерживается для совместимости. Нейтральное имя не скрывает остальные признаки трафика и не подтверждает происхождение запроса.

4. Сохраните пути, query string и `GET`/`HEAD`. Отключите принудительное кэширование персональных ответов подписки и сохраняйте Cache-Control источника.

**VK:** HTTP-заголовки → Добавление заголовков запросов → название и значение → Сохранить изменения. **Яндекс:** HTTP-заголовки и методы → Редактировать → Заголовки запроса к источнику → Добавить → Сохранить. Добавление заголовков ответа клиенту для этого не подходит.

После обновления подписки панель распознаёт CDN по этому заголовку, даже когда Host изменён на основной сайт. Геофайлы, контрольные суммы, HTML/QR и персональные ссылки устройств сохраняют CDN-домен. Несколько CDN получают разные UUID; API-ключи в CDN указывать не нужно.

Провайдерские инструкции: [VK: заголовки](https://github.com/vk-cs/docs-public/blob/master/docs/ru/networks/cdn/instructions/manage-cdn/http-headers/http-headers.md), [Яндекс: заголовки запросов и ответов](https://yandex.cloud/ru/docs/cdn/operations/resources/configure-headers).

### Запасной способ без заголовка

С версии 1.1.7.79 доступны ссылки `https://cdn.example.com/cdn/<UUID>/<ключ>`. При статичном пути он стоит перед `/cdn/<UUID>`. Они продолжают работать; панель формирует их автоматически в карточке пользователя, API и шаблонах. В окне настройки вариант находится в свёрнутом разделе **Если CDN не позволяет добавить заголовок**. Только для этого способа старую ссылку без ID нужно один раз заменить; настроенный заголовок снимает это требование.

### Проверки

UUID — публичный селектор зарегистрированного CDN, не пароль и не подтверждение того, что запрос физически прошёл через CDN. Он не отменяет проверку ключа, статуса, заморозки, срока или HWID. Произвольный hostname, URL, несколько значений, несоответствие имени значению, неизвестный UUID, основной домен и конфликт ID в заголовке и пути отклоняются. Селектор потребляется на странице подписки и не пересылается как авторизация. Страница подтверждает контекст панели собственным действующим токеном; отзыв токена приводит к отказу, а не подстановке основного домена.

Публичный `GET /api/sub/domains/:uuid/resolve` возвращает только UUID и публичный адрес CDN. Он не раскрывает список доменов, родительский источник, данные пользователей или адрес панели. Управление реестром защищено авторизацией и scopes.

`SUB_PUBLIC_DOMAIN` остаётся основным адресом без служебного пути CDN. `REMNAWAVE_PANEL_URL` используется только для закрытого серверного соединения страницы с панелью. Поле API `publicBaseUrl` содержит готовый публичный префикс; добавьте ключ пользователя. Новых переменных окружения и миграций БД нет.

## Привязка к пользователю

В карточке пользователя есть поле **Домен подписки**. Пустое значение использует основной домен. Выбор основного или CDN-домена меняет ссылку пользователя и API-ответ с его подпиской, не меняя хосты VPN и не требуя перевыпуска ключей.

Домен нельзя удалить, пока он основной, назначен пользователям или является родителем CDN-доменов. Это защищает действующие ссылки от случайной поломки.

## API

| Операция | Путь | Scope |
| --- | --- | --- |
| Список | `GET /api/subscription-domains` | `subscription-domains:list` |
| Один домен | `GET /api/subscription-domains/:uuid` | `subscription-domains:get` |
| Создать | `POST /api/subscription-domains` | `subscription-domains:create` |
| Изменить | `PATCH /api/subscription-domains/:uuid` | `subscription-domains:update` |
| Удалить | `DELETE /api/subscription-domains/:uuid` | `subscription-domains:delete` |

В запросах создания и изменения передавайте `name`, `domain`, `path`, `kind`, `parentUuid` и `isDefault`. `path` — необязательный статичный путь подписки, например `/api/sub`; CDN без пути наследует путь основного домена. Для `domain` принимаются только публичные hostname без схемы, порта и пути. Для `CDN` обязателен UUID основного домена; для `PRIMARY` `parentUuid` должен быть `null`.
