# Перенос пользователей Remnacust

В интерфейсе используйте экспорт и импорт на странице пользователей. Для переноса сначала создайте на целевой панели профили, ноды, хосты и внутренние сквады. Экспорт пользователей не является копией всей базы.

## Доступ

`GET /api/users/export` и `POST /api/users/import` требуют действующего JWT администратора. Обычные API-токены не допускаются, включая токен со всеми правами. Эти служебные операции панели намеренно исключены из каталога методов для API-токенов.

## Экспорт

`GET /api/users/export` возвращает:

```json
{
  "response": {
    "users": [],
    "exportedAt": "2026-10-04T00:00:00.000Z"
  }
}
```

Необязательный query-параметр `squadUuid` ограничивает экспорт членами выбранного внутреннего сквада. Без него экспортируются все пользователи.

Каждая запись включает имя, короткий идентификатор, ключи VLESS/Trojan/Shadowsocks, статус, сроки, квоту и период трафика, лимит HWID, тег, описание, email, Telegram ID и имена внутренних сквадов. Зашифрованные в базе ключи расшифровываются перед экспортом, чтобы они работали на целевой панели с другим `APP_SECRET`. Поэтому файл содержит действующие секреты доступа. Не загружайте его в GitHub или публичные ссылки.

Для файла импорта сохраните объект `response` или создайте `{ "users": response.users }`: список `users` должен быть на верхнем уровне. Скопированный полный HTTP-ответ с внешней обёрткой `response` не является файлом импорта.

## Импорт

`POST /api/users/import` принимает от 1 до 20 000 записей в `users`. Минимальный пример:

```json
{
  "users": [
    {
      "username": "alice",
      "expireAt": "2030-01-01T00:00:00Z",
      "activeInternalSquads": ["Premium"]
    }
  ],
  "defaultInternalSquadUuid": "22222222-2222-4222-8222-222222222222"
}
```

Имя пользователя — 3–36 латинских букв, цифр, `_` или `-`. Даты передаются строками ISO 8601. Имена в `activeInternalSquads` сопоставляются с внутренними сквадами целевой панели; отсутствующие имена пропускаются. Это поле импорта содержит имена, хотя одноимённое поле обычного создания пользователя содержит UUID.

`defaultInternalSquadUuid` — UUID дополнительного существующего сквада, который добавляется всем создаваемым пользователям, даже если в файле уже были сквады. Можно передать `null` или не указывать поле. Для отказа от восстановления назначений передайте `activeInternalSquads: []`; форма импорта делает это при снятой галочке восстановления.

Передавайте исходные ключи из экспорта, чтобы сохранить данные подключения. Если ключи не переданы, при создании формируются новые. Nullable-поля экспорта допускаются схемой импорта. Неверный формат, например повреждённый UUID VLESS или отрицательная квота, отклоняется проверкой запроса. Запись с `expireAt: null` учитывается как ошибка отдельного пользователя.

Ответ:

```json
{
  "response": {
    "created": 1,
    "skipped": 0,
    "failed": 0,
    "errors": []
  }
}
```

Совпадение имени пользователя или короткого идентификатора с существующей записью приводит к пропуску. Ошибки создания отражаются в `failed` и `errors`. Импорт не обновляет существующие записи. Повторный запуск не считается подтверждением полного переноса: проверьте итоговые числа, назначения и подписку созданного пользователя до удаления исходной панели.

## Границы переноса

Этот экспорт не переносит ноды, профили, хосты, API-токены, зарегистрированные устройства, историю расхода и все настройки панели. Для восстановления всей базы используйте её резервную копию с сохранением серверных секретов. Для перехода между разными версиями сначала проверьте перенос небольшого набора пользователей в тестовой установке.
