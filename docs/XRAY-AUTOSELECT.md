# Автовыбор и история шаблонов Remnacust

Панель 1.1.7.32. Шаблоны Xray JSON можно редактировать кодом или во вкладке «Автовыбор». Эти вкладки используют один черновик. GUI меняет существующие блоки JSON, сохраняет остальные аутбаунды, правила, пользовательские параметры и порядок ограничительных правил. Новый балансер добавляет правило перед прежним общим правилом; прежнее правило остаётся. Просмотр отличий расположен справа, на телефоне — под формой. Изменения вступают в силу после сохранения и нового получения подписки.

## Выбор источников

```json
{
  "outbounds": [{ "tag": "direct", "protocol": "freedom" }, { "tag": "block", "protocol": "blackhole" }],
  "remnawave": {
    "injectHosts": [{
      "selector": { "type": "tags", "values": ["LTE"], "expected": 3 },
      "mode": "random", "selectFrom": "ALL", "tagPrefix": "lte"
    }],
    "assignTo": { "tags": ["AUTO_LTE"] }
  },
  "routing": {
    "balancers": [{ "tag": "balance-lte", "selector": ["lte"], "fallbackTag": "lte", "strategy": { "type": "leastPing" } }],
    "rules": [{ "type": "field", "network": "tcp,udp", "balancerTag": "balance-lte" }]
  },
  "observatory": { "subjectSelector": ["lte"], "probeUrl": "https://www.gstatic.com/generate_204", "probeInterval": "30s", "enableConcurrency": true }
}
```

`selector.type` может быть `uuids` или `tags`. Теги совпадают точно и разворачиваются в доступные хосты; повторяющиеся UUID исключаются. Старые `remarkRegex`, `tagRegex`, `sameTagAsRecipient` работают в режиме `all`.

| Режим | Поля селектора | Поведение |
|---|---|---|
| `all` или отсутствует | `values` | Все доступные хосты из выбранного пула |
| `random` | `values`, `expected` | До `expected` уникальных доступных хостов без повторов |
| `group` | `groups` | Одна случайная непустая группа после проверки доступа |

`expected` — целое число от 1 до 1000. Если доступных хостов меньше, возвращаются все доступные. Выбор выполняется при формировании подписки. Клиент сохраняет выданный набор до обновления подписки. Это не выбор нового пула при каждой VPN-сессии.

`groups` поддерживает именованный объект или массив массивов. Пример для тегов: `"groups": {"primary": ["VK", "YC"], "backup": ["DDOS"]}`. При `type: "uuids"` элементы должны быть действительными UUID хостов. Недоступные группы исключаются, затем группа выбирается равновероятно; в ней могут остаться только доступные хосты.

`selectFrom`: `HIDDEN` по умолчанию, `NOT_HIDDEN` или `ALL`. Доступ пользователя, видимость, отключение, ограничения и исключения проверяются до случайного выбора. Назначения шаблонов не расширяют доступ. Если явно указанный режим не имеет доступных источников, соответствующий профиль пропускается, чтобы не выдавать фиктивный адрес или неработающий балансер. Для старых записей без `mode` сохранено прежнее поведение.

## Клиентские балансеры

Стратегии: `random`, `roundRobin`, `leastPing`, `leastLoad`. Выбор пула ограничивает число выданных аутбаундов, а стратегия балансера выбирает среди них уже на клиенте. `leastPing` и `leastLoad` требуют `observatory` либо `burstObservatory`. GUI добавляет необходимые префиксы к существующему наблюдению, сохраняя URL, интервалы и остальные параметры. `fallbackTag` указывает резервный аутбаунд, а не балансер. Селекторы Xray сопоставляются по префиксу. Для каждой группы используйте отдельный непересекающийся префикс; первый сгенерированный аутбаунд получает имя префикса, остальные — суффиксы `-2`, `-3`.

При редактировании префикса GUI обновляет точные связанные селекторы, резервный аутбаунд и наблюдение. При переименовании балансера обновляются ссылки в правилах. Явное удаление балансера убирает только его и ссылающиеся на него правила. Удаление пула блокируется, пока его использует балансер. Старое именование по названию или тегу хоста сохраняется; для добавления балансера по префиксу его нужно явно переключить.

Официальная семантика Xray: [routing](https://xtls.github.io/en/config/routing.html), [observatory](https://xtls.github.io/en/config/observatory.html).

## Назначение получателям

`remnawave.assignTo.hosts` — UUID получателей, `assignTo.tags` — теги получателей. Это отдельные списки от источников в `injectHosts`. Теги назначения распространяются на будущие хосты с этими тегами.

Приоритет: явный шаблон в карточке хоста; назначение UUID в шаблоне; назначение по тегу; стандартный шаблон. При конфликте нескольких назначений используется порядок шаблонов (`viewPosition`, затем UUID). Изменение или восстановление назначения действует при следующем формировании подписки. Служебный блок `remnawave` удаляется из клиентского JSON.

## История всех типов

Вкладка «История» работает для Xray JSON, Singbox, Mihomo, Clash и Stash. Сохраняются последние 30 версий с датой. Новая миграция создаёт первую версию из существующего кода; ранее не записанную историю восстановить невозможно.

Можно сравнить сохранённую версию с текущим черновиком и открыть её в редакторе. Восстанавливается весь код, включая автовыбор, балансеры, наблюдение и назначения. Несохранённый черновик заменяется после предупреждения. Для применения нужно сохранить: это создаёт новую версию, позволяя отменить сам откат. Параллельные сохранения сериализуются блокировкой строки, запись кода и истории атомарна. Повторное сохранение одинакового содержания не занимает слот истории. При удалении шаблона его история удаляется каскадно.

Защищённый API: `GET /api/subscription-templates/{uuid}/revisions`, право `subscription-template:get-revisions`. Чтение истории не предоставляет право изменения. Восстановление сохраняется через прежний `PATCH /api/subscription-templates` с правом записи. История содержит полный код: предоставляйте доступ только тем администраторам или API-токенам, которым разрешено его читать.

Холст убран из sidebar. Вкладка холста внутри профиля и прямой маршрут сохранены.


## Обновление панели и нод и очистка образов

Обновление из интерфейса и из консоли использует один установщик. Обновление ноды из панели загружает опубликованный стабильный выпуск установщика, закрепляет тег и проверяет SHA-256 скрипта по SHA256SUMS и digest метаданных перед запуском. Дальше установщик проверяет образ, меняет основной Compose, сохраняет переменные, тома, подключения и фактический порт, ждёт готовности и выполняет восстановление при ошибке. Простой pull старого тега больше не используется.

После успешного обновления панели, сайта подписки или ноды очищаются старые неиспользуемые образы соответствующих компонентов Remnacust. Сохраняются текущая версия, предыдущая версия для отката и все образы, используемые контейнерами, включая остановленные и другие проекты. Чужие репозитории, БД, reverse proxy, тома и данные не удаляются. Учтены алиасы тегов и digest. Очистка не использует force или глобальный prune и ограничена двумя минутами; если её нельзя закончить безопасно, она откладывается, а успешное обновление не превращается в ошибку. На неудачном обновлении очистка не запускается.

В интерфейсе панели обновление самой панели выполняет установленный хостовый агент (нужен systemd и штатная установка); обновление ноды требует настроенного SSH-доступа с root или sudo без запроса пароля. Другие ядра, установленные отдельно через менеджер Xray, сохраняются как данные в томах; обновление встроенного ядра следует закреплённому комплекту выпуска.
