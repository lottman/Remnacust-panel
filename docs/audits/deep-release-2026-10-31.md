# Предрелизный аудит Remnacust — 31 октября 2026

## Первый этап: проверка до исправлений

Проверены незакоммиченные изменения поверх панели 75789a05, установщика c80b8b55, нода 8efd633c и неизменённые исходники ядра 1.1.11. Независимый проверяющий работал без истории чата, без правок и публикации. Проверка не распространяется на каждую строку всех зависимостей и не заменяет испытание физических iOS-устройств.

### F01 / P1 — недостаточная привязка существующей страницы к панели

`installer/subscription_migration.py:candidates`, строки 39–55; вызывается из `subscription_pages.py:discovered`.
Две панели используют service alias `api` в разных сетях. Сравнение hostname принимает страницу второй панели, поскольку общая сеть проверялась только для имён remnawave/remnacust. Совпадение публичного hostname также принимало другой порт. Доказательство независимого воспроизведения: чужая страница попала в discovered, stop сформировал команду для её сервиса. Требуется проверка сетевого alias конкретного контейнера и полного публичного origin. Выпуск блокируется до исправления.

### F02 / P2 — restart может затронуть зависимые сервисы

`installer/subscription_pages.py:service`, строка 243. Compose restart без `--no-deps` включает зависимые сервисы с `depends_on.restart: true`. Возможен перезапуск общего proxy. Требуется ограничить restart выбранным сервисом. [Механизм Docker Compose](https://github.com/docker/compose/blob/v2.39.4/pkg/compose/restart.go#L46-L65).

### F03 / P2 — принятый job остаётся queued после ошибки обнаружения

`installer/update-agent.py:Agent.page_work`, строки 271–280. Повторный selected и проверка managed происходят до обработчика терминального состояния. При кратковременном отказе Docker или изменении регистрации worker выходит, оставляя queued и блокировку повторного действия до двух часов. Требуется проверять текущий request под lock и записывать failed при ошибке выбора/проверки действия.

### F04 / P3 — новый набор discovery-тестов не включён в общий запуск

`tests/installer.test.sh` запускает тесты явным списком; `test_legacy_subscription_pages.py` в нём отсутствует. Локальный ручной запуск проходил, но общий CI его не выполнял. Добавить в общий тестовый entrypoint.

## Карта системы и границы

Панель: Nest/Express API, PostgreSQL/Prisma/Kysely, очереди и отдельные scheduler/processor роли; React/Mantine UI. Публичный генератор разрешает пользователя/устройство/доступные хосты, затем применяет шаблон, клиентские пулы и геофайлы. Отдельная страница подписки проксирует разрешённые маршруты к заданной панели. Нода принимает аутентифицированные команды и применяет конфигурацию через закрытый API ядра. Установщик и root-agent управляют локальным Docker; браузер передаёт только ограниченные идентификаторы и действия.

## Область и ограничения

Официальные источники: [INCY Routing](https://docs.incy.cc/routing/), [INCY full JSON](https://docs.incy.cc/full-xray-config/), [INCY Autorouting](https://docs.incy.cc/autorouting/), [Happ Routing](https://www.happ.su/main/dev-docs/routing). Размер 900000 байт — запас панели для форматированного профиля INCY, а не опубликованный гарантированный предел всех версий клиента. Нативная проверка конфигурации не равна подключению на iOS. VPN/TUN и системный proxy не запускались; пользовательские серверы не изменялись.

Итоговые результаты проверок и статусы исправления добавляются после регрессии. Старые номера строк выше относятся к состоянию до ремонта; имена функций позволяют найти изменённые участки.

## Исправления после первого этапа

F01: публичный адрес сравнивается как scheme/hostname/port, внутренний alias требует общей сети и отсутствия другого владельца имени во всех сетях страницы. Повторная независимая проверка выявила дополнительный случай страницы в двух сетях; он также закрыт отдельной регрессией. F02: используется `restart --no-deps`. F03: повторный выбор и проверка действия находятся в обработчике под lock после проверки актуальности request; ошибка записывает failed, новый запрос не блокируется. F04: discovery-набор включён в общий entrypoint CI.

Финальная независимая перепроверка F01–F03: PASS; проверены также порядок сетей/inventory и различие между недоступной чужой сетью и второй сетью самой страницы. Блокирующих находок в конкретном ремонте не осталось. Проверки типов, линтеры и production-сборки панели и backend страницы подписки прошли; frontend сохраняет 26 неблокирующих предупреждений инструментов.

## Результаты и ограничения безопасности

Backend: 730 тестов, 724 пройдены, шесть платформенных проверок пропущены на Windows. Первый параллельный запуск превысил жёсткий трёхсекундный лимит отдельного процесса regex-теста под нагрузкой. Изолированный запуск и повтор полного набора с четырьмя параллельными файлами прошли без изменения производственного кода и без ослабления таймаута. Frontend: 264 теста, включая scripts. Нода: 184/184 в Linux; её Windows-запуск выявил ограничения создания symlink и не считается успешной проверкой Linux-компонента.

Production npm audit четырёх пакетов: нет moderate/high/critical. Две low-записи backend относятся к известной цепочке deepmerge/nestjs-zod, совместимого исправления аудит не предлагает. Утечка custom headers прямого follow-redirects закрыта версией 1.16.2 и loopback-регрессией; эксплуатация через Axios приложения не заявляется.

Полный повтор Go-тестов выбранных пакетов не состоялся из-за сброса соединения с proxy.golang.org при загрузке модулей. Исходники xray не изменились относительно закреплённого Core 1.1.11; бинарные/native проверки не заменяют этот непройденный запуск. Старые отчёты использовались только как навигация, не как новое доказательство. Непроверенные области выше не считаются успешными.

Выпуск Stable/Latest разрешается только после успешных CI именно публикуемых коммитов, сборки всех шести образов amd64/arm64, проверки десяти файлов комплекта и SHA-256, соответствия исходным pin и анонимной доступности. Результаты публикации записываются в release notes. Обновление пользовательских работающих серверов в этот выпуск не входит.
