# 1.1.7.108

- Система геофайлов теперь включается явно в дополнительных настройках подписки и по умолчанию выключена. Включение требует JSON на базовом адресе; несовместимые изменения отклоняются также при одновременных запросах.
- При выключенной системе скрывается вкладка геофайлов, прекращается автоматическое обновление файлов, а сохранённые назначения остаются доступны после повторного включения. Дублирующий переключатель JSON из вкладки геофайлов удалён.
- Ручные правила шаблонов сохраняются. Ссылки `geosite:` по-прежнему требуют соответствующих категорий в DAT клиента; для независимости от клиентского DAT используйте обычные списки адресов.
- Очистка ранее выданного управляемого профиля ограничена подтверждённой историей этого провайдера. Обычные профили приложений не заменяются пустым профилем без такой истории.
- Настройки берутся с актуальным поколением кэша и копируются для каждого запроса. Настройки внешнего сквада не могут включить глобальную систему геофайлов.
- Обновлены документация, четыре локализации, API-контракт и миграция БД. 199 миграций проверены на PostgreSQL 14.24, 15.19, 16.15, 17.11 и 18.6 с ограниченным владельцем схемы.

## English

- Geofile processing is an explicit opt-in in additional subscription settings, off by default. It requires JSON at the base URL, including during concurrent updates.
- Disabling it hides the editor tab and stops automatic file refresh while retaining assignments. Manual template rules remain unchanged; `geosite:` references still require matching client DAT categories.
- Retirement only clears a previously confirmed provider-owned profile. Request-local settings copies and committed cache generations prevent settings leaking between requests.
- Documentation, four locales, API contracts and the database migration were updated. All 199 migrations were checked on PostgreSQL 14.24/15.19/16.15/17.11/18.6 with a restricted schema owner.
