# Remnacust 1.1.7.117

## Русский

- Исправлена ошибка A039 после успешной заморозки пользователя. Включение, отключение и восстановление доступа после продления или сброса трафика также не зависят от немедленного ответа всех нод.
- Изменение статуса или срока атомарно сохраняется с заданием применения. При недоступности ноды панель повторяет сверку после восстановления связи и своего перезапуска. Это работает и без зарегистрированных устройств. Старое задание не удаляет более новое изменение; повторы ограничены по параллельности.
- Для новой заморозки обязательно будущее время автоматической активации. Оно задаётся до сохранения, затем доступно только для просмотра. Повторная заморозка не добавляет срок; массовое изменение сохраняет уже назначенные сроки. Старым замороженным пользователям без даты можно назначить её один раз.
- Проверка разморозки выполняется каждые пять секунд. После простоя панели срок продолжается от назначенной даты, а не от момента восстановления. Исчерпанный срок и квота сохраняют ограничения; ранняя ручная активация доступна.
- API принимает `frozenUntil` с часовым поясом при создании новой заморозки. Ошибки A263/A264 объясняют неверный или уже сохранённый срок. Права API-токенов не расширяются.
- Исправлены устаревшие задания добавления и удаления пользователей на нодах. Проверяются актуальные права, ключи и назначенные inbound; ошибки доставки повторяются, а операции одной ноды выполняются последовательно. Массовая проверка выполняется пакетами.
- Описания известных ошибок API проверены для русского, английского, персидского и китайского. Код в скобках сохраняется для диагностики; приватные ответы сервера не показываются вместо описания.
- Обновлена справка администратора на четырёх языках; исправлена ошибка генератора справки.

Сохранение статуса не подтверждает немедленное прекращение соединений на физически недоступной ноде. Изменения требуют миграции `20261112010000_user_access_reconciliation` и `20261112020000_scheduled_user_freeze`; пользователи, ключи, профили и настройки не удаляются. Панель не обновляет удалённые ноды автоматически.

## English

- Fixed A039 after a successfully saved user freeze. Enabling, disabling and restoring access after an extension or traffic reset also no longer depend on every node replying immediately.
- Status and expiry changes persist atomically with application work. Reconciliation retries after connectivity returns and survives panel restarts, including users without registered devices. Stale jobs cannot remove newer work; concurrency is bounded.
- A future automatic activation deadline is required for each new freeze. Set it before saving; afterwards it is read-only. Repeated freezes add no time, and bulk updates preserve existing deadlines. Existing frozen users without a deadline can receive one once.
- Automatic activation is checked every five seconds. After downtime, expiry continues from the scheduled deadline rather than recovery time. Expiry and exhausted quota still restrict access; early manual activation remains available.
- The API accepts timezone-qualified `frozenUntil` when entering the frozen state. A263/A264 explain invalid or already saved deadlines. API-token permissions are not broadened.
- Fixed stale queued user additions and removals on nodes. Current access, credentials and inbound assignments are checked; delivery failures retry and operations on one node are serialized. Bulk authorization checks are batched.
- Known API error descriptions were checked in Russian, English, Persian and Chinese. Diagnostic codes remain available without replacing explanations with private server responses.
- Updated the four operator guides and repaired their generator.

Saving a status does not confirm immediate termination of connections on an unreachable node. Migrations `20261112010000_user_access_reconciliation` and `20261112020000_scheduled_user_freeze` are required; users, keys, profiles and settings are retained. Remote nodes are not updated automatically.
