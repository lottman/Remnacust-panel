# 1.1.7.122

- В каждом пуле автовыбора можно независимо выбрать любые адреса, только явные IPv4 или только явные IPv6. Выбор семейства не изменяет стратегию балансировки, порядок, доступ пользователя или квоты. Доменам и смешанным адресам через запятую нужен режим «Любые адреса»; панель не выполняет DNS-поиск и не подставляет IP управления нодами в VPN-пулы.
- IPv6 можно использовать в отдельном пуле с выбором по времени ответа либо вместе с IPv4 в общем пуле. Для одного сервера с двумя семействами создаются отдельные хосты. Учитывайте поддержку IPv6 в сети клиента и на VPN-входе сервера.
- Семейство проверяется до выбора участников и повторно после привязки квотных ключей. Пустой строгий пул не превращается в DIRECT. Сохранены SNI, TLS, ключи и ограничения источников.
- Исправлены адрес IPv6 SOCKS-прокси, отклонение zone ID без исключения URL и однозначное отображение IPv6 с портом.
- Node 1.1.33 определяет основной интерфейс по IPv6-маршруту при отсутствии пригодного IPv4-маршрута. Предпочтение существующего IPv4-интерфейса и формат статистики сохранены.
- Installer 1.2.170 проверяет IPv6 хоста и добавляет отдельную IPv6-only NAT-сеть приложениям панели: API, обработчикам очередей и планировщику. Старые сети/IPAM, БД, кеш, proxy и опубликованные порты сохраняются. Режимы: `--panel-ipv6 auto|on|off`; по умолчанию `auto`. Глобальные настройки Docker и sysctl не перезаписываются. Для RA-маршрута может потребоваться предварительная настройка `accept_ra=2` на соответствующем интерфейсе.
- Редактор, подсчёт участников и руководство обновлены на RU/EN/FA/ZH. Новых миграций, разрешений API или изменений Core нет. Комплект: Installer 1.2.170, Node 1.1.33, Core 1.1.19 / Xray 26.11.9.

## English

- Each autoselect pool has an independent address filter: any address, explicit IPv4 only, or explicit IPv6 only. It preserves strategy, order, authorization and quotas. DNS names and comma-separated address lists use Any; the panel performs no DNS discovery and never infers VPN endpoints from node management IPs.
- Use separate IPv6 pools with response-time selection or mix explicitly configured IPv4 and IPv6 hosts in one pool. A server with both address families uses separate hosts. Client networks and server VPN listeners must support IPv6.
- Family checks run before selection and after quota credential binding. Empty strict pools never silently fall back to DIRECT. SNI, TLS, credentials and access restrictions remain intact.
- Fixed IPv6 SOCKS proxy hostnames, safe rejection of scoped zone IDs, and unambiguous IPv6 endpoint labels.
- Node 1.1.33 discovers the default interface through IPv6 when no usable IPv4 route exists; IPv4 preference and telemetry shape remain compatible.
- Installer 1.2.170 adds a dedicated IPv6-only NAT egress network to panel API, queue processors and scheduler after host checks. Existing networks/IPAM, databases, cache, proxy and published ports remain intact. `--panel-ipv6 auto|on|off` defaults to auto; global Docker/sysctl configuration is not overwritten. RA routes may require prior per-interface `accept_ra=2` configuration.
- Updated RU/EN/FA/ZH editor assistance, counts and guidance. No new migrations, API permissions or Core changes. Cohort: Installer 1.2.170, Node 1.1.33, Core 1.1.19 / Xray 26.11.9.
