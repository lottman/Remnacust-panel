# 1.1.7.126

Управляющие IPv4, IPv6 и имена хостов ноды собраны в один упорядоченный список: до 65 уникальных записей, включая выключенные. Порядок задаёт приоритет, переключатель разрешает адрес для связи панели. Сохранённые адреса не удаляются: их можно выключить или переставить, а для исправления добавить новую запись. При переносе прежний основной адрес и адреса MANAGEMENT/RESERVE включаются; остальные старые адреса сохраняются выключенными, чтобы панель не начинала неожиданные управляющие проверки.

Карточка показывает текущий адрес управления. Настроенный SOCKS5 сохраняется для всех резервных адресов; сбой прокси не вызывает прямой обход. Отдельный столбец показывает наличие настройки прокси, а не её работоспособность. При всех выключенных адресах управляющая связь, запуск и перенастройка не используют скрытый запасной адрес.

Параллельное редактирование параметров управления проверяется на конфликт: устаревшую форму нужно перечитать перед повторным сохранением. Массовое назначение профиля и inbound сохраняется согласованно. Сохранённые изменения остаются ожидающими применения и повторяются после временного сбоя доставки; сохранение само по себе не подтверждает успешное применение на ноде. Старые поля address и ips остаются совместимыми для внешних клиентов; совместимость API не расширяет права доступа и не снимает ограничения административных операций. Квоты и сохранённые данные восстановления не сбрасываются.

«Распределять соединения» выбирает участников для новых соединений без измерения CPU или свободной полосы. Xray использует roundRobin с HTTP-проверками: исключает серверы после неудачных проб и блокирует выбор после подтверждённого отказа всего пула, если свой резервный выход не задан. До первых результатов проб доступность ещё неизвестна; Mihomo/Clash/Stash — load-balance с round-robin. Для sing-box явно применяется urltest по времени HTTP-ответа, без циклического распределения. Уже открытые соединения остаются на прежнем сервере.

Текст шаблона подписки открывается независимо от загрузки списка хостов. Ошибка списка не блокирует редактирование; зависящие от него инструменты показывают собственную загрузку или ошибку. Ошибка самого шаблона остаётся причиной повторной загрузки. Сохраняется проверка выбранного формата JSON/YAML.

В редакторе профиля доступны три профиля адаптивного Xera HTTP: «Сбалансированный» (balanced), «Низкая задержка» (low-latency) и «Нестабильная сеть» (unstable-network). Они используют измеренные HTTP-ответы, ход передачи и ожидание запросов. В streamSettings.xeraHttpSettings.adaptive обязательны mode, minStreams и maxStreams. Целые границы — от 1 до 32, минимум не больше максимума; форма предлагает 4/32, начальный предел 8 ограничивается диапазоном. Минимум не создаёт запросов в простое.

Считаются одновременно активные HTTP-запросы отдельно для каждого направления, назначения и версии настроек транспорта. Это не число TCP-соединений, пользователей, всех сессий устройства или загрузка CPU. Подстройка допускает новые запросы, не прерывая и не повторяя начатые. «Применить в JSON» меняет черновик; профиль сохраняется отдельно, затем обновляется подписка клиента. Без adaptive сохраняются прежнее поведение, ручной JSON и extra, режимы передачи auto/stream-auto, ALPN, padding и квоты. Для адаптации нужен Core 1.1.22 или новее у клиента с поддержкой Xera HTTP. Связь Core 1.1.22↔1.1.21 проверена в Linux: 82/82 сценария IPv4/IPv6 с TLS HTTP/1.1, HTTP/2, HTTP/3 и REALITY, четырьмя прежними режимами и тремя профилями адаптации. Профили не обучают ИИ и не гарантируют невидимость для DPI или преимущество в сетях России и Китая.

Обновлено руководство на RU/EN/FA/ZH: функции, настройки, пределы и действия администратора отделены от технической документации для разработчиков. Сохранены лицензии и авторство исходных проектов. Обновлены зависимости, включая @stablelib/base64 2.0.2, Tabler Icons 3.52.0 и DOMPurify 3.4.18. Prisma остаётся на стабильной 7.10.1.

## English

Node control IPv4, IPv6 and hostnames share one ordered list of up to 65 unique entries, including disabled ones. Order sets priority and each switch permits panel control through its address. Saved addresses are retained: disable or reorder them, and add a new entry to correct one. Migration enables the previous primary and MANAGEMENT/RESERVE addresses; other old addresses remain disabled to avoid unexpected control probes.

The card shows the current control address. Configured SOCKS5 remains in use for every fallback address; proxy failure never triggers a direct bypass. A separate column shows proxy configuration, not health. When every address is off, control requests, startup and reconfiguration do not use a hidden fallback address.

Concurrent control-setting changes are checked for conflicts: reload a stale form before saving again. Bulk profile and inbound assignments are saved together. Saved changes remain pending and are retried after temporary delivery failures; saving alone does not prove successful application on the node. Legacy address and ips fields remain compatible for external clients; API compatibility does not expand access rights or remove administrator-only restrictions. Quotas and persisted recovery data are retained.

Distribute connections selects members for new connections without measuring CPU or spare bandwidth. Xray uses roundRobin with HTTP checks: it excludes members after failed probes and blocks selection after probes confirm the entire pool is down, unless a custom fallback is configured. Availability is unknown before initial probe results; Mihomo/Clash/Stash use load-balance with round-robin. sing-box explicitly uses urltest by HTTP response time without round-robin distribution. Existing connections remain on their original server.

Subscription-template text opens independently of the host list. Host-list failures leave editing available; dependent tools show their own loading or error state. Failure to load the template itself still requires retrying. The selected JSON/YAML format remains checked.

The profile editor offers three adaptive Xera HTTP profiles: Balanced (balanced), Low latency (low-latency) and Unstable network (unstable-network). They use measured HTTP responses, transfer progress and request waiting. All three fields in streamSettings.xeraHttpSettings.adaptive are required: mode, minStreams and maxStreams. Bounds must be integers from 1 to 32, with the minimum no greater than the maximum; the form offers 4/32 and clamps the initial limit of 8 into that range. The minimum creates no idle requests.

Limits count simultaneously active HTTP requests separately for each direction, destination and generation of transport settings. They do not count TCP connections, users, all device sessions or CPU load. Adjustment admits new requests without aborting or replaying existing ones. Apply to JSON changes the draft; save the profile separately, then refresh the client subscription. Without adaptive, previous behavior, manual JSON and extra, auto/stream-auto transfer modes, ALPN, padding and quotas remain intact. Adaptation needs Core 1.1.22 or later in a client supporting Xera HTTP. Native Linux interoperability between Core 1.1.22 and 1.1.21 passed 82/82 IPv4/IPv6 scenarios covering TLS HTTP/1.1, HTTP/2, HTTP/3 and REALITY, four existing modes and three adaptation profiles. Profiles do not train AI or guarantee DPI invisibility or an advantage on networks in Russia or China.
