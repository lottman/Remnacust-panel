# Проверенные патчи зависимостей

`npm ci` запускает [apply-dependency-patches.cjs](../scripts/apply-dependency-patches.cjs) через `postinstall`. Источник истины — [manifest.json](manifest.json): путь файла, исходный/итоговый SHA-256 и точные замены. Все файлы проверяются до записи; неизвестное содержимое зависимости останавливает установку. Повторное применение допустимо.

Патчи относятся к закреплённым `nestjs-zod`, `xray-typed` и `deepmerge`. Они сохраняют контракт OpenAPI, типы конфигурации и проверенное безопасное поведение merge. Версии и integrity зависимостей в lockfile не подменяются локальной правкой их файлов.

## deepmerge 4.3.1

Локальная защита проверенных путей [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4): свойства результата создаются через `Object.defineProperty`, чтобы `__proto__` оставался обычным собственным полем и не вызывал унаследованный setter. Покрыты исходник, CommonJS и UMD; поведение массивов, символов и custom merge сохраняется.

[Регрессионные проверки](../tests/dependency-patches.test.cjs) воспроизводят эти пути, вложенные структуры, `merge.all`, обычное объединение схем, повторное применение и отказ при непроверенном содержимом. Номер версии может по-прежнему попадать в отчёт `npm audit`: локальная защита не объявляется исправлением upstream и не скрывает advisory.

## Обновление зависимости

Изучите новую версию, заново проверьте необходимость каждого патча и пересоздайте manifest с реальными хешами. Не отключайте проверку SHA-256 ради установки. Если выполняете `npm ci --ignore-scripts`, перед использованием backend запустите `node scripts/apply-dependency-patches.cjs` самостоятельно.

Docker-сборка применяет патчи до сборки и переносит проверенные runtime-зависимости в образ. [README backend](../README.md).
