# Remnacust

## .env、Docker 和数据的位置

### 固定工作目录

面板：/opt/remnacust/panel/.env 和 /opt/remnacust/panel/docker-compose.yml。节点：/opt/remnacust/node/.env 和 /opt/remnacust/node/docker-compose.yml。独立订阅页面：/opt/remnacust/subscription-page/.env 及同目录的 docker-compose.yml。不要在 /opt/remnacust 根目录另建 .env。每项服务只有一个不带日期后缀的工作目录。其他页面可选择明确的固定目录。用 ls -la 查看隐藏的 .env 文件。

### 编辑并应用更改

面板先运行 cd /opt/remnacust/panel，再运行 nano .env 或 nano docker-compose.yml。保存后用 docker compose config --quiet 验证，再用 docker compose up -d --no-build --pull never 应用。节点或页面应先进入各自目录。docker compose restart 不会重新读取环境变量；up -d 会重建受影响的容器，可能造成短暂连接中断。不要随意替换 APP_SECRET、SECRET_KEY 或现有数据库凭据，它们与已保存的数据及访问权限相关。

### 旧版带日期目录

先运行 cat /opt/remnacust/FILES.txt 查找活动目录及 Compose 文件。更新会把安装程序管理的旧 panel-<日期>-<编号>、node-<日期>-<编号> 移至固定的 panel、node 目录，并更新环境文件及绑定挂载路径。密钥、Docker 卷及停止状态保持不变，验证失败时回滚。可单独运行 remnacust normalize-layout --component panel 或 --component node。未使用的旧目录移至 backups/retired-layout。被其他容器使用的路径或明确选择的外部安装不会盲目迁移，其实际位置保留在 FILES.txt。

### 其他文件和数据

backups/ 保存备份及回滚历史，logs/ 保存操作日志，registry/ 保存活动安装记录，control/ 是面板更新的本地通道；它们不是额外的面板工作副本。PostgreSQL、缓存及备份数据可能位于 Docker 卷中。移动工作目录不会新建数据库或替换现有卷。根目录及服务目录中的 FILES.txt 列出实际使用的文件。迁移后数据和已保存的密钥保持不变。

## 入门

### 主要部分

用户是账号及其访问设置；节点是连接服务器。配置文件定义 Xray 配置，主机定义订阅中的连接地址。内部小组将用户与允许的入站连接关联起来。首次配置请阅读“建立第一个连接”。

### 访问条件

连接需要正常运行的节点、已启用的入站连接、用户可用的主机，以及允许该入站连接的内部小组。用户状态、订阅到期时间、流量配额和设备限制也会影响访问。主机和标签限额独立于用户总配额。

### 检查修改

保存后检查详情中的新值。如果连接仍使用旧设置，请检查节点状态和日志，并在客户端刷新订阅。

### 面板离线一天

自主策略不会仅因面板不可达而停止。计划离线一天需要已应用的策略、持久卷、有效密钥，以及用户、主机和标签每项限制的足够本地额度。用户总剩余额度分配在各节点之间，不等于每个节点的额度。订阅到期、额度耗尽及配额周期结束仍会拒绝访问。重置后的下一周期需要面板重新分配额度；当前实现不会在离线时为下一周期授信。CDN、DNS、代理及节点证书必须独立工作。重建容器需要持久状态目录。通过 CUSTOM_CORE_URL 下载的内核还需要源站可达。断连期间新增的封禁或冻结在恢复连接后同步。维护就绪检查只确认当前状态，并不保证一天的流量。

### 维护日志与长期运行

CLI 详细日志位于 /opt/remnacust/logs/installer-panel.log、installer-node.log 或 installer-subscription-page.log。状态检查使用独立日志，不覆盖上次更新日志。同一组件下次操作才替换旧日志，并行执行无法覆盖正在使用的日志。面板更新保留 panel-update-<ID>.log，页面操作保留 page-<页面 ID>-<任务 ID>.log，SSH 节点维护在节点上保留 node-maintenance.log。失败时显示路径。日志仅 root 可读，不包含在公开订阅中，不记录输入或密钥跟踪。APT 自动确认；配置问题仍需通过 SSH 交互回答。配置缓存限制条数和大小，过大的条目绕过本地缓存，仍从原始来源返回。工作结束后，成功、错误或连接断开均释放容量。已比对官方 Remnawave 3.0.0、3.4.3 和 3.4.8 的 SQL 历史；未知或修改过的历史会在更改应用前停止迁移。

### 面板离线时的节点

已确认自主策略的节点可在面板离线时继续使用已保存的密钥，包括 CDN 直连节点的 XHTTP。访问期限、配额、限速和规则仍在本地执行；额度耗尽或到期仍会拒绝访问。新用户、续期和封禁在恢复连接后同步。安装程序在停止应用前检查节点自主性。未确认就绪时会警告并继续更新，无需额外参数。依赖面板的节点可能暂时断连。没有本地配额的旧策略会在 90 秒后到期，不能简单取消此期限。手动执行 docker compose down 会绕过检查，也会停止同一项目中的节点或代理。

### 更新进度与日志

面板更新显示八个阶段、已用时间和最近 24 条事件。只有存在上次操作的计时数据时才估算剩余时间，否则显示剩余阶段数。关闭页面不会取消更新。服务在校验和安装前固定最新安装程序的版本；经过验证的新面板可取代过期通知中的目标版本。成功更新后保留当前、上一版本及容器正在使用的镜像，清理多余的组件镜像。面板不会获得 Docker 套接字。

### 更新后的浏览器刷新

构建变化后，管理员已打开的标签页会检查面板版本并自动重新加载。数据缓存、显示偏好和表格状态会重置。登录、已保存模板、历史记录、SSH 密钥库和待处理维护操作会保留，正在执行的修改请求不会被中断。活动标签页每 45 秒及重新切回时检查，面板不可用时会在恢复后重试。服务器设置和用户数据不会被清除。没有此检查的旧版本标签页需要先手动刷新一次。即将发布的更新会在重载前保存配置或模板的本地草稿。保存失败时取消自动重载。可在“历史记录→未保存草稿”中恢复，且不会未经选择自动应用。不支持恢复的旧标签页仍可能丢失文本，请先复制。

### 受支持的系统与 PostgreSQL

安装器 1.2.141 支持 Ubuntu 22.04/24.04/26.04 LTS 与 Debian 12/13，架构为 amd64/arm64。Docker 使用当前发行版的官方仓库。不会自动接受 Ubuntu 中间发行版或衍生系统。amd64 矩阵检查真实用户空间、Bash、Python、OpenSSL 与单元流程，不能代替内核启动、systemd、防火墙或 arm64 测试。

已使用非超级用户数据库所有者，在 PostgreSQL 14.24/15.19/16.15/17.11/18.6 上检查全部 195 项迁移以及配额、到期和诊断场景。新安装请选择仍受支持并安装当前修复的主版本。PostgreSQL 14 将于 2026 年 11 月 12 日结束支持；版本 13 未测试且已结束支持。跨主版本升级需要单独使用 pg_upgrade 或导出/恢复。不要让新主版本镜像直接打开旧数据卷，请先在副本上验证迁移。

### 模板新鲜度

缓存版本从 PostgreSQL 的一行元数据读取，并与模板在同一事务中更新。回滚不会发布新版本。Redis 清理失败不会导致其他 API 进程继续提供旧模板。读取不会扫描用户或模板表；个人 HWID、权限及订阅输出仍然独立。

### 网络存储与冷缓存

网络块存储本身不意味着服务器不兼容。关键在于读写延迟、可用 IOPS 和已确认写入的持久性。PostgreSQL 或操作系统启动后，部分数据尚未进入内存；之后变快可能是缓存预热，但不能证明查询没有问题。应比较冷、热缓存下的订阅延迟、磁盘负载及数据库等待。不要仅为测试而清空生产数据库缓存。

共享缓存可用时，同一 API 进程内并发读取同一个原始模板会共享一次数据库查询。个性化配置、HWID 和权限检查不会共享。相同地理文件构建也会复用有界任务。慢存储仍会限制吞吐量，增加数据库连接不能解决 IOPS 不足。

PostgreSQL 需要正确的 POSIX 文件系统语义及可靠 fsync。NFS 需要 hard 挂载，服务器导出必须保证 fsync 的持久性。不要为速度关闭 fsync。blks_hit 表示 PostgreSQL 缓存命中，不包含全部操作系统缓存。PostgreSQL 14/15 使用 pg_stat_database 和 pg_stat_activity；pg_stat_io 从 16 起可用。官方要求：https://www.postgresql.org/docs/current/creating-cluster.html

## 建立第一个连接

### 配置顺序

1. [创建配置文件](/dashboard/management/config-profiles)，设置有效的 inbound 和唯一 tag。
2. [连接节点](/dashboard/management/nodes)，选择配置文件并启用入站连接。
3. [创建内部小组](/dashboard/management/internal-squads)，允许此入站连接。
4. [创建主机](/dashboard/management/hosts)，填写地址、端口并关联入站连接。
5. [创建启用的用户](/dashboard/management/users)，设置到期时间并加入小组。
6. 打开[用户](/dashboard/management/users)，复制订阅链接并导入兼容的客户端。

### 订阅中缺少主机

检查小组成员关系、节点上的入站连接、主机隐藏或禁用状态、小组限制和用户状态。再检查输出格式及 User-Agent 响应规则。主机存在于面板中不代表每位用户都能使用它。

## 导航、表格与选择

### 页面导航

侧栏可展开分类。在手机上通过菜单按钮打开导航，选择页面后自动关闭。快速启动用于查找页面；按标识符可打开指定用户、节点、主机或配置文件。文档链接会保留所选文章或 API 操作。

### 表格与操作对象

使用搜索、列筛选、排序、每页数量和列可见性设置。选择行与筛选表格不同，批量操作前应核对对象数量。限额中的“全部”针对当前有访问权限的所有用户，不仅是当前页或搜索结果。

## 主页：指标与状态

### 指标含义

主页显示已传输流量、当前带宽、在线用户和节点、账号状态及活动统计。累计流量与带宽不同。当前在线、今天或本周在线、从未在线分别统计不同时间范围，数量不必相同。

### 状态详情

打开状态卡查看详情。数据未出现时请等待加载或刷新。图标旋转表示请求仍在进行。

### 数据库诊断

主页显示应用连接、活动查询、锁等待和空闲事务。快照仅涵盖面板数据库中的当前角色，并排除诊断查询本身。不显示 SQL 文本、地址或密钥。必须使用管理员会话；API 令牌不能访问此端点。未知统计显示为“—”，而不是零。诊断失败不会影响主页其他区块。

界面仅在可见标签页中每 30 秒轮询；服务端合并并发请求，每个进程保留快照 15 秒。总流量图也使用有界的 15 秒快照。这些显示缓存不会改变访问检查、配额或封禁。等待数或查询时间升高时应检查日志与 SQL 执行计划；连接数量本身不能证明过载。

## 创建和编辑用户

### 账号与联系方式

用户名用于区分账号。邮箱、Telegram ID、说明和标签用于搜索与分组。连接访问权限由内部小组决定。

### 权限与配额

设置状态、到期时间、订阅流量配额、重置策略和内部小组，必要时选择外部小组。订阅配额为 0 表示不限量；主机和标签配额仍独立生效。下方字段说明对应当前表单。

### 保存

保存前检查小组和到期时间，保存后查看用户详情中的状态和日期。订阅在指定时刻到期，日期指示器的颜色不会改变到期时间。

### 到期检查机制

面板内部调度器每 30 秒向 USERS_WATCHDOG_QUEUE 提交到期检查。到期的 ACTIVE 和 LIMITED 用户转为 EXPIRED，并同步节点访问权限。无需额外 crontab。调度器、队列处理器、Valkey 和数据库必须运行；处理器停止会延迟执行。FROZEN 用户不参与自动到期：保存的剩余时长为 expireAt 与 frozenAt 之差，激活时从当前时间计算新到期日期，无需不断更新数据库日期。流量重置遵循独立计划，不会解除冻结。

### 冻结订阅

在用户菜单选择冻结：普通访问暂停，剩余有效期被保存。例如剩余两天会一直保持两天，直到重新激活。恢复时根据剩余时长计算新到期时间；重复冻结不会改变时长。剩余时间为零或流量额度耗尽时不会自动开放访问。续期增加剩余时间；已过期的订阅可冻结，剩余时间为零；保存的剩余时间不依赖当前日期进行格式化。冻结时显示蓝色剩余时长，日期不可编辑。有效期剩余三天时显示黄色，过期后显示红色。冻结本身不会清空流量，计划流量重置仍会执行。重启及导出导入后状态仍会保留。批量冻结通过队列逐个同步设备访问。

### 设备订阅预览

在设备卡片选择已注册设备、格式及 User-Agent 并生成预览。使用真实生成器和响应规则，不改变设备或连接历史，也不在数据库创建访问密钥。被封禁设备不会获得有效访问。主机列表为候选，生成器执行最终协议和池筛选。含密钥配置默认隐藏，仅明确请求时返回，最大 2 MiB。请作为私密数据处理，不要写入公共日志。

### 字段与控件

- **状态**: ACTIVE 为启用，DISABLED 为停用，EXPIRED 为过期，LIMITED 为配额耗尽，FROZEN 为暂停访问并保留剩余订阅时长，直到恢复。已过期账户冻结后剩余时间为零，冻结期间不可编辑到期日期。连接需要有效时长、流量和主机访问权限。
- **到期时间**: 订阅到期日期和时间。有效订阅应选择未来日期，并注意表单显示的时区。
- **Telegram 用户 ID**: 用户的数字 Telegram ID，不是用户名或备份聊天 ID。
- **电子邮件**: 用户联系方式和搜索字段，不授予入站权限。
- **备注**: 供管理员查看的记录说明，可填写服务条件或配置备注。
- **流量限制**: 以字节计的订阅配额，0 不限量；表单单独显示单位，主机或标签配额独立。
- **流量重置策略**: 用户总配额重置方式：不重置、每日、每周、自然月或滚动月。主机和标签的周期单独设置。
- **外部分组**: 具有独立订阅输出设置的外部小组，需要该小组的模板或订阅页面时选择。
- **到期时间**: 有效期和访问已暂停。重新激活后将继续计算已保存的剩余时间。冻结期间无法编辑日期。
- **内部分组**: 授予用户访问所选入站的小组，可分配多个内部小组。
- **订阅域名**: 已注册主域名或 CDN 域名的 UUID。留空使用默认域名。
- **用户名**: 用于搜索和管理用户的账户名，创建时不能与已有账户重复。

## 用户操作与详情

### 状态与重置

ACTIVE 表示其他条件满足时允许访问；DISABLED 表示已禁用；EXPIRED 表示已到期；LIMITED 表示订阅配额已用完。启用、禁用、重置流量和撤销或更换订阅是不同操作。重置订阅用量不会重置每个主机或标签的配额，请在“限额”中管理这些配额。

### 详情按钮

二维码和连接密钥用于导入订阅。JSON 显示数据，元数据展示附加属性，详情展示账号信息，节点展示分配或访问情况。其他按钮打开种子限制、订阅请求历史、HWID 设备和活动连接。工具提示说明各按钮用途，手机按钮具有更大的点击区域。

### 链接与删除

点击订阅字段或复制按钮即可复制链接；旁边的帮助也可在手机上点击打开。链接包含用户访问凭据，请勿公开真实链接。删除会移除账号，禁用则保留账号以便以后重新启用。

### 检查结果

小组、流量、期限、设备和状态修改会影响各操作对象。删除前检查选择范围。完成后刷新表格并检查一个账号。网络失败不代表操作未执行，重试前先检查当前状态。

## 导入与导出用户

### 导入文件

上传导出的 JSON 文件，其中必须有 users 列表，最多 20,000 条记录。“按名称恢复群组”会分配名称相同的现有内部群组，不会创建缺失的群组。取消勾选后不导入文件中的群组分配。表单中另选的群组仍会分配给所有导入的用户。

### 导入范围

导入后检查创建、跳过和失败的数量。用户名或短标识与现有记录重复时会跳过该记录，其他错误在导入结果中显示。测试一个新用户的订阅。导出文件包含访问凭据，请妥善保管。它不能替代数据库备份，也不包含配置、节点、API 令牌和全部面板设置。

### 字段与控件

- **按名称恢复内部小组**: 按文件中的名称恢复内部小组成员关系；目标面板需存在同名小组，缺失的小组会跳过。
- **将所有用户加入额外群组**: 为所有导入创建的用户分配额外内部群组，即使恢复文件中的群组也会添加。留空则不分配额外群组。

## HWID：设备、封锁与注册

### 数量限制与注册

新安装默认启用 HWID，升级会保留已保存的开关。兼容应用请求订阅时发送设备标识。用户限制留空时使用全局备用限制，0 表示设备数量不限，正数表示上限。例如设为 3 时，第四台新设备无法注册。“禁止新设备”单独控制注册，已有的允许设备仍可访问。

### 删除与封锁的区别

删除设备会清除注册；若允许新设备，同一应用可以再次注册。要禁止访问，请使用封锁：保留记录并撤销该设备的访问权限。解除封锁会移除禁令。“删除所有未封锁设备”只清除允许的注册，保留封锁记录。

### 使用条件

客户端必须发送受支持的 HWID 请求头。删除注册不等于永久禁止注册。自动化注册、封锁和解封需要各自的权限，仅能查看设备并不代表可封锁设备。

### 字段与控件

- **备注**: 供管理员查看的记录说明，可填写服务条件或配置备注。
- **显示生成的配置**: 包含该设备的私密密钥和链接，请勿公开分享。
- **禁止新设备**: 现有设备可继续使用。允许注册后仍保留设备数量限制。

## 内部小组

### 用途

内部小组关联允许的入站连接及用户。创建小组、选择入站连接并添加用户。一个用户可加入多个内部小组。修改入站连接会改变访问权限，但不会自动创建节点或主机。

### 管理

卡片可打开成员、入站分配、统计和小组操作。导出成员导出的是用户，而非整个小组的基础设施。主机的小组限制可允许或排除访问，因此加入小组不代表订阅会出现所有主机。

## 外部小组与订阅方案

### 用途

外部小组为成员提供订阅输出方案，包括模板、订阅页面和受支持的覆盖设置。它不能替代负责入站权限的内部小组。分配前请检查小组设置。

### 覆盖设置

修改外部小组模板或设置可能影响全部成员的订阅输出。请比较个人订阅和全局设置，因为小组覆盖值可能改变结果。删除或修改已分配的小组后检查订阅。

## 添加和配置节点

### 连接

节点是运行 Xray 的服务器代理。创建记录，填写管理地址和端口，配置连接凭据，选择配置文件并启用入站连接。管理端口与主机的客户端端口不同。检查面板服务器能否访问节点及连接参数是否正确。

卡片视图支持在选定标签后拖动节点。只调整可见节点的顺序，其他记录保留原位置。滚动时表单操作按钮固定在窗口底部。

### 字段与流量统计

名称、国家、标签和服务商用于描述基础设施。配置文件和入站列表决定运行的服务。节点流量倍率影响用户用量统计，不是带宽上限。流量跟踪、月度阈值、重置日和节点通知针对服务器用量，而非单个用户配额。

### 启动队列暂停

批量应用配置不会暂停全局启动队列；操作按节点分别协调。已有的手动暂停或旧版更新遗留的暂停不会自动解除。如果任务仍处于暂停状态，请确认维护已结束，再在 Bull Board 中恢复队列。重启面板不应取消管理员有意设置的暂停。

### 内核崩溃后的恢复

确认兼容内核崩溃后，代理可在没有面板时恢复最后的私有配置。正常进程不会重启；状态未知或管理忙碌时会推迟检查。管理员暂停和配额检查仍有效。每个代理进程每小时最多自动恢复三次。达到上限后再次崩溃，或恢复出错，都会停止重试；请检查日志、排除原因并显式启动新进程。热应用设置不会重置尝试次数。损坏的日志不会被清空。Node 和 Core 都需要包含此修复的新构建；只更新面板不会替换它们。

### 确认节点命令

同一节点的启动和停止操作按顺序执行。过期命令不应覆盖新的状态或连接地址。停止未获确认时保留错误原因，最多尝试五次，间隔 30 秒。管理员停用的节点不会在失败后自动启用。请检查连接和日志后重试操作。仍可从面板删除不可用节点。配置档案的批量任务逐个执行，同时保留共享配置准备过程。更新 Node 镜像会保留之前选择的托管 Core。请在节点任务中检查运行版本，必要时单独更新 Core，再刷新客户端订阅。确认支持并成功应用策略后，过期的自动选择限额警告会清除；检查失败不会解除限制。

### Xray 设置

“Xray 设置”为整个面板选择统一内核，默认使用 Remnacust 自定义内核。标准 Xray 支持标准协议和传输。用户、冻结、订阅、地理文件和客户端自动选择在两种模式下均可使用。主机和设备限制、自动选择接收对象独立计费、目标访问规则、非活跃访问主机、端口计划和 Xera HTTP 需要自定义内核。标准模式会禁用相关控件和有效策略，但不会删除已保存设置。

切换前会检查活动配置、端口计划和配额日志。请解决列出的阻碍，不要为切换而删除计费数据或预留额度。自定义节点需更新 Node 镜像才能选择双内核；标准 Remnawave 节点保留基本兼容性。更改进入队列，队列暂时不可用时由调度器重试。选中模式并不代表所有节点均已应用，请检查节点状态。

切换内核需要重启内核，可能中断连接。请先保存编辑器修改。打开的编辑器会刷新并加载对应验证器和配置架构。全局选择优先于旧的 geodata.core 字段，但不会重写已保存配置。自定义内核版本管理仅在自定义模式下可用。

### 安装和证书

SSH 安装需要 root 或免密码 sudo；允许使用已有空目录。错误会显示失败阶段，详细日志保存在服务器上。启用面板 IP 限制并使用 HTTP-01 时，TCP 80 仅在证书验证期间临时开放，随后关闭；进程异常时最多 15 分钟后自动关闭。续期采用相同方式。外部及服务商防火墙需单独配置。若要始终关闭 80 端口，请使用 DNS-01 或现有证书。

### 诊断与安全操作

诊断向已注册节点发送真实 mTLS 请求，检查 Xray、用户同步和端口应用状态，不验证完整客户端路径。禁用节点不会被探测，手动检查有速率限制。端口更改先预览，再用预览哈希和当前版本确认；过期预览被拒绝。成功需要节点 ACK，而非仅入队。错误时可恢复已应用版本，不覆盖更新的修改。故障需至少 20 秒内三次观测，恢复需 10 秒内两次观测。从未连接的节点不会触发故障告警。维护和操作抑制告警；手动暂停 30 分钟不会停止健康检查。安装向导通过 SSH 使用已验证安装器，并单独确认连接；不会覆盖现有目录。NET_ADMIN 默认关闭。设置主服务器 IP 后，除 SSH 外，所有入站端口和 ping 仅接受该来源；保留 22 和检测到的 sshd 端口。规则覆盖 Docker 转发及 IPv6，保留出站响应，不清空其他防火墙规则。这会阻止外部 HTTP-01 续期；请使用 DNS-01 或外部证书管理。移除限制：python3 /etc/remnacust-node-firewall/guard.py remove。

版本检查（--check-release）不会运行 APT。面板后台组件更新会推迟需要 SSH 的操作系统维护，并在进度和私有日志中记录；仅此推迟不会阻止组件更新。请单独通过交互式 SSH 会话维护系统软件包并回答 dpkg/debconf 问题。--yes 不会代替这些回答，也不会自动重启。

### MPTCP 与 Linux 内核安全

Xray v26.10.31 默认关闭 MPTCP，仍支持显式设置 streamSettings.sockopt.tcpMptcp。只有在安装修补后的 Linux 内核并启动该内核后，才应恢复原有 MPTCP 行为。Docker 镜像不会更新主机内核。CVE-2026-98432 影响 IPv4 TCP；关闭 MPTCP 可缩小攻击面，但无法修复内核漏洞本身。应根据发行版安全公告核验具体软件包，不能只依赖 uname -r。可使用 sudo ss -Mlnp 查看监听程序。不要在未经核验的内核上启用 MPTCP。来源：https://github.com/XTLS/Xray-core/releases/tag/v26.10.31 和 https://groups.google.com/g/golang-announce/c/PCoQcdxoScw/m/aD-MgXEvAAAJ。

### 字段与控件

- **限制**: 以字节计的订阅配额，0 不限量；表单单独显示单位，主机或标签配额独立。
- **重置日期**: 重置节点月度流量计数器的日期，用于服务器用量统计。
- **达量通知百分比**: 节点用量通知的百分比阈值，不增加配额。
- **标签**: 对象标签列表，主机标签还关联已启用策略；保存空列表会清空标签。
- **备注**: 管理员备注，不是路由或访问配置。
- **国家**: 显示或分组的国家代码，旗帜不改变服务器位置。
- **内部名称**: 面板中的显示名称，系统标识符独立。
- **地址**: 此表单使用的可访问 IP 或域名，与显示名称不同。
- **节点端口**: 所选服务的端口；主机客户端端口可与节点代理管理端口不同。
- **插件**: 分配给用户的插件配置，需确认相应执行组件已在目标节点配置。
- **集成**: 已分配的节点集成配置，创建和分配是独立操作。
- **代理 URL**: 用于面板向此节点发送管理请求的 SOCKS 代理，例如 socks5://user:pass@proxy.example.com:1080。留空表示直接连接，不代理用户流量；请妥善保管 URL 中的凭据。

## 节点操作

### 启用、重启与重置

启用或禁用控制节点在面板中的状态。重启会重新应用 Xray 运行设置，并可能中断连接。重置流量统计不会删除用户或升级核心。删除节点记录不会关闭服务商的服务器。

### 批量编辑

选择多个节点后，确认框显示修改的字段。切换配置文件前检查各服务器的证书、监听地址和端口。应用后检查每个选中节点的状态，不只检查第一行。

### 修改正在使用的端口

兼容修改通过内核应用，无需重启进程。从 Node 1.1.21 起，普通配置更新遇到确切的端口或传输变更拒绝时，会先验证配置，再自动仅重启 Xray。启动失败会恢复先前的私有 checkpoint 和工作配置，连接可能短暂中断。超时、未知回复和损坏的 checkpoint 不会授权自动重启。严格 requireLiveApply 和托管端口计划保持原有约定，此类拒绝不会转为隐藏的完整重启。更新容器或内核二进制也可能中断连接。

### 字段与控件

- **国家**: 显示或分组的国家代码，旗帜不改变服务器位置。
- **插件**: 分配给用户的插件配置，需确认相应执行组件已在目标节点配置。
- **集成**: 已分配的节点集成配置，创建和分配是独立操作。
- **标签**: 对象标签列表，主机标签还关联已启用策略；保存空列表会清空标签。
- **备注**: 管理员备注，不是路由或访问配置。
- **强制执行**: 将保证所有节点完全重启 Xray 核心。
- **平滑的**: 重启所有节点上的 Xray。 但如果节点哈希与当前的哈希相同，则请求可能无法实现。 这是默认的选项。
- **强制执行**: 确保节点完整重启 Xray Core。推荐使用此选项。
- **平滑的**: 向此节点发送重启 Xray 请求；若节点哈希与当前值相同，请求可能不会执行。

## 节点资源、状态与日志

### 状态与资源

打开节点卡片查看连接、在线用户、CPU、内存、网络和 Xray 信息，可用指标取决于代理返回的数据。缺失值不代表负载为零，请检查节点连接并刷新。在“文档 → 版本”中分别查看面板、节点代理和 Xray 的版本。

主机策略暂未应用。新配置尚未发送到节点；正在运行的 Xray 保留原配置。请检查节点连接及策略应用错误。连接恢复或错误解决后，面板会重试。已配置的限制仍保持启用。

请将节点更新至包含我们 Xray 的 Remnacust Node 1.1.1。此配置需要主机隔离 v2。更新前，其限制和新连接无法生效。当前运行配置会保留；更新后，面板将自动应用新配置。

管理地址应选择 MANAGEMENT 或 RESERVE 角色。OUTBOUND、BLOCKED 及其他角色不会使地址成为管理备用候选项。所有候选地址使用节点已配置的同一个 API 端口，不扫描其他端口。请使用诊断检查连接：面板后端向节点 API 发送经过身份验证的请求。TCP 端口开放、DNS 应答或旧的绿色状态都不能证明管理连接可用。请留意检查时间，并在修改设置后重新检查。 主地址和明确配置的备用 IP 都会接受经过身份验证的 API 检查。管理员必须只填写同一节点的地址：共用的 TLS/JWT 凭据确认面板信任关系，不证明节点的唯一 UUID。此检查无法区分使用相同受信任密钥或 CA 的另一节点。不进行外部地址发现。

Proxy URL 只影响面板到节点的管理通道，不影响用户 VPN 流量。该字段默认隐藏，可显示后查看或编辑。配置 SOCKS5 后，所有候选地址均使用同一个代理。切换节点 IP 无法修复不可用的共用代理，也不会静默回退到直连。要选择直连，必须明确将 Proxy URL 留空。路由状态不得显示用户名、密码或原始代理 URL。 节点返回给 API 令牌（包括通配令牌）的响应包含 proxyUrl: null，避免泄露 SOCKS 凭据。管理员会话仍可在默认隐藏的编辑器中修改该设置；路由状态不显示密码。 RFC 1929 的 SOCKS5 用户名/密码认证会以明文将用户名和密码发送给代理。请在私有网络中或通过安全隧道使用受信任代理。Node API 通道仍由 mTLS 加密，但不会因此加密单独的 SOCKS5 握手。 [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929.html#section-3).

### 日志

状态日志帮助定位断连、应用失败和重启时间。Xray 日志显示核心消息，内容取决于日志设置。将日志时间与配置文件修改时间进行比较。

### 节点健康评分

禁用、断开或仍在连接的节点显示 0/100。缺少活动配置和入站，或缺少正在运行 Xray 的新鲜确认时也为零。满足这些条件后，配置、连接、运行内核和正常资源四项信号各占 25 分。缺失指标不会提高分数，断开节点的缓存指标不会显示为当前数据。未知数据、内存压力和持续 CPU 负载分别列出。资源缓存为 30 秒，Xray uptime 缓存为 16 秒；缓存过期表示无法确认，不等于内核崩溃。

## 节点服务器优化

### 优化级别

none、safe、balanced、performance 通过 SSH 终端运行内置脚本，修改服务器系统设置而非订阅限额。内存小于 2 GiB 或使用率至少 85% 时建议 safe，其他服务器建议 balanced。

### 验证结果

检查会读取服务器的实际状态。在执行和验证结束前，所选级别可能与上次验证的级别不同。验证失败时不要认为成功，应检查 SSH 输出。

### 恢复未保存的编辑

在配置档案或订阅模板编辑器中打开“历史记录”→“未保存草稿”。这里保留最近的本地文本，包括未完成的 JSON 或 YAML。与已保存版本比较后，选择“载入编辑器”，再正常保存；不会自动应用。

保存成功后会删除对应的临时副本。等待保存响应期间输入的新内容仍可恢复；保存失败不会删除副本。本页的删除操作只清除本地草稿。

副本按管理员和文档隔离，仅在当前浏览器及面板来源下可用，最长保留七天，每份上限 8 MiB。清除站点数据会删除副本。文本在 IndexedDB 中加密保存，但这不能保护已打开的管理员会话。存储被禁用或超过上限时会显示错误。强制刷新界面前会等待草稿写入；浏览器崩溃时尚未写入的最后输入仍可能丢失。

### 证书文件

如果面板在准备配置时需要读取 PEM 文件，请将其以只读方式挂载到 /var/lib/remnawave 下并使用该路径。禁止读取此目录以外的文件，包括通过符号链接逃逸。普通文本、FIFO 以及超过 128 KiB 的 PEM 文件会被拒绝。此规则只适用于面板读取的文件，不会移动节点证书或自动配置节点 HTTPS。

## Xray 配置编辑器

### 编辑配置

打开配置文件并编辑 JSON。按 Ctrl+Space 显示补全建议，用上下方向键选择，按 Enter 插入，或按 Esc 关闭列表。当前选项会高亮。编辑器还支持搜索、格式化和全屏。保存前修复标出的错误，并运行配置检查。

### 生成 shortId

工具中的 Short ID 标签页使用 8 个安全随机字节生成 16 个十六进制字符。将它填入服务端 realitySettings 的 shortIds，并在客户端使用相同的 shortId。重新生成不会修改已保存的配置或开启轮换。

### 应用前检查

“保存”首先验证 JSON。缺少 protocol、字段拼写错误或结构错误时会显示原因，配置与历史保持不变。内置 Xray 验证器发现其他错误时，面板会显示错误并要求确认保存。确认不会跳过服务器的结构检查。已保存的无效配置可以重新打开并修正。

### 保存后

数据库保存与节点应用是两个步骤。进入队列的提示只表示任务已提交，请在节点状态和日志中检查结果。入队失败时配置仍已保存，面板会显示警告。保存期间的新修改保留在编辑器中。制作独立版本前先克隆配置。

### X25519 密钥

工具中的 X25519 标签页分别显示 password、publicKey 和 privateKey，并提供复制按钮。password 与 publicKey 是同一个公钥，名称因版本和客户端而异。私钥用于 REALITY 服务端，公钥填入客户端支持的字段。“所有值”复制这三个字段。生成新密钥会同时更新它们，不会修改已保存的配置文件。

## Xera HTTP 传输

### 来源与连接中的位置

Xera HTTP 是 Xray-core 中 XHTTP（SplitHTTP）传输的分支，在 Remnacust Core 中继续开发。它通过 HTTP 请求和响应传递连接数据。原始实现位于 [Xray-core](https://github.com/XTLS/Xray-core/tree/v26.9.30/transport/internet/splithttp)，我们的分支位于 [xerahttp](https://github.com/lottman/Remnacust-core/tree/main/xray/transport/internet/xerahttp)。

配置中，VLESS 指定连接协议和用户，Xera HTTP 指定传输，TLS 或 REALITY 保护连接。因此 protocol: "vless"、streamSettings.network: "xera-http" 与 streamSettings.security: "tls" 可以同时使用。切换到 Xera 时，不要将 protocol 改成 xera-http；应修改 streamSettings 中的传输及其参数。TLS、用户 UUID 和路由各自承担不同职责。

### 分支中的改动

Xera 使用独立的 network: "xera-http" 和 xeraHttpSettings 注册，标准 XHTTP 仍是单独的传输。分支包含 stream-auto、用于数据块的 customDownlinkPadding、配置验证，以及会话、上传队列、请求头和数据块的资源限制。会话标识由密码学随机生成器创建，并检查允许字符及足够的熵。

请求填充 xPaddingBytes 与 customDownlinkPadding 用途不同：后者填充传输的数据块，需要两端兼容处理。共同的 XHTTP 来源不代表所有 XHTTP 客户端都能识别这些扩展。速度和稳定性取决于网络、模式、代理和参数；分支本身不承诺提速或保证绕过封锁。

### 兼容性

Xera HTTP 是我们 Xray 内核中的 XHTTP 分支。节点内核和客户端内核都必须支持它。普通 Xray 支持 XHTTP 不代表支持 Xera。确认两端构建都接受 network: "xera-http"。先克隆可用配置并测试独立主机，再为所有用户切换。

### 配置设置

在[配置](/dashboard/management/config-profiles)中打开 JSON，将对应入站的 streamSettings.network 设为 "xera-http"。传输参数放在 xeraHttpSettings 中。下面只是 streamSettings 片段，并非完整入站，请保留自己的 tlsSettings、用户、端口和其他设置。TLS 需要有效证书及匹配域名。使用 REALITY 时设置 security: "reality" 并保留自己的 realitySettings。

```json
{
  "network": "xera-http",
  "security": "tls",
  "xeraHttpSettings": {
    "path": "/connect",
    "mode": "auto"
  }
}
```

### 节点、主机与订阅

在兼容节点启用入站，在内部群组中授权，并关联一个[主机](/dashboard/management/hosts)。填写公网地址、端口和 SNI。主机的 Path 与 Host 可覆盖配置中发送给客户端的值，必须与服务器或代理接受的值一致。更新测试用户的订阅。Xray JSON 保留 xeraHttpSettings；分享链接包含 type=xera-http 和 xeraSettings，客户端必须识别此格式。Sing-box、Clash 和 Mihomo 生成器会跳过这些主机，因为它们不支持此传输。

### 模式与 HTTP 代理

先使用 mode: "auto"。我们的实现中，没有 REALITY 时选择 packet-up；使用 REALITY 时选择 stream-one，配置独立 downloadSettings 时选择 stream-up。auto 模式的服务器接受受支持的客户端模式。

- packet-up：上传拆分为有限长度的 HTTP 请求，下载使用独立流。
- stream-up：上传和下载使用两个独立的长时间流式请求。
- stream-one：上传和下载共用一个双向流式请求。
- stream-auto：HTTP/2 配合 REALITY 时选择 stream-one，存在 downloadSettings 时选择 stream-up；其他情况选择 packet-up。CDN 边缘支持 HTTP/2，不代表它向节点转发请求体时不会缓冲。

通过请求头或 cookie 上传，以及 GET 方法，都要求显式 packet-up。两端的 path、host 和修改过的请求头参数必须一致。HTTP host 与 TLS SNI 是不同设置；请通过 host 设置 Host，不要使用 headers.Host。

使用 HTTP 代理时，检查路径、请求头、请求体限制和超时。流式模式要求在请求结束前转发请求体，并禁用响应缓冲。REALITY 要求受保护连接到达内核；普通 CDN TLS 终止不能代替它。如果代理无法转发所选模式，请在独立主机测试 packet-up。

stream-auto 仍然可用：它根据 HTTP/REALITY 和 downloadSettings 选择模式，不检测 DPI、延迟或缓冲，也不会在网络错误后更改已建立流的模式。

### 额外流量填充

customDownlinkPadding 在传输块中添加随机字节，会增加流量消耗。先不启用它。启用时两端设置相同的 header 和 token：header 必须以 X- 开头，长度 3–64 字符；token 为 16–128 个 base64url 字符。不要使用代理保留请求头。bytes 范围为 0–1024，blockBytes 为 1024–16384；budgetPercent 限制额外开销，最大 100%；burstBytes 为初始额度，最大 1 MiB；uplink 启用上传填充。这些参数不能代替 TLS/REALITY，也不保证绕过封锁。

bytes 和 blockBytes 接受数字或 "起始-结束" 范围。budgetPercent: 0 或省略该字段会关闭百分比上限，而不是关闭填充。限制额外开销时设为 1–100。burstBytes 要求非零预算；初始额度可能使短连接的实际百分比更高。token 用于协调填充处理，不能代替用户 UUID、协议密码或 TLS。首次测试不要启用填充。

budgetPercent 非零而 burstBytes 为零或省略时，内核使用 4096 字节初始额度。预算针对填充字节；HTTP 请求头、TLS 和数据帧也会消耗流量。

### 验证结果

在编辑器验证 JSON 并保存配置。数据库保存与节点应用是不同阶段，请检查队列、节点状态和日志。重新下载订阅，比较客户端配置中的 network、path、mode 和 SNI。“未知传输”表示所选内核不支持 Xera。主机缺失时检查群组、访问权限、筛选条件和订阅格式。连接不稳定时回到 auto，关闭额外填充，每次只调整一个参数。

从 XHTTP 迁移时，克隆配置和主机，保留可用版本。在目标入站中将 streamSettings.network 从 xhttp 改为 xera-http，将已核对的 xhttpSettings 参数移到 xeraHttpSettings。没有单独原因时，不要修改 protocol、UUID、端口或 TLS/REALITY。同一个配置版本不要保留两个传输设置块。仅重命名不能让标准 XHTTP 内核支持 Xera：请检查两端内核及客户端实际导入的配置。先沿用原 path 和 host，使用 mode: "auto"，不启用新扩展。切换其他用户前，检查连接、上传、下载、重连和节点日志。需要回退时使用保存的 XHTTP 配置，并更新订阅。

并行测试请使用独立节点或空闲端口。两个入站不能同时监听相同地址和端口。

### 新的传输配置与 HTTP/2

同时更新客户端和服务器内核。删除 xPaddingObfsMode、noGRPCHeader、noSSEHeader 和 xPaddingMethod: "repeat-x"；这些旧参数会被拒绝。请求和已接受的传输响应始终使用 tokenish 填充。双方的填充、会话和序号位置必须一致，不再搜索旧位置。uplinkHTTPMethod 也必须一致。携带 Access-Control-Request-Method 和 Origin 的 OPTIONS 是浏览器预检；不带该请求头的 OPTIONS 可以上传数据。

h2Params 配置 HTTP/2 服务器，例如 {"MaxConcurrentStreams":128,"MaxReadFrameSize":65536}。未知字段、禁止的密码套件和无效大小会被拒绝；超时为以纳秒计的数字。这不会将 HTTP/2 客户端变成浏览器指纹。

默认请求头跟随 TLS ClientHello 家族，明确设置的值优先。无法识别的请求在创建会话和读取请求体之前得到相同的普通 404 响应。填充和这些响应不能替代 TLS/REALITY 或 VLESS。uTLS 不会模拟浏览器的整个 HTTP/2/QUIC 协议栈。运营商无法读取 HTTPS 内的 HTTP，但终止 TLS 的 CDN 可以读取。不能保证 DPI 无法区分，仍需在目标网络中进行对比测量。

传输 HTTP 请求头名称必须以 X- 开头、长度为 3–64 个字符，且不能使用代理请求头。同一位置的会话、序号和填充键必须不同。无效或冲突配置会在监听器启动前被拒绝。

tokenish 填充现在通过单次遍历生成随机 Base62 字符，使 HPACK Huffman 编码后的长度精确匹配目标，不再追加可预测的修正后缀。这是填充值的编码长度，不是整个 HTTP 请求或 TLS 数据包的大小。

服务器启用 customDownlinkPadding 时，每个请求都必须包含且仅包含一个匹配的 header/token 标记，客户端也会检查响应确认。缺失、错误或重复的标记在读取请求体和分配会话前得到普通 404，不再回退到无填充流。请同时更新两端。Browser Dialer 不支持该扩展，因此此时也拒绝 CORS 预检。建议使用 32 个随机字节经 base64url 编码生成 token。标记由整个配置共享，终止 TLS 的 CDN 和该配置的用户都能看到；它不能代替 VLESS 授权，也不能阻止已经知道标记的参与者。

### 伪装边界与测量

加密隐藏内容，但不隐藏服务器地址、数据包大小、方向和时间。仅匹配 HTTP 请求头不能复现浏览器行为。TLS-in-TLS 和 The Parrot Is Dead 研究了这些限制；其他隧道的研究结果不代表对我们 Xera 的评估。FRONT 在 Tor 模型中研究掩护流量，其参数不能未经测量直接使用。

分别评估被动分类和主动请求。在同一网络上，针对不同负载及会话长度比较普通 HTTPS 与 Xera 的流量捕获；测量误报、延迟、流量开销、CPU 和内存。H1/H2/H3 功能测试与竞态测试验证正确性，不能证明 DPI 无法区分。本地修改没有增加后台请求、人工延迟或运行中切换协议。

### 客户端 HTTP/2 线缆特征

新的本地客户端路径将 HTTP/2 开始阶段与支持的 Chrome 133 TLS 配置保持一致：SETTINGS 及其顺序、伪请求头顺序、连接窗口和请求头压缩。当固定版本的 uTLS 将 chrome、hellochrome_133 及空 fingerprint 映射到 Chrome 133 时自动启用。其他版本和家族保留标准 H2 路径，不声称具有浏览器等效特征。本次修改不改变 HTTP/1.1 或 HTTP/3。

这是受保护连接内部的 HTTP/2 行为，不是新增加密。运营商无法读取 TLS 内的 SETTINGS，但终止 TLS 的 CDN 可以。它消除一个具体的跨层不一致，却不隐藏服务器地址、会话时长或应用流量模式。尚未证明对 DPI 完全不可区分。

TLS/REALITY、证书校验、证书固定及 ALPN 检查继续由现有 Xray 路径执行。不跟随重定向，拒绝在一个传输中更改 HTTP authority，错误后不自动重放 POST。支持取消请求、关闭及连接复用。每个客户端传输最多四个连接和 每个方向 32 个活动 HTTP 请求；等待中的请求也遵循自身 context 的取消。不会增加后台请求或人工延迟。

该路径固定使用 fhttp v0.7.3。loopback 测试检查实际发送的帧，而不仅是配置值。这是本地修改，不能视为已发布版本。

解码 HTTP/2 前检查响应边界：帧不能超过声明的 16 KiB；一个请求头块最多 512 KiB、32 帧，且必须在 10 秒内完成。无效的 CONTINUATION 顺序会关闭连接。请求头完成后清除截止时间，不限制数据传输时长。这限制过量请求头处理，不改变数据或加密。

### 在编辑器中检查设置

节点配置与 Xray 订阅模板使用同一传输模式。extra、customDownlinkPadding、xmux 和 downloadSettings 内也提供补全。编辑器检查取值与边界，WASM 还会运行配置构建器。JSON 有效并不代表应用支持该传输。

更改内核后，请重新构建编辑器和前端。模式、WASM 及其 JavaScript 分别使用内容版本 URL；补全变化不会重新下载未变化的 WASM。

h2Params 与服务端资源限制保留在节点上，不写入客户端订阅，包括 extra 内的设置。共享传输设置与 downloadSettings 保留。xmux.hKeepAlivePeriod 单位为秒：0 使用默认值，-1 关闭空闲探测，正值不超过 604800。启动前验证 HTTP 标头名称和值。Host 请通过单独的 host 字段设置。

片段保存命名的配置部分，可在多个配置文件中使用并集中编辑。保存片段与同步引用它的配置是不同步骤，确认同步后才分发修改。

### 删除

删除片段后界面会提供同步操作。检查受影响配置和节点，引用可能需要修改。广泛应用前验证完整生成的 JSON，不只验证片段本身。

### 字段与控件

- **片段名称**: 面板中的显示名称，系统标识符独立。

## 生成密钥与密码

### 密钥

生成器创建受支持的密钥对和配置参数。公钥可提供给客户端，私钥应保留在服务器端。不同协议的格式不能互换。保留匹配的密钥并核对所选入站连接。

### Shadowsocks-2022

选择与 Shadowsocks-2022 配置中加密方法对应的密钥类型。服务器和客户端参数必须匹配，不同加密方法的密钥不能互换。

## 主机：地址与订阅输出

### 基本参数

备注是订阅中的连接名称。地址和端口是客户端连接目标，inbound 从配置文件提供服务器参数。SNI、Host、路径、ALPN 和安全设置必须与服务器的 TLS 或传输设置一致。主机节点分配和节点入站启用是独立设置。

在列表上方选择已启用、已禁用、可见或隐藏。可见显示 isHidden = false 的主机，包括已禁用的主机；已启用显示 isDisabled = false 的主机，包括隐藏的主机。此筛选与所选标签同时生效，支持卡片和表格视图。在卡片视图中可拖动标签内的主机，其他记录保留原位置。滚动表单时，保存、复制和删除按钮仍在底部可用。

### 可见性与操作

隐藏的主机不会出现在新的订阅响应中，但仅隐藏不会撤销已发放的连接凭据。禁用主机通过节点策略控制访问。内部群组决定哪些用户收到主机。克隆只创建具有原设置的新主机记录，不会创建服务器。保存后等待策略应用，再测试用户订阅。

面板与节点失去联系时，用户有权访问的主机会保留在订阅中，连接参数不变。节点状态本身不会隐藏主机。服务器恢复前可能无法连接；恢复后，无需仅为恢复主机条目而刷新订阅。隐藏、停用、小组限制、配额和设备封锁仍单独检查。

### 批量编辑

选择主机和要更新的字段，检查接收对象。选择修改标签并留空会清除标签；不选择该字段则保留原标签。记录顺序决定订阅顺序，启用随机排序时除外。修改入站、可见性或群组后，在客户端更新订阅，检查目标连接是否存在。

### 受限主机延迟

HTTP 检测必须通过主机本身访问允许的网站。在“仅允许”模式下，表单显示首个允许域名的可复制 URL。Happ 配有真实 Provider ID 时，面板为订阅中所有可见主机选择共同允许的 URL，并保留合适的自定义 URL 与 HTTP 方法。明确选择的 TCP 或 ICMP 不变。没有共同域名或仅允许 IP/CIDR 时，改用 TCP；TCP 只确认服务器可达，不验证 VPN 授权。在 INCY 的订阅设置中选择 HTTP/INCY 检测并填写此 URL；普通 HTTP 标头不能设置其检测地址，自动配置需要 INCY 自身的 Premium API。不会扩大网站权限，也不会通过 DIRECT 检测。网站必须响应所选 HTTP 方法；跳转到禁止域名仍会被阻止。

### 设备动态带宽

以 Mbps 设置的用户速度是此主机上该用户所有连接的共享上限。活跃设备密钥按已服务字节数共享带宽：单个设备使用空闲容量，其他设备产生流量时会重新分配；空闲设备不预留份额。设备上限合计限制其私钥的全部上传和下载连接。若用户上限为 20 Mbps、设备上限为 15 Mbps，一个设备最多使用 15 Mbps；两个持续传输的设备可共享 20 Mbps，约各 10 Mbps。这些是上限，而非网络速率保证。主机或标签的共享上限先在用户间分配，再在用户设备间分配；增加连接数不会增加份额。未配置共享上限时，核心无法知道物理信道容量。

### 单个用户的速度

在“此主机的每位用户”中，以 GiB 设置流量配额，以 Mbps 设置速度。配额限制数据总量，速度限制传输速率。同一用户在此主机上的全部设备与连接共享速度，上传和下载合计。设置 2 Mbps 时，两台设备合计最多 2 Mbps；其他用户拥有独立上限。另一主机使用自身设置。0 只关闭主机自己的限制，已启用的标签限制仍然生效。下方分别设置所有用户共享的主机总速度和计费倍率。

### 批量操作与国家搜索

启用、禁用和删除在数据库提交后返回；节点策略在后台发送，并重试不可用节点。保存成功不表示已断开连接的节点已收到更改。按钮显示进度，列表在 API 确认后更新。克隆最多同时发送三个请求；成功来源取消选择，失败来源保留以便重试。国旗搜索支持 RU/EN/FA/ZH 国家名称或两字母代码，与界面语言无关。

- **设备速度限制**: 每个标签在此主机上独立设置设备上限。启用的限制中最严格的限制生效。

### TLS、传输与客户端

SNI 指定 TLS 名称，可从地址派生；指纹配置客户端 TLS。Host 和路径是传输参数。证书固定、证书名称验证、Mihomo X25519 和 IP 版本需要兼容客户端。修改 Mux、SockOpt、传输 JSON 或服务器说明前检查输出格式支持。

### 目标域名规则

OFF 关闭附加过滤；ALLOW_ONLY 仅允许所列目标；DENY 封锁所列目标。这是主机流量策略，不是 User-Agent 订阅输出条件。检查必要的 DNS、服务目标及入站隔离支持。

## 主机标签与共享设置

### 标签与策略

标签只负责主机分组，不自动创建配额。配置并保存标签设置，每个主机可单独加入标签配额、用户速度限制和共享带宽。这些开关独立，主机自身限额仍同时生效。

### 带宽与倍率

标签配额汇总同一用户在参与主机上的用量。标签用户速度上限在各参与主机独立生效，共享带宽则由参与流量共同使用。明确的主机倍率控制统计，null 表示继承标签倍率；此时主机自身配额按表单说明使用倍率 1。

### 保存设置

标签设置作用于已启用对应配额、用户速度或共享速度开关的关联主机。设备速度继承开关也相互独立。保存前检查参与主机和限制。接收对象与个人例外位于“限制”页面。

### 流量记账与配额批处理

积压流量每个事务最多提交八张收据，每张收据可包含多个用户。PostgreSQL 提交后才删除 Redis 确认记录，重试不会重复扣除流量。读取新计数器时，锁保留到结果保存。配额 epoch 在同一修订事务内每批最多写入 500 行。协调器按所有者提交额度和游标，检查代次并在各作用域之间续租。处理预算在所有者之间检查；单个所有者拥有很多作用域时可能超过 20 秒。

### 标签设备限速

启用对应开关后，标签的设备上限在各主机独立生效，与标签配额、用户速度和共享总速度相互独立。采用最严格的有效上限；0 仅关闭对应上限。节点和核心必须支持 remnacust-device-speed-v1；不兼容节点不能确认新限制。多个绑定节点间保守地分配上限，确保总和不超过设置值；空闲带宽不会跨节点转移。HWID 用于签发独立私钥。同一密钥的副本视为一个设备；没有独立密钥的应用无法区分物理设备。面板不可用时本地规则继续生效。

### 按标签限速

标签的用户速度在每个参与主机上分别施加相同上限。分组共享总速度是所有参与流量共用的另一个速度池。每个主机独立启用标签配额、用户速度和共享总速度。多个限制同时生效时采用更严格的上限。0 表示没有对应限制，而非阻止流量。Mbps 已表示每秒兆比特；不计开销，8 Mbps 约为 1 MB/s。

## 订阅模板与编辑器

### 格式

Xray JSON、Mihomo、Stash、Singbox 和 Clash 使用独立模板。选择格式和模板再编辑结构。客户端模板不同于服务器 Xray 配置。生成器加入允许的主机和用户数据；不支持的协议可能被对应格式排除。

### 验证输出

创建或选择所需格式的模板。重命名时，请选择该格式下尚未使用的名称。名称重复时，面板会标记名称字段并说明原因，保留已输入的内容。删除前，请检查订阅设置和外部群组是否使用该模板。修改后获取测试用户的订阅并导入客户端；JSON 或 YAML 格式正确并不代表连接可用。

### 按完整 HTTP 响应时间选择

最低响应时间（ping + TTFB）通过池内每台服务器执行 HTTP 探测。Xray 使用 leastPing 与 observatory 或 burstObservatory，Mihomo/Clash/Stash 使用 url-test，sing-box 使用 urltest。测量发生在用户应用中，而非面板。时间包括建立连接、HTTPS 的 TLS 和等待 HTTP 响应，并非独立 ICMP ping 或两个独立测量值之和。

对于 leastPing，面板会补全缺失的观测器，并将所有均衡器选择器加入 HTTP 探测，手写 JSON 也适用。保留自定义地址、间隔和明确指定的 HTTP 方法。默认使用 https://www.gstatic.com/generate_204 和 30s；burstObservatory 使用 HEAD、5s 超时和 sampling 2。HEAD 不下载响应体，明确设置的 burstObservatory GET 会将读取响应体计入延迟。请使用整个池都能访问的同一个小响应，最好返回 204。面板测量无法绕过探测网站被阻止的问题。

首次测量后，应用按设置的间隔更新结果。新连接使用最新选择，无需刷新订阅；现有流不会迁移。Burst 使用样本平均值；原生 url-test/urltest 的 tolerance 可减少频繁切换。支持的设置和值取决于客户端内核。探测超时和备用路由决定失败时的行为。池成员仍受用户权限和适用配额限制。

最低负载模式以及带备用出站的轮询或随机模式需要 HTTP 观测。面板会补全缺失的探测，同时保留所选策略和自定义探测地址。不带备用出站的普通轮询或随机模式不会增加请求。探测网站不可达可能使正常服务器被排除。

### 代码和界面中的自动选择

Xray JSON 的编辑和自动选择标签页共享同一草稿。修改现有池或均衡器会立即更新对应 JSON。新池添加 injectHosts、均衡器、路由及 leastPing 或 leastLoad 所需的观测。再次为同一池添加均衡器不会创建第二张卡片。与池同名的未完成均衡器会在原位置补全。创建和复制的模板会立即出现在列表中。其他出站、规则和设置保留。更改面板与上次保存内容比较，在手机上位于表单下方。保存会应用有效草稿；含错误的文本会带警告保存在服务器和历史记录中。

### 主机池和标签

selector.type 支持 uuids、精确标签 tags、tagRegex、remarkRegex 和 sameTagAsRecipient。所有方式均支持 all/random/group；tags 分组包含标签，其他分组包含筛选后的主机 UUID。all 注入所有符合条件的来源，random 最多选择 selector.expected 个不重复主机，group 从 selector.groups 选择一个非空且符合条件的组。组可以是命名对象或二维数组。省略 mode 保持旧版 all；省略 selectFrom 选择隐藏主机。选择前检查访问权限、可见性和排除规则。接收主机和来源主机配额分别计算。随机选择在生成订阅时发生，而非每次 VPN 连接。显式模式没有可用来源时省略该配置。

### 分配与均衡

在自动选择使用位置中指定具体配置及接收主机。remnawave.assignments 包含 balancerTag 和接收方列表。在界面中先选择主机或标签，只显示相应列表。切换方式会从此分配中移除另一列表。旧的混合分配会显示警告，仅在明确选择后更改。主机直接分配优先于标签匹配；主机卡片中的显式模板优先于其他模板。同一主机可分配多个自动选择，每个生成独立配置。重复标签匹配不会生成重复配置。流量与速度限制在接收主机上设置。通过自动选择使用池成员时，不扣除成员主机配额，也不继承其速度限制。同一接收主机的多个自动选择共享额度。未设置接收主机限制且未启用其标签限制时，不设主机级上限。账户总配额仍然生效。 源池仍受用户访问权限限制。重命名或删除均衡器时会同步更新分配。旧版 assignTo 仍可读取；编辑时请为它选择具体配置。可从卡片菜单复制任意受支持格式的模板，保留设置、草稿、标签和地理文件引用，并清除接收主机分配。代码存在错误时仍可保存，错误内容作为草稿保留。错误路径会显示池编号，并可跳转到对应代码字段。tolerance 是 0 到 1 的探测失败比例，0.01 表示 1%。0 关闭此检查。0–1 外的数值在 JSON 中保留，Xray 读取配置时在内核中限制该值（例如 2 变为 1）。 通过 API 保存时也会检查规则引用的出站和均衡器。不存在的名称不会被替换为 DIRECT 或其他路由：编辑器文本作为草稿保留并显示准确的错误路径，生效模板保持不变。由主机备注或标签生成的名称在生成订阅时确定。

### 自动选择限额

流量与速度限制在接收主机上设置。通过自动选择使用池成员时，不扣除成员主机配额，也不继承其速度限制。同一接收主机的多个自动选择共享额度。未设置接收主机限制且未启用其标签限制时，不设主机级上限。账户总配额仍然生效。 Xray JSON 使用不同凭据区分直连和自动选择。直连扣除成员主机配额，自动选择只按接收主机的倍率及已启用标签限额计费。切换成员仍共享用户和设备上限，不同接收主机限额独立。访问权限、设备封禁、账户状态和目标限制始终有效。独立路由计费需要支持 remnacust-routed-device-speed-v1 的 Node/Core，旧版拒绝应用路由策略。启用前请更新 Node/Core，再在应用内刷新订阅。旧凭据仍按原方式计费，已记录的历史不会重新分配。若一台主机的 DENY 与另一台主机更宽泛的 ALLOW_ONLY 条目重叠，将移除整个重叠的允许条目。

### 历史与恢复

Xray JSON、Singbox、Mihomo、Clash 和 Stash 保留最近 30 个已保存版本。数据库升级将现有代码保留为首个版本。历史显示日期和与当前草稿的比较。在编辑器中打开会恢复全部代码，包括自动选择、均衡器和分配。替换未保存草稿前需要确认。保存会创建新版本，因此恢复操作本身也可以撤销。代码与历史在同一事务中保存。

### 所有可编辑格式的自动选择

Xray JSON、sing-box、Mihomo、Clash 和 Stash 均提供自动选择。sing-box 使用 urltest/selector；YAML 客户端使用 url-test/select/fallback/load-balance。组可按 UUID、标签或正则筛选，设置 all/random/group 和来源可见性。先检查权限；显式空池不会变成 DIRECT。手动成员保留。所有标签页共享草稿；未保存的 Xray 测试池可连同专用均衡器一起删除。表单显示保存和放弃草稿，代码工具仅在编辑页显示。

### 地理文件库

现成数据集提供已发布的 V2Fly 和 MetaCubeX GeoIP/GeoSite；导入同样检查 HTTPS 和内容，不会自动启用规则。本地文件可点击“点击上传”。在地理文件页从电脑上传或通过直接 HTTPS 链接导入，填写名称和内容格式。选择库中已有文件并附加到模板，选择 DAT 分类及 DIRECT、REJECT 或组。支持多个文件和跨模板复用。DAT 在服务器端转换为原生规则；sing-box JSON/SRS 和 Mihomo YAML/text 通过远程 rule_set/rule-providers 提供。Clash/Stash 支持 YAML payload。保存模板并刷新订阅后生效。文件链接公开，请勿上传秘密。最多 32 个 64 MiB 文件，文本最多 8 MiB；拒绝本地地址、压缩包和不相关内容。迁移时另行保留 backups/geofiles，数据库备份不包含二进制文件。删除文件后，历史版本可能需要重新绑定。

### 优先级和备用服务器

“按优先级：首个可用服务器”选择第一台健康服务器。需要精确顺序时，选择主机及所有选定主机，再用箭头排序。多个池的前缀也可在均衡器中排序。标签和正则遵循主机总列表顺序，随机模式先选子集。故障切换和恢复主服务器取决于健康检查，仅影响新连接，已有连接不会迁移。Xray JSON 在输出时转换为标准单候选 leastPing 均衡器及 Loopback 链。首次检查成功前或全部服务器不可用时阻断连接，显式 fallbackTag 最后使用。界面会移除指向同一池的自动备用项，保留自定义备用项和检查设置。每个均衡器最多 128 个候选，每份配置最多 256 个。routing script 及其他均衡器冲突的宽泛选择器不兼容。Mihomo/Clash/Stash 使用原生 fallback，遵循 proxies 顺序，代码显式成员在池成员之前。sing-box 配置不支持自动严格优先级，selector 为手动选择，URLTest 按延迟选择。需要完整 JSON/YAML 订阅。

点击“服务器顺序”在独立窗口调整顺序，使用箭头移动成员，长列表分页显示。若需精确的服务器顺序，请选择具体主机及全部已选主机。轮询会循环分配新连接；若只想在前一台不可用时切换，请选择“优先级：首个可用”。显式轮询顺序在内核排序标签后仍保持，每个均衡器最多 128 个成员，每个配置最多 256 个。修改后保存模板并刷新订阅。

### 何时将接收主机添加为 proxy

“同时将接收主机添加为 proxy”对应 remnawave.addVirtualHostAsOutbound。启用后，生成器根据接收主机的地址、端口、传输和安全设置额外创建一个标签为 proxy 的独立出站。自动选择不要求启用此开关，开关也不会自动启用 TLS。对于仅代表均衡器的“自动”占位主机，请保持关闭；真实的 injectHosts 池成员和均衡器仍会保留。仅当它是客户端支持的额外真实连接时启用。内核可能拒绝未使用 TLS/REALITY 或 VLESS encryption 的公网 VLESS；Happ iOS 的“通过代理”检测可能报告 failed to build outbound config with tag proxy / vless without TLS。普通检测通过或其他设备可用，并不能验证这个额外出站。占位主机应关闭开关，真实主机应修正传输与安全设置，然后保存模板并在应用中更新订阅。此开关不会配置服务器或安装证书。

### 临时分发错误

读取用户、设备或主机失败不代表订阅已被删除。配置分发返回临时错误并建议 30 秒后重试；用户确实不存在时仍返回 404。主机查询失败不会被当作成功的空订阅。确实没有可用主机时，会跳过额外的模板和配额查询。重复失败时检查日志及数据库连接，不要为修复网络问题而替换用户密钥。

### 输出大小与生成错误

生成的订阅最大为 16 MiB。Sing-box、Mihomo、Stash 和 Clash 的分组展开在生成期间也有限制，并为转义与格式化预留空间；过多的分组成员可能在达到精确上限前被拒绝。请减少分组数量或组内服务器数量。生成失败返回 HTTP 503，而不是成功的空订阅。缓存不可用时从数据库读取模板。

### 带警告保存

即使 JSON/YAML 无效、未选择主机或地理文件操作未填写，仍可保存。含错误的文本会作为草稿保存在服务器和历史记录中，重新打开时恢复相同文本。订阅继续使用上一份可用配置。修复警告并再次保存后，有效内容会替换工作版本并清除草稿。网络或数据库错误不会被报告为保存成功。

### 在同一卡片中选择主机与均衡流量

主机来源与其策略位于同一块区域。使用共享均衡器的池会合并显示，手动均衡器仍可见。删除区域会移除其来源、均衡器及关联规则，同时保留独立组和手动出站。leastLoad.expected 表示所选节点数量；tolerance 是 0 到 1 的允许探测失败比例，0.01 表示 1%，2 不表示两个节点。Xray 会将超出范围的有限数值限制为 0–1；此类模板可带警告应用，并保留原始数值。新建池会按 UUID 选择格式支持的已启用主机。没有合适主机时，设置会保持为草稿，直到选择来源。

### 应用何时下载地理文件

面板按每个配置计算大小，包含列表展开和客户端格式化开销。小型规则集内嵌，Happ/INCY 下载大型 DAT。需要 JSON 订阅：启用“在订阅基础路径提供 JSON”或使用 /json。保存模板并刷新订阅。

### 地理文件自动交付与大小

启用基础链接 JSON 后，Throne 1.x 从稳定版 1.2.0 起可通过自身 User-Agent 获取完整 Xray JSON 数组；若发送 beta 版本号，最低为 1.2.0-beta.5。旧版或未识别版本保持原格式。明确使用 /json 或 /v2ray-json 时，即使 User-Agent 被识别为浏览器也会返回配置。此功能不授予 Throne 专用 Happ/INCY 扩展或 DAT 交付能力，仍遵守普通兼容客户端规则及预算。明确格式选择和访问限制仍然生效。 不再提供手动交付开关。面板先将全部所选地理文件生成为内嵌规则。INCY 的大型无逗号列表使用无损 Xray StringList 格式。每个最终配置按四空格格式化后的大小与内嵌阈值 90,000 字节或 20,000 个条件比较；整个配置仍有 900,000 字节的保守预算，为客户端修改预留空间；这不是 INCY 官方公布的精确上限。此检查不累加多个主机，整个响应仍有独立的 16 MiB 传输上限。配置过大时，受支持的 Happ/INCY 使用分类命名隔离的合并 DAT；内嵌处理限制也可能触发下载。其他 Xray 客户端可从一个模板的文件内嵌最多 50,000 个条件，不发送 Happ/INCY 头；20,000 个条件的切换阈值仅用于自动 DAT 交付。仍保留编译、模板大小和完整响应的限制，不截断规则。应用必须支持完整 JSON 配置导入。服务器链接订阅不携带路由。v2rayTun 使用自己的 routing 格式，而非 Happ/INCY 配置。启用基本地址 JSON 时，v2rayTun 会收到包含这些规则的完整配置。主机排除设置及响应规则中的明确 JSON 禁用仍然生效。sing-box/Mihomo/Clash/Stash 小型数据集内嵌，大型数据集远程加载；二进制 SRS 始终远程加载。为兼容旧版 Clash，原生规则集也采用下载方式。DIRECT、REJECT、分组及规则顺序均保留，不覆盖手动 routing 或地理数据。配置名称使用订阅 profile-title（包含小队覆盖），未设置时使用订阅域名，稳定短后缀用于隔离同名订阅。旧 downloadToClient 字段仍可读取，但不再控制交付方式。客户端间隔仅适用于下载，服务器刷新使用独立计划。

### 启用和关闭地理文件

订阅设置 → 主要设置 → 附加设置：先启用基础地址 JSON，再启用 Remnacust 地理文件。此功能默认关闭。启用后编辑器才显示地理文件标签。关闭后保留文件库、关联及更新设置，但不再用于新订阅，并停止后台自动刷新。管理员手动设置的 Xray JSON（geodata、geosite:、geoip:、ext:）及 routing 标头中的 DAT 地址在开关关闭时仍然保留；清理之前的自动配置不会覆盖这些设置。下载和更新由支持相应方式的内核或应用执行。geosite:、geoip: 或 ext: 引用只读取本地 DAT 分类，不会自行下载文件；须单独设置下载地址和更新方式。管理员仍可手动上传或刷新文件库中的文件，但此操作不会自动将文件加入订阅。关闭 JSON 前必须先关闭地理文件；面板不会自动关闭。切换后请在应用中刷新订阅。已开始的操作可能仍按原设置完成。此前签发的下载链接仍然有效。

### 启动与并发请求

面板启动后，不同地理文件构建在有界队列中等待：每项操作最多同时运行两个任务、接受 32 个任务。相同请求共享一次构建。DAT 缓存最多保留 16 个集合和 32 MiB。订阅页面最多等待面板 30 秒，客户端断开时取消请求；访问失败不会被缓存。DAT 下载使用独立的八连接池。每个页面进程最多接受 16 个下载请求（包括等待中的请求），慢速文件不会占用页面和配置请求的连接。过载时返回 503 和 Retry-After: 2，请稍后重试。

### 从模板移除地理文件

保存模板并在应用内刷新订阅。禁用最后一个自定义地理文件后，仅当服务器保留历史记录时，面板才会清除此订阅此前签发的配置：清空文件地址及规则列表，并关闭定期下载。手动写入 JSON 的普通 geosite/geoip 规则仍保留并使用应用标准文件。显式路由头优先；禁用自定义文件不会关闭客户端全部路由。配置名称保持不变；移除的 GeoIP 或 GeoSite 类型会显式发送空下载地址及所有空规则列表。同一类型的多个文件中移除一个后，合并 DAT 仅包含剩余来源。应用中的其他配置和共享文件库不会被删除。DAT 内容变化时会生成新的签名下载地址；内容不变时地址保持稳定。旧链接及 .sha256 校验仍然有效。面板更新后，请在应用中刷新订阅以替换已保存的 DAT。

### 域名目标的 GeoIP

地理文件生成 GeoIP 规则时，最终 Xray JSON 使用 IPOnDemand，在处理 IP 规则时解析域名，使 DIRECT、REJECT 和 GeoIP 均衡器能在 TCP/UDP 兜底规则之前匹配。内嵌规则和下载 DAT 的行为相同。此前手动规则的优先级不变，源模板不会被覆盖。仅含域名的 GeoSite 及其他客户端格式保留原有 DNS 策略。解析失败时继续应用后续路由规则。

### 地理文件自动交付与大小

### 服务端自动下载与更新保护

在库中选择文件，设置 HTTPS 来源、自动更新和 15 分钟至 30 天的服务端间隔。设置立即保存，并作用于使用此文件的所有模板。URL 导入会保存来源；电脑上传需另设来源 URL。自动更新默认关闭。调度器每分钟检查一次，持久租约避免同一文件重复并发下载。来源失败、面板重启和手动重试均不重置间隔。会验证地址、重定向、大小、格式以及活动模板使用的分类。出错时保留上一份可用副本；库中显示状态和下次检查时间。原始哈希 URL 保持不变；可更新链接和已签名 URL 返回当前版本，且不使用 immutable 缓存。服务端与客户端计划独立，因此更改不一定立即传入客户端。 源站更新成功后，新生成的订阅使用当前文件。内嵌规则需刷新订阅，DAT 还需在应用中刷新；未刷新的已保存配置仍是旧快照。手动上传的文件不会随第三方网站变化，需配置来源并启用自动更新。将大型列表展开到每个配置只会增加体积，不能刷新已导入规则。

### 更新与文件完整性

订阅页面将 DAT 与 JSON 分开传输：JSON 的 16 MiB 限制不再截断 DAT，DAT 有独立的 64 MiB 上限。中断的下载不算成功。EOF 或缺少分类可能表示本地文件不完整或过期。请同时更新面板和独立安装的订阅页面，再在客户端更新订阅，并将 DAT 与对应的 .sha256 比较。同一数据包的并发请求共用一次构建，不同构建仍受资源限制。批量修改主机在 API 返回前写入数据库，节点规则同步独立执行。主机编辑器打开时重新读取数据，只提交修改的字段，避免覆盖批量更新。部分用户批量操作使用后台队列，并非所有操作都排队。

### 编辑库文件

### 附加地址与路由

附加地址区域位于地理文件选项卡。导入支持 Xray JSON 规则、数组或以逗号分隔的片段，包括末尾逗号。可为所有地址选择同一操作，或保留规则中的路由。导入会在当前模板中添加独立规则；不支持的条件会使整个块被拒绝，不会被静默删除。每行输入一个域名、IP 或 CIDR，选择 DIRECT、REJECT 或已有的 VPN/自动选择路由。example.com 包括子域名，full:example.com 为精确匹配；也支持 keyword: 和 regexp:。域名与 IP 会生成独立规则，不要求同时匹配。规则位于地理文件及兜底规则之前，适合设置例外。

每个自动选择使用一张可展开卡片，集中配置服务器、策略和订阅主机分配。分配关联到具体的负载均衡器名称，重命名时保留关联。旧分配若只有一个可用目标，会显示在该卡片中；目标不明确时需显式选择。打开页面不会重写代码。选项卡随页面滚动，保存操作保留在底部。地理文件可从文件库、电脑或链接添加。上传会立即将文件存入共享文件库，兼容文件可一步关联至当前草稿。设置分类、动作和客户端更新间隔后保存模板；交付方式由系统自动选择。从模板移除文件不会从文件库删除文件。共享文件设置和服务器刷新位于文件库的可展开区域。

## 全局订阅设置

### 输出与请求头

设置响应头、订阅名称或说明、更新间隔、支持链接和默认模板。响应头随请求返回，显示方式取决于客户端。自定义备注可解释账号状态。外部小组可覆盖全局输出设置。

### HWID 与客户端操作

全局 HWID 规则和默认值在此设置，用户专属设置仍保留在账号中。输出的操作或按钮需要兼容客户端，不能代替管理员权限。测试启用、禁用、到期和限额用尽账号的响应。

### 备注顺序

打开“订阅设置”中的备注卡片。使用上下箭头移动通知原因，保存设置，然后在客户端更新订阅。默认顺序为：订阅已过期、订阅已禁用、订阅已冻结、禁止新设备、设备已封禁（HWID）。只显示当前适用原因的消息。每种原因的文本在此卡片中单独编辑。

启用合并订阅状态与 HWID 时，如果订阅已过期或被禁用，同时设备已封禁，会按所选顺序显示两组消息。例如默认先显示过期，再显示设备封禁；将 HWID 移到过期上方即可反转顺序。关闭合并时优先显示订阅状态消息；订阅有效时显示设备封禁消息。

禁止新设备单独处理。如果新设备注册被拒绝，同时订阅已过期或被禁用，则显示列表中位置更高的原因。因此将禁止注册移到过期上方，会显示注册被拒绝的消息。这两种原因不会合并。已经注册且获准的设备，在满足其他访问条件时仍可使用。

流量额度耗尽、设备数量上限和不支持 HWID 各有独立消息，不属于此列表。调整顺序会改变订阅中的消息，封禁与访问检查仍然生效。显示方式取决于客户端。

### 混合节点的首次启动

准备策略和凭据前，面板先检测当前节点及共享入站的其他节点的能力。检测在 SQL 事务外进行，并限制并发与时间。策略和配置使用同一份兼容性快照。节点不可用时仅延迟受影响的入站，独立的健康节点继续启动。兼容性未知时保留原配置并安排重试；网络故障不会将节点识别为原生 Remnawave，也不会解除限制。

### 订阅性能与兼容性

面板 1.1.7.95 使用 SQL 集合检查已签发凭据及批量配置用户，保留期限、状态、分组、HWID 封禁与密钥轮换检查。节点预检先于昂贵的配置构建，暂停限额按节点一次读取。同步请求合并，每个进程最多同时处理三个节点；占用中的 advisory 锁在事务外重试。已确认的原生 Remnawave 节点获得基础配置，其入站不启用新增的主机限额、目标规则和非活跃用户例外。同一入站上的自定义节点使用相同的兼容凭据；独立兼容入站仍保留扩展。缺少自动选择接收主机配额功能的旧版自定义核心使用池内服务器的普通凭据和限额。升级 Node/Core 并刷新客户端订阅可启用独立归属。面板显示兼容模式。未知节点或网络错误本身不会关闭限制。降级不会清除现有配额储备及财务围栏。旧版订阅页面 API 保持兼容，隐藏密钥的页面不生成无用链接。此模式无需新增 .env 变量；UTC 到期检查迁移另有说明。

### 未启用访问与冻结

允许未激活订阅访问的主机适用于 EXPIRED、DISABLED、FROZEN、LIMITED，以及时长已到期的 ACTIVE 账户。附加选项可在订阅激活时隐藏这些主机。组权限、设备封禁和主机自身限制仍然有效。在自定义备注中配置 FROZEN 内容及其顺序。{{FREE_HOST}} 在该行插入获准的主机，不能绕过 HWID 封禁或授予权限。请将该主机的入站添加到用户的内部组。共享入站时，应通过组访问设置限制其他主机，避免额外授权。解析凭据后若仅剩通知，设备预览会显示警告。外部组可以覆盖文字和顺序。旧设置自动获得冻结默认文字，不会替换已保存的消息。未激活订阅的 JSON 使用独立连接，不加载共享或已分配模板、负载均衡或地理文件；主机限制仍然生效。域名、IP 和网段生成独立规则。HWID 拒绝时会显示已保存的设备上限或不支持设备警告，而不只是订阅状态。同一台电脑上的 Happ 和 INCY 使用不同 HWID，各占一个设备名额。

### 多个订阅链接

### CDN：一次配置

从配置 CDN 窗口复制专属中性请求头名称和 UUID 值，在 VK 或 Yandex 中添加到源站请求。名称在更新后保持不变；迁移时只需替换旧通用名称。HTTPS 源站、Host 和 SNI 使用主订阅网站，关闭个性化响应的强制缓存。客户端现有链接无需替换，文件、校验和及设备链接仍使用 CDN。ID 不绕过密钥、状态、冻结、期限或 HWID 检查。/cdn/<ID> 路径保留为不支持请求头的备用方式，无需新增 .env 变量。 名称使用安装私钥生成，无法仅凭公开 ID 计算。若单独更换 APP_SECRET，请将新的请求头名称复制到 CDN。

### 订阅域名与 .env

主域名与 SUB_PUBLIC_DOMAIN 通过本地安装服务双向同步。API 在启动、打开列表时及每 30 秒检查 .env。在面板更改主地址会更新 .env 和已注册的 Compose，无需重启。支持域名、HTTPS URL 和安全路径。CDN 域名仍保存在注册表中。域名列表 API 的身份验证依赖错误已在面板 1.1.7.78 修复，请使用该版本或更新版本。需要安装程序 1.2.113 或更新版本；服务缺失时显示不可用状态，不会虚假确认。文件被并发修改时拒绝覆盖。DNS 和证书需单独配置。

编辑主域名时可选择开放访问、仅限 CDN 或重定向到 CDN。重定向只指向属于同一主域名的已注册 CDN，并保留订阅密钥、/json、设备路径、地理文件路径及查询参数。策略适用于 HTML、配置、DAT 和校验文件。源站地址及 SUB_PUBLIC_DOMAIN 应保留主域名，不要改为 CDN。每个主域名最多关联三个 CDN。

请先更新面板和我们的订阅页面。在配置 CDN 中复制独立标头名称和值，填入 VK/Yandex 的请求标头。CDN 必须覆盖该标头，而非追加第二个值。不要将密钥写入响应标头、公开链接或客户端设置。获取密钥需要域名写入权限或单独的 credentials 权限；列表读取不会泄露密钥。公开 UUID 和旧 /cdn/ID 路径仅用于选择域名，不能绕过源站限制。每个 CDN 的名称和密钥均独立且与当前安装绑定。

启用限制前请测试 CDN 的 HTML、基础链接、/json 和地理文件下载。缺少正确密钥的 CDN 请求返回 403，避免重定向循环。直接访问在仅限 CDN 模式返回 403，重定向模式返回不缓存的 307。不跟随重定向的客户端应直接使用 CDN 链接。进程间更新最多需五秒。现有域名升级后保持开放。旧页面可在开放模式工作；限制模式需要更新的订阅页面，或由 CDN 携带同一标头直接访问面板订阅 API。本功能保护订阅交付，不会隐藏网络 IP 或改变 VPN 传输。

关闭模式返回 HTTP 403，不会重定向。关闭主域名将关闭其全部 CDN；关闭单个 CDN 不影响其他地址。即使存在 CDN，也不能关闭或删除最后一个可用主域名。用户卡片、二维码和链接 API 仅显示可用地址，隐藏仅限 CDN 或重定向的主域名。删除旧主域名时，可明确确认将其用户转至当前默认域名；转移和删除在同一事务中完成。凭据、设备、冻结状态、到期时间和限额保持不变。请先移动或删除其子 CDN。

### 订阅刷新与 HWID

向应用返回订阅前，会在数据库中检查用户、设备、注册策略和设备数量限制，无需等待节点响应。个人密钥通过持久化任务单独下发，失败后重试。节点不可用时仍会返回订阅；该节点收到密钥后，新连接才能使用。已知设备无需等待注册新设备使用的锁。已知设备刷新时不会向所有节点重复下发密钥，但每次仍重新检查权限，不会绕过 HWID 封禁或注册限制。

打开网站或不带设备请求头的 curl 请求，与 Happ、INCY 的处理路径不同。排查时应使用相同链接及应用的 User-Agent、HWID 进行对比。不要在公开日志中泄露订阅链接或 HWID。

## 在独立服务器上代理订阅

### 代理的流量

客户端 → 独立代理 sub.example.net → 订阅页面服务器 198.51.100.20 → 面板 API。这是订阅交付代理，不是节点 VPN 流量代理。连接固定 IP 可绕过源站 DNS 查询；Host 选择源站站点，SNI 与证书验证确认其身份。本例中 origin.example.net 是页面主域名，sub.example.net 是它的 CDN/代理域名。地址和密钥均为示例。面板私有地址只供页面服务器使用，不要向客户端公开。

### 准备面板与服务器

在“订阅 → 设置 → 订阅页面”中添加主域名 origin.example.net 和子 CDN sub.example.net。从“配置 CDN”复制该域名专用的请求头名称和值。X-… 名称及 UUID/签名值因 CDN 而异。将 sub.example.net 的 DNS 指向独立代理，源站证书应匹配 origin.example.net。源站 HTTPS 站点必须将完整路径转发给已更新的订阅页面。页面的 REMNAWAVE_PANEL_URL 和 API 令牌只保存在服务器私有 .env 中。独立部署的页面需单独更新。现有 Remnawave 页面可在安装器“迁移”中选择“从 Remnawave 迁移订阅页面”（migrate-remnawave-subscription-page）；保留面板连接及设置。

### 服务商 CDN、独立源站与旧链接

服务商 CDN 方案：客户端 → CDN → 独立服务器上的 origin.example.net → Caddy → 本地订阅页面 → 面板私有 API，响应沿原路返回。按服务商要求，使用 A 或 CNAME 将公网 sub.example.net 指向 CDN。CDN 源站设为页面的 HTTPS 域名或 IP，Host 与 SNI 均为 origin.example.net。面板专用头应添加到 CDN 请求，不能添加到响应。源站 Caddy 将完整请求交给本地页面。3010 只是示例，请使用实际发布端口并仅绑定 loopback。该块假定 Caddy 运行于同一主机；独立 Docker 网络中应使用服务名和对应端口，而不是 127.0.0.1。

```caddyfile
origin.example.net {
    reverse_proxy 127.0.0.1:3010
}
```

平滑迁移时，将 legacy.example.net 保留为已注册的 OPEN 主域名，并保持 HTTPS 到页面的转发。保留 DNS 与证书，使已导入链接继续工作。将 origin.example.net 设为默认主域名，从用户卡片或链接 API 向新客户端发放 sub.example.net 的 CDN 链接。显式绑定旧域名的用户需另行修改，密钥无需改变。SUB_PUBLIC_DOMAIN 应保持为与面板设置同步的源站主域名，不应改为子 CDN。若不希望向客户端列出新源站，可选择“仅 CDN”或“重定向到 CDN”。已导入的旧 URL 不会自动消失。只保留 Caddy 块而不在面板注册旧域名并不充分，未知主机名可能被拒绝。待客户端迁移完成后再停用旧域名。

### 转发完整路径

转发 /KEY、/KEY/json、设备链接及全部 /geofiles/... 路径，包括 .dat、.sha256 与查询参数。保留订阅前缀；下列示例假定前缀为空。不要统一添加 /api/sub：那是直接访问面板 API 的另一种架构。不要截断 URI 或重定向到内部服务地址。保留客户端 User-Agent、Accept、HWID 请求头，以及 Routing、Profile-Title、Subscription-Userinfo、Content-Type、ETag 响应头。仅覆盖本 CDN 的专用头。不要强制缓存页面、订阅或错误；DAT 应遵循源站 Cache-Control。HTML 返回 200 并不证明 JSON 和地理文件可用。

### Caddy：通过 HTTPS 连接源站 IP

将此块放入独立服务器的 Caddyfile。在 Caddy 服务环境中设置从“配置 CDN”获得的 SUB_ORIGIN_HEADER 和 SUB_ORIGIN_VALUE，私密保存，不要发布展开后的配置。ACME 可达时 Caddy 获取公网域名证书；示例不配置 DNS 或防火墙。显式 Host 也适用于 Caddy 2.9/2.10。源站 TLS 验证保持开启，无需 tls_insecure_skip_verify。

```caddyfile
sub.example.net {
    reverse_proxy https://198.51.100.20 {
        header_up Host origin.example.net
        header_up {$SUB_ORIGIN_HEADER} {$SUB_ORIGIN_VALUE}
        transport http {
            tls_server_name origin.example.net
            dial_timeout 5s
            response_header_timeout 30s
        }
    }
}
```

### Nginx：验证源站主机名

请先提供有效的公网域名证书。在私有文件 /etc/nginx/private/sub-origin-header.conf 中仅保存一条使用面板专用名称和值的 proxy_set_header 指令，并替换下方示例值。文件应位于 webroot 外且仅管理员可读；标准 Nginx root 主进程在启动时读取它。无特权部署仅授权所需服务读取。没有 URI 的 proxy_pass 保留原始路径和查询参数，证书验证与 SNI 均显式开启。

```nginx
server {
    listen 443 ssl;
    server_name sub.example.net;
    access_log off;
    ssl_certificate /etc/letsencrypt/live/sub.example.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/sub.example.net/privkey.pem;
    location / {
        proxy_pass https://198.51.100.20;
        proxy_http_version 1.1;
        proxy_set_header Host origin.example.net;
        proxy_set_header Connection "";
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $remote_addr;
        include /etc/nginx/private/sub-origin-header.conf;
        proxy_ssl_server_name on;
        proxy_ssl_name origin.example.net;
        proxy_ssl_verify on;
        proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
        proxy_connect_timeout 5s;
        proxy_read_timeout 30s;
        proxy_cache off;
        proxy_buffering off;
    }
}
```

### 验证与排错

示例关闭 Nginx 访问日志，避免订阅密钥进入常规请求日志。错误日志也可能含 URI，应限制读取权限。验证时隐藏输入测试 KEY 并按 Enter，JSON 将保存到独立私有目录，完成后请删除。

限制源站前运行 caddy validate --config /etc/caddy/Caddyfile 或 nginx -t。命令中的 KEY 是自己的私有测试订阅密钥，不要写入公开日志。首个 --resolve 命令绕过源站 DNS 验证 IP、SNI 和证书，不绕过访问策略。启用“仅 CDN”后，没有签名头的直连应返回 403。第二条命令验证代理。还应使用各支持应用的真实 User-Agent 测试基础链接。从 Routing 响应头获取真实 DAT URL，再下载文件与校验和；虚构 /geofiles/test.dat 不是有效测试。仅 DAT 返回 404：检查 /geofiles 转发与源站页面版本。403：检查策略和 CDN 头名称/值。502/504：检查 origin 连通性、TLS 和日志。不要使用无限超时。

```bash
umask 077
CHECK_DIR=$(mktemp -d)
IFS= read -r -s KEY
curl --fail --silent --show-error --resolve origin.example.net:443:198.51.100.20 "https://origin.example.net/${KEY}/json" -H 'User-Agent: INCY/2.6.2/ios' -o "$CHECK_DIR/origin.json"
curl --fail --silent --show-error "https://sub.example.net/${KEY}/json" -H 'User-Agent: INCY/2.6.2/ios' -o "$CHECK_DIR/proxy.json"
```

### 限制源站与保护隐私

验证成功后，在主域名启用“仅 CDN”，正确签名头允许源站请求。“重定向到 CDN”向客户端返回 307；“关闭”则拒绝整个家族，包括 CDN，三者不同。最后一个主域名不可完全关闭。网络隔离需另行限制源站 HTTPS 仅允许代理/CDN IP，同时保留 SSH、管理 API 和证书签发续期，并检查主机商防火墙。通过受保护的私有网络，可使用公网域名 Host 直接向页面端口发送 HTTP，替代源站 HTTPS；不要公网开放该端口，也不要在公网 HTTP 上传输凭据。CDN 头不是 API 令牌，也不能从 DNS/历史记录抹除源站 IP。私有地址、Authorization 和 CDN 密钥不可出现在响应正文、Location、响应头或 webroot 中。

[Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) · [Nginx proxy module](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)

## 限额：范围与用户表格

### 显示范围

选择单个主机或将主机共享配额的标签。页面显示有配额、速度限制或封锁的范围；没有限制且未封锁的范围会隐藏。

### 列含义

在表格中比较已用流量、实际配额、剩余流量、一次性追加量和访问状态。例如基础配额 100 GiB 加上 20 GiB 追加量，共计 120 GiB；计费使用 80 GiB 后剩余 40 GiB。无限流量仅移除所选范围的个人配额，仍记录用量，不会解除流量暂停、订阅到期或其他用户限制。

### 搜索与状态

按用户名、标识符、邮箱或 Telegram ID 搜索，并使用状态、可用性、小组筛选、排序和每页数量。“已封锁流量：N / M 位对象”针对所选对象模式，而非仅可见行。

### 面板不可用时

兼容节点使用预先分配的本地配额储备。面板不可用时，连接可继续使用剩余本地储备；申请新储备需要恢复连接。耗尽储备不会变为无限流量。重置立即应用到可访问节点，其他节点重新连接后接收重置。失联节点仍使用旧储备期间，总用量可能暂时超过新配额。限速和其他本地规则继续生效。

## 追加、重置、封锁与解封

### 追加流量与重置用量

追加流量为已有正数配额的主机或标签增加一次性额度。重置从零开始记录当前周期用量，但保留历史统计，也不会取消个人不限量。

### 封锁与解封

封锁会暂停指定主机或标签及对象的流量。解封移除此暂停，不会延长订阅、启用禁用账号或增加流量。整个范围的封锁和个人封锁会同时考虑。

### 选择操作对象

只操作一位用户时仅选择其行。批量操作可针对所选用户、全部当前有权限的用户或指定小组成员。搜索和分页不限制“全部”或“小组”模式。确认前核对模式和数量；结果不明确时先刷新表格再追加流量。

## 个人与批量不限量

### 授予与撤销

授予不限量会保存所选主机或标签的个人例外，直到明确撤销；重启和周期变化后仍有效，范围设置不变。撤销后恢复当前基础配额及已有追加量。只授予一人时仅选择该用户。

### 生效范围

不限量仅免除此范围的配额。暂停、带宽、到期、状态、HWID 和其他范围限制仍有效，用量继续记录。批量授予只针对当前对象，新用户和未来加入的小组成员不继承。

## 周期、倍率与带宽

### 不同限制

用户配额限制数据量，主机用户带宽限制单个用户，共享带宽是公共上限。倍率改变计费流量，不改变连接速度。所有适用限制同时生效，某项不限量不会关闭其他限制。

### 周期重置

主机或标签可按天或月重置，0 表示不自动重置。配额窗口从保存的配置基准时间计算。修改倍率按策略重新计算当前范围用量，不改变普通订阅用量。改变周期前检查剩余配额、追加量和用量。

### 字段与控件

- **每用户流量限额**: 此主机或标签的个人流量配额；主机表单按 GiB 输入、按字节存储，0 表示不限制此配额。
- **使用标签流量配额**: 将主机用量计入用户的共享标签配额；关闭时主机自身配额仍有效。
- **用户速度限制**: 主机上的单用户带宽，由该用户所有设备和连接共享；单位 Mbps，0 表示不设置此限制。
- **使用标签的每用户速率**: 将标签的个人速度上限应用到该主机，每个参与主机分别执行此限制。
- **设备速度限制**: 此主机上单个设备私钥的速度上限，单位 Mbps，所有连接和两个方向共用。0 关闭此上限，用户上限仍然有效。需要兼容节点及核心。
- **应用标签的设备速度限制**: 独立于其他继承开关，将标签的设备密钥上限应用到此主机。
- **整台主机速率限制**: 所有用户共享的主机或标签总带宽；100 Mbps 上限由同时运行的连接共同使用。
- **使用标签共享速率**: 让主机参与标签的总带宽上限，由参与的连接共同使用。
- **主机流量倍率**: 流量统计倍率：设为 2 时，传输 1 GiB 按 2 GiB 计入；主机留空时从标签继承。
- **流量重置间隔**: 此配额用量重置之间的天数或月数，需同时选择单位；0 表示不自动重置。
- **自动重新生成 SNI 和 shortId**: 轮换池中的 SNI，重新生成 shortId，并自动重启节点

## 活动连接与断开会话

### 获取状态

选择用户或节点后收集连接。有些操作会先创建任务再获取结果，列表不是整个基础设施的即时快照。按 IP 或节点分组可查看活动与可用位置数据。

### 断开连接

断开会话会关闭目标当前的连接，不会禁用账号，获准客户端可重新连接。持续拒绝访问应使用账号状态、HWID 封锁或相应范围暂停。断开后重新获取快照。

### 节点权限

通过 Xray 读取活动连接 IP 不需要 NET_ADMIN。节点上的附加 Linux 功能才使用此权限。安装和更新节点时，如果无法确认运行中容器拥有该权限，安装程序会单独询问。已生效的权限会保留且不重复询问。自动化时使用 --net-admin 或 --no-net-admin；旧 Compose 中仅存在 cap_add 并不能证明权限已生效。

## 备份

### 访问与文件

首次安装面板时，安装程序会询问备份密码；按 Enter 可自动生成。安装完成后会显示该密码，并将其保存到面板目录中的 `backup-password.txt`，仅 root 可读取。请在服务器之外保存一份密码。管理员输入该密码后进入此页面。点击“创建 ZIP 备份”并等待文件出现。加密压缩包包含数据库转储，打开时需要密码。请下载到独立存储。发送会将所选文件发到 Telegram，删除会从服务器移除文件，“关闭访问”会重新锁定页面。数据库备份不包含服务器 .env、证书或节点文件。面板没有恢复按钮，恢复由服务器管理员执行。 ZIP 使用 AES。解压后的 database.dump 仍为 PostgreSQL custom 格式压缩转储，没有额外加密，不能直接在文本编辑器中阅读。使用与 pg_dump 主版本相同或更新的工具，运行 `pg_restore --file=database.sql database.dump` 转换为 SQL，不会恢复数据库。

### 自动创建

启用自动备份，选择 1–168 小时的周期和 1–7 天的保留期限并保存。关闭自动化停止新计划备份，但旧文件仍按保留期限删除。

### Telegram 发送

启用自动发送并填写机器人令牌、聊天或群组 ID。保存后检查备份是否到达。创建或发送失败时读取面板错误消息，服务器配置由部署管理员处理。

### 字段与控件

- **备份**: 加密数据库备份
- **备份**: 面板数据库的密码保护 ZIP 备份。可将定时备份发送至 Telegram。
- **旧备份**: 转换为加密 ZIP
- **自动化**: 定期数据库转储并发送至 Telegram
- **间隔，小时**: 计划备份间隔为 1–168 小时，仅在启用计划时生效。
- **备份保留天数（1–7）**: 备份保留 1–7 天，即使关闭自动创建也会清理到期备份。
- **发送至 Telegram**: 将计划备份发送至单独配置的 Telegram，不控制普通面板通知。
- **机器人令牌**: 备份发送机器人令牌，是秘密凭据，不是面板 API 令牌。
- **聊天/群组 ID**: 备份接收聊天，机器人必须有访问权限。

## API 令牌与权限

### 创建与编辑

在设置中为每个集成创建独立令牌，填写清晰名称、到期时间和必要权限。修改权限后保存。删除或到期会终止该集成的访问。

### 选择权限

只授予所需部分和操作的权限。读取权限获取数据，写入权限允许对应修改。允许全部操作不会开放 API 令牌不可用的管理功能。授予不限量需要相应权限。完整方法和权限见独立 API 参考。

### 令牌保管

只向可信集成提供令牌。泄露后删除并创建替代令牌。名称帮助确定使用它的服务，各客户访问控制由集成本身管理。

### 通过 API 读取私密设置

节点 API 响应不包含原始入站设置及私钥。读取配置请使用具有相应权限的配置档案 API。更新配置档案需要更新权限和 config-profiles:get；更新模板需要更新权限和 subscription-template:get，因为响应包含已保存内容。匹配的 :read、:* 或 * 权限同样允许读取。缺少读取权限时，请求会在修改数据前被拒绝。修改、启用、停用、延长用户期限、重置流量及撤销订阅还需要 users:by-id。修改外部分组需要 external-squads:get，调整顺序需要 external-squads:list；匹配的 :read 和 :* 权限同样适用。创建用户无需读取现有密钥。管理员会话的行为保持不变。

### 用户管理令牌与永久访问

“用户”预设允许创建、修改、冻结/恢复用户、重置流量、读取订阅密钥及链接、批量管理用户。这是固定的 30 项 users 资源权限；HWID 管理以及分组和域名目录需另行选择。不包含面板设置、服务器、备份或令牌管理。冻结使用 用户 API 和 {"id":123,"status":"FROZEN"}，恢复使用 ACTIVE。需要 users:update 或 users:write，以及 users:by-id 或 users:read；users:* 同时包含两种权限。已过期账户冻结后剩余时间为零。创建时选择“永不过期”：expiresInDays: null 保存为 expireAt: null，并签发带显式 permanent 标记且没有 exp 的 JWT，不使用虚假的遥远日期。每次请求均检查数据库中的撤销状态和当前权限。编辑名称及权限不会改变令牌值和期限；更改期限请创建替代令牌后删除旧令牌。订阅页面最小权限仅为 system:metadata、subscriptions:subpage-config、subscription-page-configs:get、subscription-page-configs:list。仅在启用 Marzban 旧链接兼容时另加 users:by-username。

### 字段与控件

- **API Tokens**: 管理您的 API Token用于程序访问。
- **永不过期**: 删除前一直有效。权限变更立即生效。

## 通知

### 面板事件

服务器管理员在安装配置中设置用户、节点和服务通知：启用发送，填写机器人令牌，并为事件类型指定聊天。面板没有涵盖这些参数的独立表单。自动发送备份在“备份”页面单独设置，可以使用不同的机器人。

### 检查发送

修改设置后检查是否收到通知。缺失时核对令牌、接收者和机器人聊天权限。向管理员报告发送错误时提供事件时间和面板消息。

## 故障排查

### 无法保存

读取面板消息并检查必填字段。会话到期时重新登录，权限不足时联系管理员。错误持续时记录错误文字、时间和操作内容供支持人员排查。

### 连接不可用

1. 检查用户状态和订阅到期时间。
2. 检查总配额、主机或标签限额及设备限制。
3. 确认内部小组允许所需入站连接。
4. 检查节点状态、配置、主机和日志。
5. 在客户端刷新订阅并重试。
批量操作结果不明确时，重复前检查对象当前状态。

## 变量格式与单位

### 参数与 Base64

参数位于冒号后，以 | 分隔：`{{NEXT_TRAFFIC_RESET_AT:format=DD.MM.YYYY HH:mm}}`、`{{STATUS:ACTIVE=启用|DISABLED=禁用|EXPIRED=到期|LIMITED=已达限额}}`。RESET_STRATEGY 可为 NO_RESET、DAY、WEEK、MONTH、MONTH_ROLLING 提供标签。`rwEncodeBase64:` 编码最终字符串并加上 `base64:`。未知变量保持原文。

### 数值、不限量与上下文

LOCATION 的 MB 或 GB 以 1024 为基数，最多三位小数且无单位；不限量的 LIMIT 或 LEFT 返回 ∞。普通 TRAFFIC_USED_MB/GB、TOTAL_TRAFFIC_MB/GB 带单位。没有当前主机时，LOCATION 请求头可输出去重、分号分隔的“名称：值”列表；多个标签也可形成 TEG 列表。LOCATION RESETAT 使用 UTC。

### 时间值

UNIX 值为秒而非毫秒。缺少 LAST_TRAFFIC_RESET_AT_UNIX 或 NEXT_TRAFFIC_RESET_AT_UNIX 时返回 0，格式化值为空。DAYS_LEFT 不低于 0。普通不限量订阅的 TRAFFIC_LEFT 按规则返回 0 而非 ∞，与 LOCATION LEFT 不同。

## 理解在线数量

### 连接与唯一用户

节点在线总数累加各节点连接；同一账号连接两个节点可能计两次。在线用户按唯一账号计数，因此两张卡片不同并不代表异常。参阅 [Remnawave 入门指南](https://docs.rw/learn-en/quick-start/)。

### 流量比较

“今天”卡片将当前统计周期与前一周期比较，数值来自节点报告。新面板为零不必然表示故障，应检查统计时间、周期和真实客户端连接。

## 密码、通行密钥与 OAuth2

### 密码与会话

管理员在登录页登录。修改认证设置后，在另一个会话中验证登录和恢复访问。[官方入门指南](https://docs.rw/learn-en/quick-start/) 描述忘记密码时的 Rescue CLI；使用时核对实际容器名称。

### 通行密钥

在管理员设备或浏览器中注册通行密钥，可在设置查看或删除。注册与登录不同，添加密钥不会自动关闭其他方式。WebAuthn 需要正确的面板域名和 HTTPS。

### OAuth2

在所选身份提供方配置 Client ID、Client Secret 和 redirect URI。Generic OAuth2 还需要授权接口、令牌接口、面板域名，以及提供方 OpenID Connect 配置中的精确 issuer。issuer 可以包含路径，末尾的 / 也参与比较。面板将其与 ID 令牌中的 iss 比较，拒绝其他 issuer 的响应。升级已有配置后，请先填写此字段，再通过 Generic OAuth2 登录。在另一会话中确认新登录方式可用前，保留已有的登录方式。管理员 OAuth2 登录与 API 令牌分别配置。

## 打开订阅时会发生什么

### 同一链接的不同响应

用户在浏览器打开订阅链接，或将其加入应用。浏览器可能收到说明页面，应用则收到所选格式的配置。面板会考虑请求标头和响应规则。若应用未收到连接，请在请求历史中找到该请求，检查响应格式、用户状态和 HWID。

### 生成流程

主机定义连接入口并关联一个入站连接；模板选择配置格式；响应规则决定输出行为；订阅设置加入元数据；外部小组可覆盖模板和设置。分别检查各环节。

## 客户端格式与模板

### 格式系列

模板按客户端类型区分，包括 Mihomo、Xray JSON、sing-box 和 Base64 回退。选择实际客户端对应的模板；服务器支持入站协议不代表所有生成器都能表示其传输。新核心功能应检查生成的 JSON 和格式支持。

### 外部小组与响应规则

外部小组可为成员覆盖模板，响应规则根据请求条件选择输出。修改后检查某用户的请求历史和实际客户端输出。[官方概览](https://docs.rw/learn-en/quick-start/)说明模板与响应规则的区别。

## 支持项目

### 地址与网络

在文档目录中选择“支持项目”即可直接打开地址页面。也可从更多选项菜单进入。页面列出 TON 网络的 Gram、Solana、TRON 网络的 TRC20、Litecoin、Ethereum 和 Bitcoin 地址。在列表中找到对应网络并点击复制。转账前在钱包中核对完整地址，币种和网络必须与所选网络一致。

### 页面的功能

复制按钮将地址放入剪贴板。面板不会连接钱包、签名或发送交易、扣款或创建订阅。Telegram 链接用于向项目作者提出问题和建议。
